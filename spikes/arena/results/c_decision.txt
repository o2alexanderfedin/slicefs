Decision (spike C)
------------------

C-sim (REDUCE 1 part), 1 GiB live, 10x churn, 64 MiB arenas:
- G* = 64. Padding + unusable at 85 %, file delete: G=64 2.14 % (corpus),
  0.42 % (synthetic); G=256 8.2 %, G=512 16 %, G=4096 67 % / 23 %. The
  same for every allocator at one G. "Unusable" (holes smaller than the
  smallest record) is 0 everywhere, so the other rules break the tie.
- Dirty arenas per 8 MiB commit <= 2: V1 1.89 / 1.68 (mean, corpus /
  synth) and V4 1.60 / 1.64 pass. V2 13.5 / 14.0 and V3 5.8 / 5.4 fail.
- Adversarial (object delete) not worse than compaction, peak space at
  85 %: V1 1.625 vs CMP 1.579 on the corpus (3 % worse: FAIL), 1.512 vs
  1.564 synthetic. V4 1.250 vs 1.579 and 1.209 vs 1.564 (pass).
- So the plan's rule picks no allocator of V1-V3 on the corpus trace.
  V* = V4 (added here). V1 stays as the plan-grid allocator in every disk
  table (C1).
- V3 evacuation is not needed: it copies 1-11 MiB per run, gives no space
  gain over V1, and has 3x the dirty arenas per commit.
- The simulator agrees with the disk: compaction peak space 1.55 (sim) vs
  1.56 (disk, RS and V1); V4 1.23-1.25 (sim) vs 1.24 (scale model); V2
  13-15 dirty arenas per commit (sim) vs 15.7 F_FULLFSYNC per commit (disk).

Accept rules for C on disk (64 MiB arenas; fills 50/70/85/95 %):
- WA <= 1.1: C1 1.02 / 1.03 / 1.05 / 1.15, C4d4 1.01 / 1.02 / 1.04 / 1.10.
  Compaction (V1, RS): 1.34 / 1.40 / 1.63 / 1.61. Most of C's WA is
  checkpoint rewrites (wa_idx up to 0.14 at 95 %).        C1 FAIL at 95 %
- Space amplification <= compaction at every fill (peak, amp_pre):
  50 % 2.05 vs 2.04 (equal), 70 % 1.46 vs 1.80, 85 % 1.33 vs 1.56,
  95 % 1.10 vs 1.45. Just after a GC at 50 % compaction is lower (1.25 vs
  2.05): it frees whole arenas at once.              PASS (tie at 50 %)
- Sync per commit within max(10 %, 2N) of A: mean sync() time vs V1:
  C1 +54 / +92 / +128 / +286 %, C4d4 +24 / +50 / +39 / +44 %. The
  deterministic count, F_FULLFSYNC per commit: V1 1.09-1.12, C1 1.71 /
  2.30 / 2.50 / 4.49, C4d4 1.38 / 1.71 / 1.38 / 1.55. Each arena written
  in a commit costs one F_FULLFSYNC (C-B2: 21 ms each, linear in N), and
  RULE W / RULE C add dirty-list and checkpoint writes.            FAIL
- Put throughput within max(5 %, 2N) of A (wall and CPU): CPU per GiB is
  1-17 % lower for C at every fill. Wall MB/s: C1 +2 / -18 / -9 / -43 %,
  C4d4 +9 / -9 / +5 / -19 %. Inside the noise except C1 at 95 %.
                                     C1 FAIL at 95 %, otherwise in noise
- Reopen after kill -9 <= 0.5 s: a 64 MiB arena scan costs about 0.105 s
  (warm cache, CPU-bound: CRC + zstd + BLAKE3): 1 dirty 0.13 s, 2 0.24 s,
  8 0.84 s; clean close 0.03 s. SEEK_DATA changes nothing for full
  arenas. Crash loop (1 MiB arenas): max reopen 6-20 ms.
                                          PASS for <= 4 dirty arenas
- GC: CPU 18-76 % lower than compaction (no copies), but wall time
  +36 % to +196 %: after each GC every arena that lost records gets a
  checkpoint (about 3 F_FULLFSYNC each).

Verdict: reject reuse as the plan specifies it (C1 fails WA at 95 %, the
sync rule at every fill, and throughput at 95 %). The best variant
measured (C4d4) passes WA, space and reopen, and fails only the sync rule
(+24-55 % F_FULLFSYNC per commit). Its gains are real: peak disk space
-18 to -25 % at 70-95 % fill, WA -25 to -36 %, GC CPU -60 to -75 %.
