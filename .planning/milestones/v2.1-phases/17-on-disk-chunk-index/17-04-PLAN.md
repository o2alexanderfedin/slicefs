1. crates/chunk-store/src/mem.rs: add MemIo::fail_next_write_durable(kind: Kind, n: u32): the next n write_durable calls of that kind fail with EIO and write nothing; MemIo::fail_write_durable_after(kind: Kind, skip: u32): after skip more good write_durable calls of that kind, the next one fails once; MemIo::fail_sync_after(skip: u32): after skip more good syncs (pack sync, directory sync or durable write), the next one fails once (fail_next_syncs cannot pass the first sync and fail the second); and MemIo::set_fail_removes(on: bool): remove fails with EIO and keeps the file. 3. Damage (writable): if the MANIFEST exists but its magic, version or CRC is bad, or a listed run is missing or Run::open refuses it, log one tracing::warn line that names the reason, remove every run file and the MANIFEST, and open as a store without a MANIFEST (lib.rs then replays every pack and flushes at the limit, as in 17-03 Task 2).
4. Damage (read-only) [Read-only open]: read the MANIFEST and open the runs; if a listed run is missing, read the MANIFEST once more (a merge in a writer process can replace it between the two reads) and try again; if it still fails, or the MANIFEST is damaged, ignore every run, start from hwm (0, 0) and zero stats, and replay every pack into the RAM memtable. Write nothing.
5. A page CRC failure in Run::get is Error::Corrupt, and Index::get returns it at once: it never goes on to an older run (17-03 rule; the damaged page can hold a tombstone that hides an older Put). read returns the error (get gives None); contains gives false; put treats it as not found and writes the object again (17-03 rule), so the new memtable entry shadows the damaged run. Write in the doc comment of put that stats can count such an object twice.
6. Repair path: pub fn request_index_rebuild(&self) -> Result: writes a new MANIFEST with the same runs, hwm and stats and the flags bit 0 set (write_durable), and logs one tracing::error line that names the reason. A writable open that reads a MANIFEST with the flag rebuilds as in step 3 (and the new MANIFEST has the flag cleared); a read-only open with the flag acts as in step 4 (replay every pack into RAM, write nothing). 17-06 calls it when a merge finds a damaged page and 17-07 when GC does; this plan tests it directly.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk -> open | index files can be damaged, partial (crash), or from another release |
| writer process -> read-only process | a mount can replace runs while scrub or stats opens the store read-only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-06 | Tampering | Index::open, Index::get | high | mitigate | a damaged MANIFEST, footer or table makes a writable open rebuild from the packs and a read-only open replay in RAM; page CRCs stop wrong data at lookup, and a page error never falls through to an older run; the rebuild flag is the repair path for damage found later; tests flip bytes in each part, including a newer page over an older Put |
| T-17-07 | Tampering | flush crash ordering | critical | mitigate | the active pack is synced before a run that points into it is written; the MANIFEST is the commit point; orphans are removed at open; seven crash tests (one of them during the replay of a rebuild) check byte-exact reads and exact stats after MemIo::crash |
| T-17-08 | Denial of service | read-only open of a damaged index | low | accept | it replays every pack into RAM (the old cost); only for damaged indexes, and it writes nothing |
| T-17-SC | Tampering | cargo dependencies | high | accept | no dependency change; builds use --locked |
