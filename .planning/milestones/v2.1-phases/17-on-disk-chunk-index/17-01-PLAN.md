1. Make a worktree in the scratch directory: git worktree add SCRATCH/wt-17-spike -b spike/17-index from the phase branch HEAD. Work only in benchmarks/index-bench there.

3. Add src/spike_runs.rs: an index-only prototype of the locked layout. It is not the product code (17-02 and 17-03 write that), but it follows the same rules, so its numbers predict the real design:
   - memtable: a BTreeMap from the 33-byte ObjectId to a 25-byte Loc, flushed to a run file at 1,000,000 entries; run files in DIR/index/.
   - run file: 4 KiB pages of 58-byte entries (33-byte ID, pack u64, offset u64, stored u32, raw u32, flags u8), sorted by the full ID; one 8-byte fence per page (digest bytes 0..8 of the first entry); one blocked Bloom filter at 10 bits per key with 512-bit blocks and 7 probes, all positions taken straight from digest bytes (block from digest 0..8, h1 from 8..16, h2 from 16..24, Kirsch-Mitzenmacher), no hashing; a footer with the offsets.
   - open: read only each run's footer, fence table and filter; never a page.
   - lookup: memtable, then the runs newest first: filter, binary search of the fences, one pread of one 4 KiB page (std::os::unix::fs::FileExt::read_exact_at).
   - close: flush the memtable, then merge all runs into one run (a stand-in for the tiered merges of 17-06), then write the exact object count to a small file. objects() returns the exact count (the bench checks it).
   - put(data): id = Blake3_256.id(data); if the lookup finds it, it is a dedup hit; else insert a synthetic Loc for object i: pack = i / 1,240,000 + 1, offset = 14 + (i mod 1,240,000) x 54, stored 8, raw 8, flags 0.
