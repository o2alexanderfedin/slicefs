<objective>
Tracer of the store: one object goes put, memtable, flush to one run file and a MANIFEST, then reopen reads the MANIFEST and the run footer, and contains and get find the object with one page read. The in-RAM map of every object goes away. Then the replay and stats rules are made exact.

Purpose: IDX-01 (sorted runs with a sparse key table and a memtable), IDX-02 (open reads only footers and tables) and IDX-03 (packs stay the truth; entries not in a run are found again from the packs). 1. crates/chunk-store/src/index.rs (new, declared mod index; pub(crate) items) [Layout: runs + MANIFEST] [Stats at cold open] [GC interaction]:
   - Entry: Put(Loc) or Tomb(pack).
   - MANIFEST bytes: magic SFMF, version u16 = 1, flags u32 (bit 0 = "rebuild the index from the packs at the next writable open", used from 17-04; written as 0 here; an unknown bit makes the MANIFEST damaged), sequence u64, next run number u64, high-water mark pack u64 and offset u64, stats objects, raw_bytes, stored_bytes (u64 each), the live runs newest first (count u32, then per run: num u64, byte length u64, entry count u64), the obsolete run numbers (count u32, then u64 each: runs this MANIFEST replaced, to delete once it is durable), CRC32C. Always written with write_durable(0, Kind::Manifest, ..): it is the commit point of every flush. Decode checks the CRC and every count against the length with checked arithmetic.
   - High-water mark (hwm) rule: every record of a pack below hwm.pack, and every record of pack hwm.pack at an offset below hwm.offset, is in a durable run (or hidden by a durable tombstone). At a flush in normal operation, hwm = (active pack number, active pack length) if a pack is active, else (next_pack, 0). At a flush during the open replay, hwm = (the next pack to replay, 0): no pack is active yet, and the .idx entries of a pack are in ID order, not offset order, so a mark inside a pack would be wrong.
   - Memtable: a BTreeMap from ObjectId to Entry. In this plan it is one map inside Inner; 17-05 shards it [Concurrency: sharded memtable].
   - Index: the memtable, the runs (Vec of Arc of Run, newest first) and the current MANIFEST values. get(id) returns Result of Option of Loc: the memtable first, then the runs newest first; the newest entry decides: Put gives the Loc, Tomb gives None. A run read error is returned at once: get never goes on to an older run after an error (an older Put could be an entry that a tombstone in the damaged page hides).
   - tombstone(id, pack): a memtable insert that does no I/O. It inserts Tomb(pack) unless the memtable already holds a Put of id in another pack (a newer copy, which must survive). The caller must have proved, under the same store lock and with a complete read of the index, that the Put of id in that pack is the current entry. This refines [GC interaction] on purpose: lookups and merges use newest-wins per ID, so a tombstone hides only the entry it was written for, and a rule "hide only that pack and keep searching" would let a stale older entry of the same ID (for example a duplicate whose bytes GC punched) come back.
   - flush(io, hwm, stats): only when the memtable is not empty. Order: (a) the caller has synced the active pack (a run must never point at bytes that are not durable); (b) write the sorted memtable to a new run (the next run number) with RunWriter, then io.sync_dir(); (c) write the new MANIFEST (sequence + 1, the new run first, the hwm, the stats) with write_durable; (d) open the new run with open_run and Run::open and put it first in the run list; (e) clear the memtable. On a failure in (b) or (c) return the error; the memtable and the old MANIFEST stay, and the partial run file is removed (best effort).
   - iter_all(): a merged iterator over the memtable and every run in ID order; the newest entry per ID wins and tombstones hide; yields Result of (id, Loc); a run read error ends it with that error.
   - open(io, read_only): read the MANIFEST (absent: no runs, hwm (0, 0), zero stats); open each listed run with open_run and Run::open. It reads only the MANIFEST, the footers and the tables.
2. crates/chunk-store/src/lib.rs:
   - Remove the allow(dead_code) attribute on mod run (17-02). Remove the in-RAM map field of Inner and put the Index in its place; remove what only that field used. Options gets index_memtable_limit: usize, default 1 << 18 entries [Tuning surface]. Add pub struct IndexInfo { runs, run_entries, memtable_entries, hwm_pack, hwm_offset } (u64 fields) and ChunkStore::index_info().
   - open_with [Layout: cold open]: Index::open; stats start from the MANIFEST; stats.packs from the pack list. Replay only what the hwm does not cover: for each pack number at or above hwm.pack, ascending, take its entries as today (the .idx if valid; else resync_scan for a sealed pack; scan_pack and the cut for the last pack, which becomes the active pack), and keep only entries whose (pack, offset) is at or above the hwm. Each kept entry goes into the memtable; it counts in stats only if Index::get found no Put for its ID before the insert (a copy that GC wrote above the hwm, or an entry that is already in a run, is not counted twice). Packs below hwm.pack are not opened and their .idx files are not read. During the replay a writable open flushes only after it has finished a pack (never inside one), when the memtable has reached the limit, with hwm = (the next pack to replay, 0); so the memtable can go over the limit by at most one pack's entries during the replay. A read-only open never flushes and writes nothing.
   - add(id, loc): memtable insert; stats grow only for an ID without a current Put (the same rule). After the insert, when the memtable has index_memtable_limit entries or more: sync the active pack, then Index::flush with the current hwm and stats [Concurrency: sharded memtable, size-limit flush]. A flush failure sets Inner::failed (as a failed .idx write in seal does today) and is returned.
   - put, read, contains and stored_len use Index::get under the store lock. A page read error in put's dedup check counts as not found (the object is written again; the new memtable entry shadows the damaged run); read returns the error; contains and stored_len answer not found. seal is unchanged (it writes the .idx) and does not flush; close is unchanged and does not flush.
   - gc_finish, in five phases, all under the store lock in this plan [Concurrency: GC tombstones before punch/delete]:
     (A) read: fill the per-pack map of current entries with one complete Index::iter_all pass (the same RAM as the removed field; 17-07 replaces it). An error returns at once: no copy, no tombstone, no flush, no pack change, and Inner::failed is not set.
     (B) copy: for each pack to compact, read its kept records and append them to the active pack, then insert each new Loc in the memtable (no stats change). A read error returns at once; the copies made so far are harmless duplicates with newer, valid Locs.
     (C) tombstones: Index::tombstone for every removed entry, with the stats decrement and the removed counters (no I/O, so nothing can fail here).
     (D) durable point: sync the active pack, then flush. A failure sets Inner::failed and returns: no pack is punched or deleted, and because the store refuses writes until a reopen, the tombstones in RAM are never flushed.
     (E) destructive step, only after (D): punches (write the .idx without the victims, mark the header, punch, as punch_pack does today, without its own index changes) and deletes (the .idx, then the pack), then sync_dir.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk -> MANIFEST decoder | the MANIFEST can be damaged or written by another release; its counts are untrusted |
| index -> put dedup check | a stale positive makes put skip the write, so the object is lost without an error |
| index read -> GC decision | a failed read must not turn into a decision to remove or keep |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-03 | Tampering | index.rs MANIFEST decode | high | mitigate | magic, version, flags and CRC32C checks; every count is checked with checked arithmetic against the length before an allocation; an unknown flag bit is damage |
| T-17-04 | Tampering | put dedup check after GC | critical | mitigate | GC removals are tombstones for the current Put only; the active pack is synced and the memtable flushed (MANIFEST durable) before any pack is deleted or punched; in this plan every lookup runs under the store lock; the tracer test a_gc_removal_is_a_durable_tombstone checks put after GC and after reopen |
| T-17-05 | Denial of service | memtable RAM | medium | mitigate | the memtable flushes at Options::index_memtable_limit (default 1 << 18 entries); during the open replay it can go over the limit by at most one pack's entries; the replay covers only records above the high-water mark |
| T-17-24 | Tampering | gc_finish after an index read error | critical | mitigate | phase A reads the whole index before any change and returns on the first error; tombstones are inserted only after every read succeeded and do no I/O; a failed durable point fails the store so the RAM tombstones are never flushed; Index::get returns a run error instead of an older entry; the test a_gc_that_cannot_read_the_index_changes_nothing |
| T-17-SC | Tampering | cargo dependencies | high | accept | no dependency change in this plan; builds use --locked |
</threat_model>
