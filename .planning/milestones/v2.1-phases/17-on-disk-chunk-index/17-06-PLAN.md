  <action>
Write the tests first, run them, then implement [Merge policy] [Concurrency: Arc snapshot, tiered merges, delete only after a durable MANIFEST]:
1. Options: index_merge_fan_in: usize, default 4; index_background_merge: bool, default true (tests set false) [Tuning surface]. IndexInfo gets run_tombstones.
2. Tier of a run: the integer floor of log base fan_in of max(1, entries / index_memtable_limit). Policy: walk the run list from the oldest run to the newest; the first window of fan_in adjacent runs with the same tier is the next merge; none means no merge.
3. One merge step (in index.rs, called by lib.rs): under the store lock pick the window, allocate the output run number, clone the input Arcs; release the lock. Read the inputs with Run::iter (no lock held), merge them by ID (a k-way merge with a small heap); for one ID the entry of the newest input wins; if the window includes the oldest run, drop every tombstone (nothing older exists), else keep the winning tombstone. Stream the output with RunWriter through create_run (sync every 64 MiB and at the end), then sync_dir. Take the store lock; if the inputs are no longer the same adjacent window in the run list, remove the output and return false; else write the new MANIFEST with write_durable: sequence + 1, the SAME hwm and the SAME stats as the current MANIFEST (a merge changes no content, and these stats must stay those of the run contents, not of the memtable), the live list with the output in place of the inputs, obsolete = the input numbers. Then install the new run set, bump gen, release the lock, and remove the input files (a failed removal is logged; the next open removes them from the obsolete list, 17-04). Readers that hold the old Arcs keep reading the removed files (open handles). A read error from an input ends the merge with that error: it never skips a page (a skipped tombstone would bring back an older entry); remove the partial output and change nothing else. If the error is Corrupt (a damaged page, not a transient I/O error), call request_index_rebuild (17-04), so the next writable open rebuilds the index from the packs; from then on the store does no more merges until it is opened again (the damaged run stays in use for its other pages).
4. Only one merge runs at a time: a merge mutex held for the whole step.
5. lib.rs: pub fn merge_index_now(&self) -> Result of bool (one policy step; for tests and tools) and pub fn merge_index_all(&self) -> Result of bool (one merge of every run into one; for tests and tools; it rewrites the whole index). Both refuse a read-only store with an error.

Write the tests first, run them, then implement [Merge policy]:
1. ChunkStore holds the store lock as an Arc of the Mutex of Inner. A merge control value (stop flag, a Mutex of a state with "work pending" and "busy", and a Condvar) is shared with one thread spawned in open_with when the store is writable and index_background_merge is true. The thread holds only the Arcs it needs (store lock, Index, PackIo, merge control) and copies of the Options values, never an Arc of ChunkStore.
2. Every flush (size limit or GC) sets "work pending" and notifies. The thread waits on the Condvar; when woken it runs merge steps until the policy finds none or stop is set; then it clears "busy" and notifies. The merge loop checks the stop flag between input pages; on stop it removes its partial output (best effort) and returns.
3. pub fn wait_index_idle(&self): blocks on the Condvar until no work is pending and the thread is not busy; returns at once when background merges are off or the store is read-only. (For tests and the 17-08 bench; no sleeps.)
4. close() and a new Drop for ChunkStore: set stop, notify, join the thread (Drop ignores a join error). close() does not flush (as in 17-03).
5. A merge failure in the thread: one tracing::warn line with the error, remove the partial output, and wait for the next notification; it never sets Inner::failed (the runs are derived; the foreground keeps working). A Corrupt error also requests the rebuild (Task 1) and stops further merges until the store is opened again.
6. Write the five tests above in tests/index_crash_tests.rs.
