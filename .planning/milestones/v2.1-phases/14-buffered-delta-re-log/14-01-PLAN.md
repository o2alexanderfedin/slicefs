<objective>
Plan A of the phase tracer: replace the full-file buffer of random writes with an overlay on the committed content, end to end on the switch, write and read paths. The old mode is one enum variant, so its removal is compile-atomic: every arm that matched it (release, destroy, commit_cut, flush_handle, setattr, gc_start) gets a real overlay arm in this plan, in its simplest correct form. Plan 14-04 (plan B, wave 2) then adds the dirty limit and the test hooks, the final relog form (1 MiB pieces after the commit), the Streaming setattr case, the log text with the Phase 13 check, the grep gates and the counting-allocator proof. Both plans ship in the one phase PR.

Decision IDs. 14-CONTEXT.md has no IDs, so the planner numbers its bullets in order. "Direction set by the user": D-01 [no full-file buffer anywhere], D-02 [bounded memory per open file, Docker 1 GiB and 4 GiB under one VmHWM cap]. "Proposed design from #98": D-03 [patch overlay], D-04 [rebase at the dirty limit and at close, re-chunk near extents], D-05 [a commit re-logs only the dirty extents since the last rebase], D-06 [rebase protected from online GC, with a test], D-07 [open questions]. "Decisions on the research open questions": D-08 [deterministic chunking, zero-run shortcut], D-09 [no rebase at fsync; rebase in the callback that crosses the limit, and at close], D-10 [per-file dirty limit, start 32 MiB], D-11 [log-mode and replay RAM are follow-ups; Docker uses per-op], D-12 [keep or update the switch log text with the Phase 13 check in the same change], D-13 [splice API in scope]. Items of the superseded list that still apply: D-14 [record format unchanged: Op::Write, Op::Setattr], D-15 [shrink then extend: Setattr to the smallest size first], D-16 [write aliases: overlay on the owner state], D-17 [test_write takes the state out of open_files], D-18 [replay: a Write on a file with content starts an overlay on the manifest root; every base install stamps the inode size], D-19 [a base only the handle knows is a GC hazard], D-20 [relog in pieces; this phase uses 1 MiB].

D-09 overrides the "at fsync" part of D-04. BUFR-01 is read with the D-05 definition: a commit logs the bytes changed since the last rebase, bounded by the dirty limit, not by the file size. BUFR-03 is read as: the commit gate is never held exclusively (commit_cut, gc_start) for a hash; a rebase holds it shared.

This plan implements D-01 (switch, write, read, release), D-03, D-04 (close trigger), D-09, D-14 to D-19. D-12: this plan keeps the old text of the switch log line, so it and the Phase 13 Docker check stay in step; plan 14-04 changes both together.

Purpose: the hard user rule. The daemon never holds a whole file in RAM, not even as a fallback.
Output: overlay.rs (new) with property tests, filesystem.rs on overlays at every arm, one alias test.

A. New module `crates/slicefs-cli/src/overlay.rs` (pure data, no I/O), registered with `pub mod overlay;` in lib.rs.
- `pub const EXTENT_OVERHEAD: usize = 64;`
- `pub struct Overlay { pub base: Option<ObjectKey>, pub base_len: u64, pub visible: u64, pub size: u64, extents: BTreeMap<u64, Vec<u8>>, cost: usize }`. Invariants: visible <= base_len; extents do not overlap and do not touch (touching ones are merged); every extent ends at or below size.
- `Overlay::new(base, base_len, size)` (visible = base_len), `write(off, data)` (merge every overlapping or touching extent into one Vec; size = max(size, end)), `truncate(n)` (drop extents at or past n, cut the one across n, visible = min(visible, n), size = n), `cost()` = sum of Vec capacities + EXTENT_OVERHEAD per extent (Pitfall 7), `is_clean()` (no extents and visible == base_len == size), `extent_ranges()` (sorted ranges), `extent_count()`, `copy_out(off, len) -> Vec<u8>` (bytes of one range inside one extent), and a way to move pending writes in without a copy.
- A range view for reads: `view(off, len) -> RangeView` copies base, visible, size and only the extent parts inside [off, off+len). `RangeView::read(base_read: impl FnMut(u64, usize) -> std::io::Result<Vec<u8>>) -> std::io::Result<Vec<u8>>`: base bytes for [off, min(end, visible)), zeros up to min(end, size), extent parts laid over. Nothing in the module allocates by offset or by size.

If the stream has bytes (`next_expected_offset > 0`): base = `state.clone().finish()` (no zero padding), base_len = visible = streamed. Keep the eprintln line, its fields and its old text unchanged (D-12: plan 14-04 changes the text together with the Phase 13 check).

Delete the pwrite helper (no caller is left). Write aliases already resolve to the owner state through owner_fh (D-16); keep that.
- test_read: under the open_files lock take only `ov.view(offset, size)` of the overlay of this ino (the first state with this ino and byte_count > 0, as today), unlock, read the base part through the per-inode `readers` cache (key = base) and call `RangeView::read`. Memory is O(request).
- `fn rebase_overlay(&self, ino, s: &mut OpenFileState) -> Result<(), i32>`: if the overlay is clean, return. Else stream the merged content [0, size) into a fresh `Stream` in pieces of at most 1 MiB (each piece from a RangeView over a `content::Reader` of the base), `finish`, install with install_root (None when size is 0), set last_committed_root, and replace the overlay with `Overlay::new(root, size, size)`. - finalize_write (release, destroy): for an overlay, call rebase_overlay; no full-content `put_all` there.
- flush_handle: an overlay returns Ok at once (D-09: fsync is durable through the write log). Delete the snapshot variant that cloned the buffer.
- commit_cut, overlay arm (D-15): in the same place as the Streaming pending relog, log for each overlay `Op::Setattr { size: Some(visible), .. }` if visible < base_len, `Op::Setattr { size: Some(size), .. }` if size != visible, then the extents as `Op::Write` records of at most 1 MiB each (split a larger extent; no record may come near MAX_PAYLOAD = 64 MiB, which would stop the segment reader), then the existing ctime Setattr when ctime > time. No Op::Truncate for overlays (a resize to 0 clears the manifest). Plan 14-04 changes this to descriptors before the commit and pieces of at most 1 MiB after it.
