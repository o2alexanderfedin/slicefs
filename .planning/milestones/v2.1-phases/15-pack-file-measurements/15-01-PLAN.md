The header comment follows boost-test.sh: one line on what it measures, the usage line `seed-measure.sh <slicefs-binary> <data-dir> [runs]`, and the env list. - Arguments: $1 = slicefs binary (must be executable). $2 = data dir (when $2 is empty, use the BOOST_DIR env, as boost-test.sh does). The dir must exist. $3 = runs (else the RUNS env, default 3). A missing or bad argument prints the usage to stderr and exits 2.
- Env: WORK (default: a new `mktemp -d` dir; print "work dir: PATH" to stderr), LABEL (default: basename of the binary), INPUTS (default `rand` in this task; Task 3 widens it), RAND_BYTES (default 1073741824).
- When `uname -s` is not Darwin, print that the script needs macOS (stat -f, /usr/bin/time -l) and exit 2. A Linux run is a deferred idea; do not add GNU variants.
- stdout carries ONLY CSV. All progress goes to stderr. The header line is exactly: build,input,run,in_bytes,in_files,secs,mb_s,apparent_bytes,alloc_bytes,files,vt0_files,packs_files,segments_files,other_files,peak_rss_bytes (15 columns). Print the header first on stdout. At start, also write the header to $WORK/results-$LABEL.csv, replacing any older file of that name, so a re-run with the same WORK never mixes old rows into the new ones. Then append every row there too.
- Input `rand`: the source dir is $D/in-rand-$RAND_BYTES and it holds random.bin. When the file is missing, write it with `head -c $RAND_BYTES /dev/urandom` to a temporary name in the same dir, then mv it into place, so a killed run cannot leave a short file. When the file exists with a different size, exit 1 with a message. The file has its own dir because seed walks only directories.
- An input name that is not handled exits 2 with a message.
- Per input: in_bytes = the sum of `stat -f %z` over the source files (the fbytes pattern of boost-test.sh). in_files = the count of `find -type f`. Read every source file once to warm the page cache (find with -exec cat {} + to /dev/null).
- Per run i in 1..RUNS: store=${WORK:?}/$LABEL/INPUT/store-$i. Every rm -rf in the script uses a path built from the ${WORK:?} prefix and never removes WORK itself. Delete the store if it exists. Run `/usr/bin/time -l -o TIMEFILE "$B" seed "$store" "$src"` with the seed output going to a log file under $WORK. Pass only the two positional arguments and no options, because only the current build has the extra option. Do not name that option anywhere in the script, not even in a comment (an acceptance gate checks this). When the exit code is non-zero, print the label, input, run and exit code, plus the last 5 lines of the log, to stderr, and exit 1 without printing more rows.
- From TIMEFILE: secs = the first field of the line that contains " real". peak_rss_bytes = the first field of the "maximum resident set size" line (bytes on macOS).
- mb_s = in_bytes / 1e6 / secs, computed with a python3 one-liner, 1 decimal, with secs floored at 0.01.
- Store numbers: apparent_bytes = the fbytes sum over the store. alloc_bytes = `du -sk` of the store × 1024. files = the count of `find STORE -type f`. vt0_files, packs_files and segments_files = the same counts under those top dirs (0 when a dir is absent). other_files = files minus those three (for example FORMAT).
- Do not call the slicefs stats subcommand: its fields differ between builds.
- After the row is written, delete that store dir.
