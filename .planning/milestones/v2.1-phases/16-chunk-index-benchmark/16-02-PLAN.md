Project rules for this plan:
- Cargo needs `export PATH="$HOME/.cargo/bin:$PATH"`.
- No mounts. The bench works on pack files only.
- The stores are built once into a scratch directory OUTSIDE the repo and are never committed. The docs name it only as `$D`.
- Docs: plain ASD-STE100 English, no user home paths, no licensing talk.
- Long runs (100M create takes minutes; a full 100M run takes about 20-40 minutes) go in the background (run_in_background) and are waited on; do not poll with sleep in the foreground.

Expected values from 16-CONTEXT.md (for the sanity check, not targets): steady RSS about 153 B/object at 1M, 122 at 10M, 98 at 100M (hashbrown buckets, power-of-two sizing); peak about 147 B/object at 100M (old and new tables during the last resize); disk about 104 B/object (54 B record + 50 B idx entry); about 81 packs at 100M.

Environment at planning time: the host is macOS with 32 CPUs, 192 GiB RAM and about 700 GiB free disk. The OrbStack Docker VM reports MemTotal of about 16.8 GB, so the Linux 100M run will probably not meet the 20 GB condition of [Linux run]. That is the decision's own condition: record the reason, do not change the condition.
</context>
