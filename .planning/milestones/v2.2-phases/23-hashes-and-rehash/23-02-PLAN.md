<objective>
Give the store one crash-safe step that makes a new root and new roots for all snapshots current, and a GC entry that runs on a store that is already open under a held lock. These are the switch (step 4) and GC (step 6) of the rehash run; plan 23-04 calls them.

Task 1 is the tracer: one path through every layer this plan touches. The loaders keep the last record of each snapshot version, a switch segment supersedes a snapshot root, and `gc_on_open_store` on the open store frees the objects that only the old snapshot root used. Task 2 pins every crash state of the switch with unit tests (by file edits) and runs the plan gates.

Decisions this plan implements: D-19 (option a: superseding record in one new segment, last record per version), R-06, D-06 (switch crash states), D-20 and R-07 (GC entry on the open store, no second lock, no segment copy), D-04 (GC frees the old objects), the switch of D-18 step 4. Discretion choices (reversible, recorded here): stop points inside the switch are not added as hooks; the tests make each crash state by file edits (rename the `.seg` back to `.seg.tmp`, truncate it, restore old segment files from a copy). Plan 23-04 adds the step hooks of the whole run. The helper that removes old segments is the existing `wal::remove_segments_before`, made `pub(crate)`, not a copy.

Purpose: HASH-04 (crash-safe switch; GC frees the old objects after the switch).
Output: the loader rule, `write_switch_segment`, `remove_switch_tmps`, `gc_on_open_store`, tests.
</objective>
