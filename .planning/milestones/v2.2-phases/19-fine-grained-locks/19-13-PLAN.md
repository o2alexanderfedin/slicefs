<objective>
Close the WAL-writer part of LOCK-01 and the mkdir window of LOCK-04.

Orchestrator decisions implemented here (gap closure, reversible internals):
- G2 (WAL half): no WAL lock is held during the record pwrite. This covers `PerOpWal::write_out` and its drain, and the record write of the buffered strategies. F_FULLFSYNC vs fsync semantics do not change. Spike 19g: `wal_writer` hold p99 is about 20 ms on macOS, because the write waits behind a concurrent F_FULLFSYNC.
- G4 (LOCK-04, D-08): mkdir takes the inode number first, locks the `[parent, ino]` stripes, then calls `create_directory_at` with that number. This is what `new_entry` does for create, mknod and symlink since 19-10. Test: a racing create in the new directory can never log before its `Mkdir` record, and replay never stops.

Planner choices (reversible):
- One record write in flight per segment. Under `writer` a write-out takes the queued batch and reserves its sequence numbers and the end offset. It writes the frames (CRC computed outside the lock) with no lock. Then it publishes under `writer`. `SegmentReader` stops at the first cut, bad or out-of-sequence record, so a gap would lose every later record. One write at a time never leaves a gap, and the batch still carries every queued record (group write).
- Segment writes become positional (`write_all_at` on a shared file at the end offset). The buffered stream writer goes away.
- `rotate` stays as it is: it runs only offline (`snapshot switch`). It waits for no write in flight first. The SUMMARY lists it.

Purpose: the WAL locks cover memory work only, and namespace records keep their apply order for mkdir too.
Output: the positional segment writer, the unlocked write-out in all strategies, the cut without a file create under `writer`, and the mkdir stripes with their test.
</objective>
