<objective>
Take the slow tails out of the chunk-store lock `ChunkStore::inner` (RESEARCH Lock Inventory A rows 12-15): pack create, seal join, index run write, the KEEP_CAP wait, the trust-floor write and the pack open on a read. Prove each with a deterministic test in which another thread's `put` and `read` finish while one thread is parked inside the slow operation.

Decision IDs are numbered in 19-01-PLAN.md (objective). This plan implements:
- D-14 LOCK-01 scope: a page-cache `pwrite` under `ChunkStore::inner` is not disk I/O; pack create, seal join, index flush, fsync and the KEEP_CAP wait are, and must leave the lock.
- D-06 (use): every new or moved lock in chunk-store is `Rank::Store`.

Research spike (RESEARCH "Spike before 19-04", reversible: decide and report): Task 1 writes the tests first, records which rows hold the lock, and the per-row fix is chosen from the recommendations below; the SUMMARY names the fix per row.

Purpose: LOCK-01 names the store lock; ROADMAP criterion 3 needs it free of disk I/O and waits.
Output: hold knobs in `mem.rs`, `lock_tail_tests.rs`, the restructured tails in `lib.rs`, `retry.rs` (and `index.rs` if the run write needs a frozen memtable).
</objective>

Facts (verified at 2c39d65; line numbers move after Plan 01, grep the names):
- `put` takes `inner` and calls `append` (`lib.rs` near 1468): when there is no active pack it calls `self.io.create(num)` and writes the header under the lock; the record `write_at` follows; when the pack is full it calls `seal`, which first calls `inner.join_seal()` (waits for the previous seal's background fsync and `.idx` write). After the append `put` calls `flush_if_full` -> `inner.flush_index(&*self.io)` (writes an index run).
- `RetryingPack::write_at` (`retry.rs` near 228) runs under `inner`; when `kept > KEEP_CAP` it calls `settle(true)` (waits for the background sync); `start()` spawns it; `sync_here` syncs inline when the file has no sync handle.
- `raise_trust_floor` calls `self.io.write_durable(0, Kind::Trust, ..)` under `inner` (error path after a failed index read).
- `read` (near 2351) calls `inner.reader(io, pack)` (near 2949), which opens the pack file when it is not cached.
- `MemIo` (`mem.rs`) has `hold_syncs(on)`: while on, pack syncs wait on a condvar. `ChunkStore::open_with(Arc::new(mem.clone()), opts)` builds a store over it (see `race_tests.rs` `store`). `mem.rs` uses the shim since Plan 01 (`sync::Mutex`/`sync::Condvar`, `Rank::Store`).
- `gc_begin` also joins a seal under `inner`; it runs under the exclusive commit gate (RESEARCH Inventory B, known exception, not changed here).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| request threads -> ChunkStore::inner | puts and reads of many files share the store lock |
| process -> disk (crash) | packs, `.idx`, runs and the trust floor must stay crash-consistent when written outside the lock |
