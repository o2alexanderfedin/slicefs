<objective>
Finish the header rules of the chunk profile, give `seed` and `mount` the option `--chunk-profile`, show the profile in `stats`, and prove two profiles through the file-system layer in one process.

Task 1 adds the rules that pair the `chunks` line with the `chunk-profile` flag, plus the clap parser of the option, and runs the Kani gate. Task 2 wires `--chunk-profile` into `seed` and `mount`, with the refusals. Task 3 adds the stats line and field and the two-file-system test, and runs the plan gates.

Decisions this plan implements: D-02, D-05 (Kani and clippy gates), D-07, D-09 (criterion 4 at the command level), D-10 (pairing rules), D-11 (class recorded as confirmed), D-17 (refused values at parse), D-18, D-19, D-22 (slicefs-cli half), D-23, D-24.

Note on D-18 (reported to the orchestrator, not a scope change): `mount` cannot make a new store today. `load_store` refuses a path with no `segments/` and a store with no committed root, and the `header::check` doc says the same. So `--chunk-profile` on `mount` is a check against the recorded profile, and a new store gets its profile through `seed`. If the header is missing (a path with no store), the mount does not compare, and `load_store` gives its own refusal as today.

Discretion choices (reversible): the M9 reasons `chunks line with no chunk-profile flag`, `chunk-profile flag with no chunks line`, `the feature chunk-profile must be ro_compat`, `two chunks lines` and `bad chunks line`. A `chunks` line that names the default profile, with the flag, is accepted (this build never writes it). The value name of the option is `MIN/AVG/MAX`. The JSON field is an object of bytes.

Purpose: PROF-01 at the command level (set at `seed`, kept in FORMAT, a different profile refused at `mount`, default 4/8/32 KiB) and the slicefs-cli half of PROF-02.
Output: the header rules, the option on two commands, the stats line, and the tests.
</objective>
