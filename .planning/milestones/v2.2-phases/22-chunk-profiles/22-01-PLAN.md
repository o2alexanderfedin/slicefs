<objective>
Make the chunk profile a property of the store, end to end. A new store can record a FastCDC profile in its header. Every open of the content store takes the profile from the header, and every use of the chunk sizes in `file.rs` reads the profile of the store. The default stays 4/8/32 KiB with today's header bytes.

Task 1 is the tracer of the phase. It is the thinnest path through every layer that the phase changes: the chunk-store type and store field, the writer cut in `file.rs`, the `chunks` header line, the content open, and one end-to-end test. That test writes a profile header, seeds a tree with the existing `seed`, and finds the chunks of that profile in the store. Task 2 moves the other `file.rs` sites to the profile, with a per-store zero chunk. Task 3 adds the golden cut-point test, the two-store test and the old-reader check, then runs the plan gates.

Decisions this plan implements: D-01 (default unchanged), D-02 (header policy), D-04 (small file.rs change), D-05 (Kani, model and clippy gates), D-09, D-10 (line, flag, release constant), D-11 (class checked by a test), D-12, D-13, D-14, D-15, D-16, D-17 (limits), D-18 (the profile in the first header write; refuse another profile on an existing store), D-20, D-21, D-22 (chunk-store half).

Discretion choices (reversible, recorded here): the header word is `chunks` with sizes in bytes. The release word comes from `header::CHUNK_PROFILE_RELEASE`, with the placeholder value `v2.2` (the release name is an owner question, and tests use the constant, never the text). `chunk_ranges` and `CHUNK_MIN`/`CHUNK_AVG`/`CHUNK_MAX` stay as helpers of the default profile, used by tests and by `ChunkProfile::DEFAULT`, and no non-test code in `file.rs` uses them. The profile error type is `String`, as `parse_hash` uses. `Display` gives `16/64/256 KiB` when all three sizes are whole KiB, and `64/256/1024 B` when they are not.

Purpose: PROF-02 (every use reads the store profile; two stores in one process; golden cut points) and the store half of PROF-01 (one profile per store, kept in the format marker).
Output: the profile type and store field, the profile-aware `file.rs`, the header line, the content open, and the tests.
</objective>
