<objective>
Build the reproducible benchmark of the five chunk profiles: a Rust example that runs on the chunk-store API in process, and a driver script with a README. It runs by hand on macOS or Linux, never inside the test suite. Plan 22-04 runs it on the Boost data and writes the report.

Task 1 writes the example and checks it directly on a generated input. Task 2 writes the driver and README and runs the smoke mode on macOS. Task 3 adds a no-FUSE Docker mode, runs the smoke mode in Linux, and runs the plan gates.

Decisions this plan implements: D-03 (bounded memory of the tool), D-06 (not in cargo test), D-07, D-14 (the README note on metadata values), D-24 (no mount test), D-25, D-26, D-27. It uses the profile type of D-12 (plan 22-01).

Discretion choices (reversible): the example lives in chunk-store (no new workspace member and no Cargo.toml change). Output lines start with the subcommand word, followed by `key=value` fields. The cold open is a read-only open (it writes nothing and starts no merge thread). Edits are 4 KiB (`EDIT_SIZE`) on an edit base of the first 64 MiB of the probed file (`EDIT_BYTES`), so an insert near the start does not re-chunk the whole 823 MB tar nine times per run. Read latency uses 4 KiB reads: sequential over the first `SEQ_BYTES` (64 MiB), random `READS` (10,000) from a seeded xorshift. Latency is in microseconds with one decimal; p50 and p99 are nearest-rank.

Purpose: PROF-03, criterion 3 (one reproducible script that reports the metrics of the five profiles and runs outside the test suite).
Output: the example, the driver, the README, the Docker mode, smoke logs.
</objective>

Walk DIR for the apparent bytes (`metadata().len()`), the allocated bytes (`std::os::unix::fs::MetadataExt::blocks() * 512`) and the file count. - `probe --profile P --store DIR --key HEX [--seq-bytes N (67108864)] [--reads N (10000)] [--seed N (1)] [--edit-bytes N (67108864)] [--edit-size N (4096)]`: open the store writable (edits put objects). Sequential: one `FileReader` reads 4 KiB steps from 0 up to min(len, seq-bytes), timing each `read`. Random: `reads` uniform 4 KiB offsets in [0, len - 4096] with one `FileReader`. Print p50 and p99 (nearest-rank, microseconds, one decimal). Edits: write the first min(len, edit-bytes) bytes of the content as their own content (a `FileWriter` fed from a `FileReader` in 1 MiB pieces). This is the edit base, of length L. Then run nine edits on that base, each from the base, in the order modify, insert, delete at start (0), middle (L/2) and end. With k = edit-size: modify keeps L with changed [p, p+k), and its end p is L-k. Insert has new length L+k, keep p and changed [p, L+k), and its end p is L (an append: keep L, changed [L, L+k)). Delete has new length L-k, keep p and changed [p, L-k), and its end is a truncate (keep L-k, no changed range). New bytes come from a seeded xorshift. The `SpliceSource` serves each byte from the new bytes or from the base through a `FileReader` at the shifted offset, and holds no copy of the base (D-03). For each edit, take the `stats()` delta (objects, stored_bytes) and `SpliceStats::rechunked`, then read the edited window (up to 64 KiB around p) back through a `FileReader` on the new key and compare it with the expected bytes (exit 1 on a mismatch, so a broken path never gives numbers). Print one `edit kind=<modify|insert|delete> where=<start|middle|end> objects= stored_bytes= rechunked_bytes=` line per edit, then `probe seq_reads= seq_p50_us= seq_p99_us= rand_reads= rand_p50_us= rand_p99_us= edit_objects=<sum> edit_stored_bytes=<sum> edit_rechunked_bytes=<sum>`, then `close()`.
