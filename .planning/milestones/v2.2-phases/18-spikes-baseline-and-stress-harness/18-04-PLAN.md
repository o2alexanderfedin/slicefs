Per D-10, create `crates/slicefs-cli/examples/s1_probe.rs` from the RESEARCH skeleton, with these changes so each round reaches the server (no page-cache hit) and the result is clear:
- `lookup`: names `slow0` to `slow9` map to inodes `10` to `19` (READ of these is delayed 200 ms in the worker); every other name maps to inode 3. Replies use a zero TTL.
- Arrival and reply are logged to stderr (`ARR seq=.. unique=.. inflight=.. t_ms=..`, `REP seq=.. unique=.. t_ms=..`), as in the skeleton.
- `destroy` prints to stdout `S1 RESULT arrived=<n> max_inflight=<n> reply_order_inversions=<n>`. Also print that line when `mount` returns, so it is printed if `destroy` does not run.
- The macOS-only `MountOption::CUSTOM("backend=fskit")` stays inside `#[cfg(target_os = "macos")]`, so the file builds on Linux.

Create `scripts/macos-mount-test/s1-overlap.sh <probe-binary>` (bash, `set -u`, quote all paths). It works on macOS and Linux:
- Copy `mounted`, `waitmnt` (60 s limit plus `kill -0` of the probe), `waitexit` (60 s) and `run` (kill-based limit) from `large-copy.sh`; `trap cleanup EXIT` unmounts and kills the probe.
- Start the probe in the background on a temp mount point (`$WORK` or `mktemp -d`), stdout and stderr to files, and wait for the mount.
- 5 rounds; in round i: start `dd if=$M/slow$i of=/dev/null bs=4096 count=1` in the background and note the time; after 50 ms run a `python3` loop that calls `os.stat` on 50 new names `f$i-0` to `f$i-49` and records each latency in ms; wait for `dd` with a 10 s limit. Print `round=<i> dd_ms=<x> fast_stats_during_slow=<n> max_stat_ms=<x>` (a stat is "during slow" if it ended before `dd` ended).
- Unmount: on macOS `umount` then `diskutil unmount force`; on Linux `fusermount -u` then `umount -l`. Wait for the probe to exit (60 s limit), then print the probe's `S1 RESULT` line, `uname -sr`, and on macOS `sw_vers -productVersion`. Exit non-zero if there is no `S1 RESULT` line.

Add a mode `s1` to `run.sh`: build `--release -p slicefs-cli --example s1_probe`, wait until the container is 45 s old (as the `bigwrite)` line does), then run `/src/scripts/macos-mount-test/s1-overlap.sh /target/release/examples/s1_probe`. Add `s1` to the usage line and the header comment.

Run the control: `scripts/docker-linux-test/run.sh s1` (in the background with a 15 min limit), and save its output to `.planning/phases/18-spikes-baseline-and-stress-harness/runs/s1-linux-control.log` with a first line `# S1 Linux control, commit <short sha>, <date>`. Remove home paths from the saved text before commit. Expected: `max_inflight >= 2` and `reply_order_inversions >= 1` (Linux sends LOOKUPs while a READ of another inode is pending). If max_inflight is 1 on Linux, the probe is wrong: fix it before Task 2.
