- The type is `slicefs_cli::filesystem::SliceFsFilesystem` (Send + Sync + 'static). Use `slicefs_cli::handlers::handle_*`, not `test_*`: handlers append the WAL record. - File model per D-06: per 4 KiB block two `AtomicU32` values, `committed` and `pending`. Stripes of 16 blocks; stripe `s` is owned by thread `s % threads`; only the owner writes it. A write picks an owned stripe and 1..=16 blocks inside it, sets `pending = v + 1` before `handle_write`, sets `committed = v + 1` after it returns Ok. A read picks any range of 1..=16 blocks; for each block it accepts a version in the range [committed read before the op, pending read after the op] and compares the bytes with `block_bytes` for those versions. With serialize on, this range is one value, so the check is exact. After each write the thread reads its written range back and checks it (a check after each step).
- Setup: `handle_create` of `one-file` in the root (ino 1), `handle_setattr` with `size = Some(file_bytes)`, `handle_release`; then each thread opens its own handle with `handle_open(.., libc::O_RDWR)` and releases it at the end.
- One operation (per D-04 and D-07): if `serialize`, lock the harness `Mutex<()>` first; then time `gate.read()` on `fs.commit_gate()` as `gate_wait` (use `unwrap_or_else(|e| e.into_inner())` as `fuse_callbacks.rs` does); time the handler call as the op latency; record `gate_hold` when the read guard drops. Never take the serialize mutex while the gate is held (RESEARCH Pitfall 3).
- Errors: a handler `Error(errno)` becomes a `Mismatch` entry with the op name and errno; it does not panic in the worker.
- `fn verify_files(..) -> Vec<Mismatch>` after all threads are joined: read every block of the file through `handle_read` and compare with the model `committed` version. The test asserts the list is empty and prints at most the first 20 entries.
- Histograms per D-01: per thread and per op kind (`read`, `write`, `gate_wait`, `gate_hold`), `Histogram::<u64>::new_with_bounds(1, 60_000_000_000, 3)` in nanoseconds, use `saturating_record`; merge with `add` after the join. Create `crates/chunk-store/src/lock_stats.rs` and declare it `pub mod lock_stats;` in `lib.rs` (always compiled, so call sites in other crates need no cfg). Contents per D-02 and D-07:
- `pub enum Site { Store, Io, Wal, WalWriter, WalPending, OpenFiles, Readers }` with `pub const ALL: [Site; 7]` and `fn label(self) -> &'static str` giving `store`, `io`, `wal`, `wal_writer`, `wal_pending`, `open_files`, `readers`. All seven are defined now; Plan 02 converts the other sites.
- `pub const ENABLED: bool = cfg!(feature = "lock-stats");`
- `pub fn lock<'a, T>(m: &'a std::sync::Mutex<T>, site: Site) -> Guard<'a, T>`. Feature off: `#[inline(always)]`, body `m.lock().unwrap()`, and `pub type Guard<'a, T> = std::sync::MutexGuard<'a, T>` (same behaviour as today, including the panic on poison). Feature on: `Guard` is a `TimedGuard<'a, T>` that holds the std guard, the site and the acquire `Instant`, and implements `Deref` and `DerefMut`. Wait time: `try_lock` first; if it gets the lock, the wait is 0; on `WouldBlock`, time the blocking `lock().unwrap()`; on `Poisoned`, panic as `unwrap` does. Hold time: from acquire to drop. In `Drop`, compute the hold, release the std guard first, then record, so the recorder never runs inside a site lock and never adds to the measured hold.
- Recorder (feature on only): one `Mutex` per site (a static array built once with `std::sync::OnceLock`) that holds two `hdrhistogram::Histogram<u64>` values, `wait` and `hold`, in nanoseconds, each `new_with_bounds(1, 60_000_000_000, 3)`, recorded with `saturating_record`. The report values come from these histograms. Do not write bucket code by hand.
- `pub struct SiteStats { pub label: &'static str, pub count: u64, pub wait_p50_ns: u64, pub wait_p99_ns: u64, pub wait_max_ns: u64, pub hold_p50_ns: u64, pub hold_p99_ns: u64, pub hold_max_ns: u64 }`, `pub fn snapshot() -> Vec<SiteStats>` (one entry per site, in `Site::ALL` order; empty with the feature off) and `pub fn reset()` (clears all histograms; a no-op with the feature off). Doc comment: the recorder is process-global, so tests that run in parallel in one binary share it.

In `crates/chunk-store/src/lib.rs` change each of the 18 `self.inner.lock().unwrap()` sites to `lock_stats::lock(&self.inner, Site::Store)` (also the one inside `fn held()` and the one passed as `&mut ...` to `raise_trust_floor`, which takes `&mut Inner` through `DerefMut`). Change the field `g` of `struct Held<'a>` to `lock_stats::Guard<'a, Inner>`. Leave the `if let Ok(mut inner) = self.inner.lock()` in `impl Drop for ChunkStore` as it is, with a one-line comment: a drop must not panic on a poisoned lock, so it is not timed.

In `stress_harness.rs`: call `chunk_store::lock_stats::reset()` at the start of a run.
