Decisions that this plan implements (labels of 21.1-CONTEXT.md):
- [Header]: the text file `<store>/FORMAT` grows into the header; one item per line; durable write.
- [Number]: the first line is `slicefs-store 7 ...`.
- [Flags]: lines `compat <name> <release>`, `ro_compat <name> <release>`, `incompat <name> <release>`.
- [Parse order] (refined after research): collect the flags first; the strongest unknown flag decides; unknown lines are allowed only when a flag is unknown.
- [Number parse]: parse the number, do not compare the line.
- [Hash line]: `hash <name>` stays a store setting, not a flag.
- [Initial flags]: format 7 has no known flag (`KNOWN_FLAGS` is empty); tests use test-only names.
- [Release numbers]: tests use the test-only release token `r-test`; no real release number anywhere.
- [Durable first]: the header is durable before `packs/` exists.
- [Ro-compat], [Mount lock], [Ro tracer], [Ro requests] (no per-request EROFS check: the FUSE `RO` option stops writes in the kernel).
- [Snapshots]: a snapshot mount of a normal store keeps its current behavior.
- Claude's discretion (this plan decides): module `crates/slicefs-cli/src/header.rs`; the names below; the message texts M4-M10 (plain, short).
- Reversibility: the header layout and the names are reversible now (the format is not frozen; no deployments), so there is no checkpoint.
