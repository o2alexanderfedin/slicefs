## Deviations from Plan

### Decisions inside the plan (reversible)

1. **A text for a header that is not UTF-8.** The plan says "not UTF-8: error". The error is `InvalidData` with the text `{store}/FORMAT is not UTF-8 text; it is not a SliceFS store header.` (`msg_not_text`). Plan 21.1-04 must add it to the doc next to M10.
2. **`header::write_text` is `pub(crate)`.** `content::select_hash` needs the durable writer with a text (it still writes `marker(new)`).
3. **The stop steps on a failed mount.** Before, a failed `fuser::mount` stopped only the flusher and the online GC before `mounted?`. Now `Started::stop` runs before `mounted?` (as the plan says), so the commit timer and the segment GC are also stopped and joined on that path. Both stop at once (100 ms sleep pieces, `unpark`).
4. **`Started` holds a strong `Arc` of the file system during the mount.** Before, the file system went with `MountedFs` into `fuser::mount`. `stop` drops it before the lock, so `mount.lock` is still removed last.
5. **The pending-log test calls `flush_wal` before `std::mem::forget(fs)`,** as `tests/write_log_replay_tests.rs` does. The record count `n` comes from `scan_store_with_log` in the test, and the message must contain `{n} request(s)`.

## Notes for plan 21.1-02

- `--hash` and `--auto-snapshot` are silently ignored on a ro_compat mount now. Nothing is written: `load_store_read_only` does not call `select_hash`, and `test_destroy` returns before the auto snapshot. M11 and M12 are still to do.
- `header::check` is called only by `mount::start`. `run_mount` still calls `content::check_format`, and a format-6 store gets its "metadata in vt0/" text (M2 is still to do). Every first line with a number other than 7 gives M4.
- `content::open` still writes a header for any store without one, also a store with data (M1 is still to do).
- `select_hash` still writes `marker(new)`, so it drops the flag lines. It still checks `m.starts_with(FORMAT)`.
- `parse` does not check yet: the name and release grammar, a duplicate flag, two `hash` lines (`Header::hash()` takes the first one). A `hash` line that does not have exactly two words is a `Line::Other`, so it is refused as `unknown setting` when no flag is unknown. An empty line is also a `Line::Other("")`.
- `Started` has private fields for the threads and the lock. An integration test in `tests/` can only see `fs`, `config` and `access`. Add accessors if a test needs more.
- `check(Want::Mount)` on a store with no FORMAT returns `ReadWrite` with `header: None` and writes nothing.
- Message functions: `msg_unknown_format` (M4), `msg_incompat` (M5), `msg_mount_read_only` (M6, pub), `msg_ro_write` (M6w), `msg_log_pending` (M7, pub), `msg_lock_present` (M8, pub), `msg_bad_line` (M9), `msg_too_large` (M10), `msg_not_text`.
- Test helpers in `mount::tests`: `tree`, `diff`, `ro_fixture(flag)`, `append_line`, `ro_args`, `ro_access`, `read_file`, `read_all`, `RO_FLAG_LINE`.
- The `#[cfg(not(target_os = "macos"))]` form of `start` (`backend: Option<()>`) and the Linux call in `run_mount` were not compiled on this machine (no Linux target). The first compile check is CI or the Docker build of plan 21.1-03.
