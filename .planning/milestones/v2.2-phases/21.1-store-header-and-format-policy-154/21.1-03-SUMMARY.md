# Phase 21.1 Plan 03: stats shows the header; Linux ro_compat mount check Summary

**`slicefs stats` now shows the store format number, every feature flag (class, name, release, known here or not) and the access, in text and in JSON. An empty store with no header shows `none` (JSON `null`) and gets no header. A Linux Docker FUSE mount of a store with an unknown ro_compat flag is read-only: `touch` gives EROFS, there is no `mount.lock`, and the store tree (paths and sha256) is the same after the unmount. A store with an unknown incompat flag is refused by `mount`.**

## Deviations from Plan

### Extra task (orchestrator decision)

**1. gc, snapshot create and snapshot switch refuse a path that is not a store.**
- **Found during:** plan 21.1-02 (its SUMMARY: these commands made the directory and FORMAT on a missing path, then failed).
- **Fix:** `content::require_store(store)` refuses a path with no `segments/` directory. The three commands call it before `header::check`. `seed` and `mount` do not call it; they still make new stores.
- **Text:** `failed to load segments: store not found at {store}: no segments/ directory`. It keeps the old prefix `failed to load segments:` (before: `failed to load segments: segment I/O error: No such file or directory (os error 2)`) and the words of the stats/scrub/mount text `store not found at {store}: no segments/ directory`.
- **Test:** `a_write_command_on_no_store_makes_nothing`: a missing path stays missing, and an empty directory stays empty, after each of the three commands.
- **Files:** content.rs, gc.rs, snapshot.rs, tests/store_header_tests.rs. **Commit:** `fc2db01`.

### Decisions inside the plan (reversible)

1. **The flag order in the text** is compat, then ro_compat, then incompat (by class), not the file order. JSON has the same three lists.
2. **The control `tree-check-sees-a-change`** first checks that a plain copy gives the same `snap` (so the check is stable), then that an added empty file is seen.
3. **`incompat-refused`** makes `$R/mi` first, so the mount reaches the header check.
