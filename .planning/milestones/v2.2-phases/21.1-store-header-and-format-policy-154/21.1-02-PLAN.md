<objective>
Put the header check at every open point and before any write, add the refusals that plan 21.1-01 left (no header with data, formats below and above 7, the line grammar), keep flag lines and unknown lines on a rewrite, refuse write commands and the two writing mount options on a ro-compat store, and fix the test builders that make data with no header.

State at the start (after plan 21.1-01): `header::check` is called only by `mount::start`; `content::open` writes a header for any store that has none; `content::check_format` is called by mount, gc, stats and scrub; `check` refuses an unknown incompat flag (M5), an unknown ro_compat flag with `Want::Write` (M6w), any first line other than `slicefs-store 7` (M4), a flag line that is not three words and an unknown line with no unknown flag (M9), more than 64 KiB (M10); a ro-compat mount refuses `mount.lock` (M8) and a pending log (M7). `select_hash` still writes `marker(new)` (it drops other lines).

Decisions that this plan implements (labels of 21.1-CONTEXT.md):
- [New store]: the header is written only when the store is new (no entry in `packs/` and none in `segments/`); a store with data and no header is refused with a message that names the missing file.
- [Durable first]: for a new store the header is durable before `packs/` or `segments/` exist (seed checks first).
- [Number]: format 6 is refused with the older-SliceFS message (no migration).
- [Incompat]: refuse every command that opens the store; the message names the flag and its release.
- [Ro-compat]: write commands (gc, seed, snapshot create) refuse; read commands (stats, scrub) run. Snapshot switch writes, so it refuses too; snapshot list reads, so it runs.
- [Compat]: unknown compat flags are kept on a rewrite. With the refined [Parse order], unknown lines next to an unknown flag are kept too.
- [Where]: one module, the check at the open points and before anything writes.
- [Ro options]: a ro-compat mount refuses `--hash` and `--auto-snapshot`.
- [Empty store reads]: a read command on an empty store with no header writes nothing (stats shows `none` in plan 21.1-03).
- Claude's discretion (this plan decides): the name grammar (1 to 64 of `a-z`, `0-9`, `-`; starts and ends with a letter or digit; no `--`), the release grammar (1 to 32 visible ASCII characters, no space; opaque: shown, never compared), the texts M1-M3, M11, M12; the new integration test file. Reversible (the format is not frozen), so no checkpoint.

Purpose: an old or wrong store can no longer be opened or changed by any command, and a store with a future feature is treated by its class.
Output: the full open rules, the check at every open point, the command-level tests, the builder fixes.
</objective>
