<objective>
The written review of the `unsafe` code that Miri cannot run (TSAFE-06), in every crate of the build, plus a check on every build that the review stays complete: a new `unsafe` token fails CI until the review counts it.

Decisions this plan implements: D-24 (scope widened to every crate), D-25 (recount, test code as summary lines), D-14 (the pack_io list and what Miri runs), D-11 (vendor/fuser reviewed, not linted), D-33 (the pid guard only as a follow-up).

Check form (recorded, reversible): the count is the number of `unsafe` word tokens per file (`grep -ow unsafe`, comments included), the same rule in the doc and in the script, so the numbers are easy to check by hand.

Purpose: Miri runs only the `RunMap` part of the chunk-store `unsafe`; FFI, file mapping, signal handling and the vendored FUSE layer need a written argument.
Output: docs/design/unsafe-review.md, unsafe-count.sh, one line in clippy.sh.
</objective>
