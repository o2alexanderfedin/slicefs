# Phase 21.2 Plan 06: Loom models of the commit gate and the shared dirty budget Summary

The real commit gate functions and the real throttle wait, flusher loop, notify and stop now run under loom through the `sync::raw` cfg point. Three new models pass at the CI bound 3. Each was red on a fault planted in the product code. With the pool models of plan 01, TSAFE-02 now has models of the worker pool, the shared dirty budget and the commit gate.

## What was built

- **The gate through `sync::raw`.** `commit_gate: Arc<raw::RwLock<()>>` (std `Arc`), `commit_gate()` returns that type (the same std type without loom). `GateHold` holds `raw` guards. `gate_xwaiters` and `ExclusiveWait` use `raw::atomic::AtomicUsize`. `commit_timer.rs` takes `RwLock` from `chunk_store::sync::raw` and keeps std `Arc`/`Weak`. `RwLock` left the std import of `filesystem.rs`. No new name was needed in `raw`.
- **Gate seams.** `pub(crate) fn hold_shared(gate)` (rank entry, then `read()`) and `pub(crate) fn hold_exclusive(gate, xwaiters)` (rank entry, `ExclusiveWait`, `write()`, wait marker dropped). `gate_shared` and `gate_exclusive` call them.
- **Budget seams.** `pub(crate) fn throttle_wait(ctl, now) -> bool` holds the wait part of `throttle_write`, from `throttled` +1 to `max_wait_ms`. The comment "the flusher lowers the total before it takes this lock to notify, so no wakeup is lost" stays with the loop. `throttle_write` keeps the debug panic, `dirty_now`, `kick_flusher` and the two early returns. `FlushCtl::request_stop` holds the stop step (`stop` under `flags`, `wake` and `freed` notify). `stop_flusher` keeps its debug panic and the join. `flusher::flusher_loop` is `pub(crate)`.
- **Protocol atomics.** `running`, `empty_pass`, `throttled_now`, `throttle_wait_ms` and `pass_ms` of `FlushCtl` are `raw::atomic` types, and `ThrottledNow` takes the `raw` type. These fields use only `load`, `store`, `fetch_add` and `fetch_sub`.
- **Fields kept std:** all stat counters (`passes` ... `started_ms`, `clock_offset_ms`, `idle_ms`, `expire_ms`, `hot_ms`). They are not part of the wait protocol. `max_wait_ms` uses `fetch_max`. The models read `stop_exits` only after the joins.
- **Models** in `#[cfg(all(test, loom))] mod loom_tests` at the end of `filesystem.rs`. Thread counts include the model main thread:
  - `loom_gate_commit_excludes_requests` (M3, 4 threads). Two requests each hold the gate shared, lock the stripes of inodes 1 and 2 in opposite argument order (the model asserts the two stripes differ), lock their cell, then count `started` and `finished`. The committer holds the gate exclusively, asserts `started == finished`, then locks each cell once. It uses the real `NamespaceLocks::new()` and shim `Mutex::new_keyed(Rank::Cell, ..)` cells.
  - `loom_throttle_writer_leaves_after_a_pass_frees` (M2, 3 threads). It uses a real `FlushCtl::new()` with both limits at 3 600 000 ms, and `running` and `kicked` set beforehand, as `throttle_write` finds them before the wait. The flusher runs `flusher_loop` with a pass that lowers the model total and calls `notify_freed` only when it finds the total at or above the budget. The writer must return `false` (no pay). Then main calls `request_stop` and joins the flusher, and `stop_exits` must be 0.
  - `loom_throttle_stop_wakes_two_writers` (M2, 4 threads). The pass frees nothing. Two writers wait in `throttle_wait`, and main calls `request_stop`. Both writers must return `true`, `stop_exits` must be 2, and the flusher must end.

No behavior change: `flusher_tests` (26) and `dirty_budget_tests` (1) passed with no edit. `git show --stat` of both commits lists neither file, and also nothing in `oplog.rs` or `crates/metadata/src`.

## What loom cannot see (also in the model doc comments)

- loom's `RwLock` lets a new reader in whenever no writer holds it (reader-preferring). loom reports deadlocks and failed asserts, not starvation. So M3 does not show the queued-commit deadlock of `.planning/research/STACK.md`: a queued exclusive commit blocks new shared holds while a shared holder waits for the budget. Other checks cover it: the debug panic of `throttle_write` under any ranked lock, the `Rank::Gate` same-thread rule (test `gate_after_a_lock_panics`), the S5 gate spike and the stress harness.
- `Mutex<StoreIo>` is not modeled. It is a std lock of rank 6 (a leaf) with no condvar, held only for short store calls. The models replace the store with closures, and TSan and the stress run cover it.
- `commit_timer::commit` takes the gate with its own inline code, not through `hold_exclusive`. M3 covers the steps of `hold_exclusive` only. That copy was not refactored (out of scope).
- Real time is not modeled. The limits are one hour, and under loom `wait_for` never times out. So a lost wakeup shows as a deadlock report (RESEARCH Pitfall 4).

## Deviations from Plan

### Plan text conflicts

**1. Red run 1 plant in product code.** Task 1 step 4 says to plant "lock cell a before `hold_exclusive`" in the model committer. That gives a deadlock, not the `started == finished` failure that the same step asks for. The must-have truth and the required log header both say "`hold_shared` without the gate read", so that is the plant used.

**2. M2 model 1 pre-sets `kicked` and frees only at or above the budget.** Without the pre-kick, the first pass can begin only after the writer parks, because the writer holds `flags` from its kick to its wait. If every pass notifies, the writer's own kick always causes a later pass whose notify comes after the park. In both cases the planted lost wakeup cannot be reached. With the kick that `throttle_write` makes before the wait (`kick_flusher`), and a pass that does not notify when it frees nothing, the plant gives a deadlock and the real code passes. The model also pre-sets `running`: `throttle_write` enters the wait only after it saw `running`.

### Auto-fixed (Rule 3, blocking)

**3. `tests/stress_harness.rs` imports the gate type from `sync::raw`.** Its field `gate: Arc<RwLock<()>>` named the std type, so under `--cfg loom` it did not match `commit_gate()`, and the loom clippy form (`--lib --tests`) did not build. The fix is a type change only, and the unused std `RwLock` import was removed. The file is not in `files_modified`. Commit 5751c38.

**4. Doc list lint.** A doc line that starts with `+ 1 committer` failed `clippy::doc_lazy_continuation` under loom clippy, so the text was reworded.

### Small choices

**5. The red run 2 log has no `test result: FAILED` line** (SIGABRT after the deadlock panic, see above). The Task 2 verify checks only the `# red run 2` header.

**6. Extra red run 3.** The plan asks for one red run per task. The stop model was also shown red on a planted fault (orchestrator rule: every model red first). It ran after the Task 2 commit and changes only the log.
