<objective>
Fix race (b) of Phase 19: a cross-directory rename has no ancestor check, so a directory can move into its own subtree and leave a detached cycle (the directory leaves the tree with its children). A test that calls the daemon path in process fails first; then the fix walks the `..` chain of the target parent under the rename mutex and refuses with `EINVAL`; then a short stress test stays in the suite.

Decisions this plan implements: D-26 (failing test first, then the fix, then a test that stays in CI), D-28 (the walk under the rename mutex, `EINVAL`, in the daemon), D-29 (the fallback rule), D-21 (the CI-kept check of this race is its stress test; see the note below), D-33 (no other behavior change).

D-21 says "one model per race fix is also kept". This plan keeps a stress test, as D-26 and TSAFE-03 allow ("a model or stress test"). A loom model of this race would need the whole file system (store I/O, zstd C code), and a copy of the protocol is not allowed (D-20). The walk itself is sequential code under one mutex; the stress test checks the walk and the lock together.

Purpose: the multi-worker Linux default (Phase 21) made this race reachable for in-process callers and for FUSE-T/FSKit; the Linux kernel probably refuses it in the VFS first (RESEARCH A4), so the daemon must check for itself.
Output: `check_not_ancestor`, its call in `rename_held`, `tests/rename_ancestor_tests.rs`, three run logs.
</objective>
