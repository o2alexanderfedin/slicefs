# Phase 21.2 Plan 04: Race (a), the closed-file size change Summary

A size change of a closed file now claims the inode under its stripe and pins it like an open handle. An unlink during the splice keeps an orphan that is reclaimed after the change, and a setattr of other fields in the claim window waits for the transient cell. The inode writes and the log records are in the same order.

## What was built

- `setattr_size_logged` (`filesystem.rs`). Each pass of the loop takes `stripe(ino)` first. This replaces the old stripe round trip and keeps its create-ordering purpose (WR-03) for both cases.
  - Case A (open cell): the map is read under the stripe, the stripe is dropped, then the cell is locked as before.
  - Case B (closed file), under the stripe: `get_inode` must succeed, else `ENOENT`. Then the transient cell is made and locked (stripe 3 before cell 4) and inserted, and `pin_inode(ino)` runs. Then the stripe is dropped. The splice, the install and `log(size_op())` run under the cell. Then the cell is retired, removed and dropped, and `uncount(ino)` releases the pin. There is no return path between the pin and `uncount`.
- `fn pin_inode` raises `open_count` by one with no `by_fh` entry. An unlink then keeps the inode as an orphan (`drop_last_link`), and `uncount` reclaims it with its new manifest.
- `setattr_size_closed`: the old root is released once, after `set_manifest` succeeded (size 0 and size above 0). An error path releases nothing. The new root is counted before the old root is released.
- Pause hook (tests only, the same style as the rebase hook): `Pause::SizeClaimed` (case B, after the claim) and `Pause::FieldsStriped` (`with_inode_locked`, after the map read and before the cell lock). The private `fn pause` clones the hook out of its lock.
- Tests:
  - `an_unlink_inside_the_splice_keeps_the_shared_content` (integration). `f` and `g` share one root. The rebase hook parks the splice of `f`'s size change, the main thread unlinks `f`, then the hook is released. Asserts, in this order: the result is `Ok`; there is no manifest and no inode of `f`; no orphan is left; `g` keeps its manifest and reads back; the refcount of the shared root is 1 (stats evidence only).
  - `an_unlink_inside_the_splice_replays_to_the_live_state` (integration, per-op write log). The same sequence through the handlers. The log has the `Unlink` before the size `Setattr`. After a crash, replay gives the live dump and `g` reads back. Replay reclaims `f` at the `Unlink` and skips the `Setattr` of the gone inode by the existing rule in `oplog.rs`, so `oplog.rs` did not change.
  - `a_fields_setattr_in_the_claim_window_keeps_the_record_order` (in-crate). The size change is parked at `SizeClaimed`, then the fields call at `FieldsStriped`, and the size log closure is a third pause. The live mtime must match the last record.
  - `stress_size_changes_and_unlinks_of_closed_files`. 8 rounds; in each round, 20 size changes race one unlink, with sizes in 0..128 KiB and seed `0x210204`. Each result is `Ok` or `ENOENT`, never `EIO`. Asserts: no orphan; no manifest and no inode of `f<k>`; `g<k>` keeps its manifest and reads back; the refcount is at least 1 (stats only). It has no ignore attribute.

## Behavior changes (the only ones)

1. A size change of a closed file that is unlinked during its splice succeeds: `setattr_size_logged` (and `test_setattr_size`) returns `Ok` (before: `EIO`), logs its record, and leaves no manifest of the deleted inode and no leaked count. A FUSE setattr (`handle_setattr`) always runs the fields step after the size step (it sets the ctime, also when all other fields are `None`). That step then finds the reclaimed inode, so the request returns `ENOENT` (before: `EIO`). This is valid: it is the order "unlink, then setattr". Orchestrator decision: the plan truth says "returns `Ok`"; this holds for the size change, not for the whole FUSE request.
2. A size change of an inode that does not exist returns `ENOENT` (before: `EIO` from `stamp_size`).
3. The old root is released once, after the install (before: before the splice, and a second time by the reclaim of an unlink in the splice).
4. A fields setattr that reads the cell map in the claim window waits for the transient cell, so its inode write and its record both come after those of the size change.

No new `Op` and no store format change. `git diff ee5dbe6 -- crates/slicefs-cli/src/oplog.rs crates/metadata/src` is empty.

## D-27 variant (recorded)

D-27 says "re-check the inode under its stripe before the install; move the install out of the cell hold". This plan uses the research variant: the claim under the stripe plus an open-count pin, with the install kept in the cell hold. If the install moved out of the cell hold, an open or a second size change could enter between the splice and the install. The pin gives the same guarantee: the inode cannot be reclaimed during the install. The change is reversible (one function).

## Pitfall 10 side effect

A fields setattr that finds the transient cell now waits for the splice with its stripe held. The wait is bounded by one splice, which re-chunks only near the end. About 1/256 of inodes share a stripe. Before the fix this wait already happened for a fields call that read the map after the insert. It was not measured; `lock_wait_rows` can show it if an owner wants numbers.

## Deviations from Plan

### Orchestrator corrections

**1. T-21.2-09 rated medium, not high.** The plan text (objective, the window 1 truth, the threat register) now says: a double release gives wrong refcount stats, and also possibly EIO, an orphan or a stale manifest. It cannot free content that another file uses, because GC is reachability (mark and sweep), and the refcount table only feeds `stats` and the saturated line of `scrub`. In the tests, the refcount asserts are labeled stats evidence. The main asserts are on the result, the metadata of the deleted inode, and the other file's manifest and bytes. No new logic uses the table (#165 removes it).

**2. [Rule 3 - Blocking] Gate rule.** The orchestrator rule (`timeout 3600`, 4 child tests skipped) replaced plan rule 2. In the Task 1 gate the time limit was reached with all binaries so far green, and the rest were run alone, as the orchestrator rule allows.

### Small choices

**3. The replay test accepts `Ok` or `ENOENT` from `handle_setattr`.** The plan expected the first assert to be `Ok`. After the fix, the size part succeeds and logs its record. Then the fields part of the same request (ctime) finds the inode reclaimed by `uncount` and returns `ENOENT`. Before the fix the result was `EIO`, so the assert still fails first. The log-order assert and the replay assert are as planned.

**4. Mutation run plant.** The plant removes both `pin_inode` and its `uncount`. Without the pin, `uncount` panics on its `expect`, and that tells nothing about the race. The plan text was updated.

**5. Extra metadata asserts.** The window 1 test and the stress test also assert that the inode of the deleted file is gone and that the other file keeps its manifest.

**6. The new root is counted before the old root is released.** The plan only said "after `set_manifest`". This order keeps the count when the splice gives back the same root.
