```rust
pub fn test_write(&self, fh: u64, offset: u64, data: &[u8]) -> Result<u32, i32> {
    // Phase 10: sequential writes only. Non-sequential offset detection is Phase 11.
    // For now, accept any offset -- push_bytes always appends sequentially.
    // The offset parameter is validated in Phase 11 (STRM-02).
    let mut open_files = self.open_files.lock().unwrap();
    let state = open_files.get_mut(&fh).ok_or(libc::EBADF)?;

    // Acquire io lock for FileStorageAdd (release open_files first to avoid lock inversion)
    // BUT we need mutable access to state while holding the FSA...
    // Solution: we need io within the open_files lock scope here because push_bytes needs both.
    // This is safe because no other code path holds io then tries open_files.
    // Lock ordering: open_files -> io is canonical.
    let mut io = self.io.lock().unwrap();
    let mut fsa = FileStorageAdd::new(&mut *io);
    state.state.push_bytes(&mut fsa, data);
    drop(fsa);
    drop(io);

    state.byte_count += data.len() as u64;
    state.cas_committed = false;  // New writes invalidate prior CAS commit
    Ok(data.len() as u32)
}
```

IMPORTANT: The current test_write uses offset to position data in a Vec. With push_bytes, data is always appended sequentially. In Phase 10 we only handle sequential writes (offset == byte_count).
