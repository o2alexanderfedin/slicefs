<objective>
Build the rehash engine: given a chunk store opened with the target hasher and the current root plus the snapshot roots, write every live value under the target hash and return new roots that decode to the same tree, with bounded memory and verified reads. Also a dry-run walk that writes nothing. Plan 23-04 wraps it in the `slicefs rehash` command (checks, switch, header, GC, report).

Task 1 is the tracer: one root goes through every layer of the engine (byte copy of values, the key-carrying nodes, the refcount sort, the root record) and decodes to the same tree, with every object of the target tag and every file key equal to a fresh write. Task 2 adds the on-disk old-to-new map with the fixed RAM cache, many roots with shared values, and the kept-as-is rule. Task 3 adds the dry-run mode, progress, the stop hook, the error paths and the durability check, and runs the gates.

Decisions this plan implements: D-04, D-05, D-12 (with R-04: no chunk-reuse path), D-13 (with R-03), D-14, D-15 (with R-05), D-16 (with R-02), D-22 (engine half), R-10, R-11, and the engine half of D-21 and D-18 (progress, stop hook). Discretion choices (reversible, recorded here): the map key includes a node-kind byte (slot 67 bytes, not 66; RESEARCH Q5 had 66) because one old key can be both a file and a node; the refcount sort rows are 49 bytes (new key, count, row index) because the sorter removes identical rows; type names `RootSet`, `RehashOptions`, `Mode`, `Stats`, `RehashError`, `KeyMap`, `Kind`. Engine unit tests use `TestKeyedBlake3` as the second hash (plan 23-01 adds SHA-256 in the same wave; plan 23-05 covers SHA-256 end to end).

Purpose: HASH-02 (rewrite of all objects; fresh-write keys), HASH-04 (verified reads; new objects durable before a switch), HASH-05 (bounded memory, no in-RAM map of all objects; dry-run counts).
Output: `crates/metadata/src/rehash/` (engine and map), visibility changes, unit tests.
</objective>

Engine (`crates/metadata/src/rehash/mod.rs`, D-12, D-13, R-03, R-04, R-05). Module doc: what the engine does, the two primitives (byte copy of a value; translation of a key-carrying node), why values are streamed through `FileWriter` (manifest node cuts depend on IDs, `is_cut`), that directory name keys do not change, and the RAM bound. One walker struct holds `&ChunkStore`, the target hasher, the map (a `KeyMap`; in this task a fixed-size in-RAM direct-mapped stand-in with the same `get`/`insert` signature is enough; Task 2 replaces it with `rehash::map::KeyMap`), `Stats`, the options and, for each refcount table, the sorter. In `Mode::Rewrite`, first check `cs.hasher().tag() == opts.target.tag()`, else `RehashError::WrongHasher`. Translation functions, each first looking up the map with its own `Kind` and inserting the result after success:
- value (`Kind::Value`): stream the value with `FileReader` in reads of `WINDOW` into a `FileWriter`; return `to_key(finish)`. A zero-length value is written as an empty `FileWriter`. Count `values_read`, `bytes_read`, `values_rewritten`. A read error becomes `RehashError::Read { what, key, source }` with the node kind in `what` (`file content`, `inode node`, `directory node`, `xattr node`).
- manifest list (`Kind::ManifestList`): the length must be a multiple of `KEY_BYTES`, else `Corrupt`; read windows of whole keys, translate each with the value function, write the new keys in the same order.
- `u64 -> key` map (`Kind::ValueMap` for inode, directory and xattr data; `Kind::ManifestMap` for manifest data): read the 8-byte count, check with checked arithmetic that the length is `8 + count * MAP_ENTRY` (else `Corrupt`, before any large read), then windows of whole records (about `WINDOW / MAP_ENTRY` records); check `ino` strictly ascending; translate each key (value function, or manifest-list function for `ManifestMap`); write the same count and the records in the same order.
- inode map (`Kind::InodeMap`): as above with no count; length a multiple of `inode_map::RECORD`.
- refcount table (`Kind::Refcounts`): check the length as for a map with 41-byte rows; translate each row's key with the value function; on `RehashError::Read` whose source is `chunk_store::Error::Missing` drop the row and count `stale_refcounts` (manifests are translated first, so a missing object here is used by no manifest of this root); any other error stops. Push each kept row into a `Sorter<49>` in a `TmpDir` under `map_dir`: new key (33), count big-endian (8), row index big-endian (8). Then read the sorted file twice: first count the distinct new keys, then write `[distinct count u64 LE]` and, per distinct key, `key + saturating sum of its counts (u64 LE)`.
- root record (`Kind::Root`): `FileReader::open`, the length must be `root_rec::SIZE` before the read (else `Corrupt`); translate in this order: inode map, inode data, directory data, xattr data, manifest data, refcounts; copy every other field; `put_value` of the new 230 bytes.
