Facts (verified at 3bdfa89):
- `slicefs_cli::seed::run_seed_with(store, src, hash, profile)` (seed.rs 46); `chunk_store::ChunkProfile::new(16384, 65536, 262144)`; a sparse source file is made with `File::set_len` (it reads as zeros).
- Mixed-tag trees come from a partial write of an old file after a hash change: `content::select_hash(&store, Some("test-keyed-blake3"))`, `open_fs`, `test_open` + `test_write` of a middle range + `test_release`, `close_fs` (RESEARCH Q3: splice keeps old entries and nodes with their old tags).
- `content::put_all(&cs, &bytes)` returns the key of a fresh write in that store (a dedup hit when the bytes are stored already). `chunk_store::file::file_objects` lists every object of a value (fine in tests). `ChunkStore::contains(&id)`.
- `scrub::run_scrub(store, false)` is Err on any bad object; `metadata::segment::load_store_from_segments` gives the root and snapshots.
- `docs/design/chunk-store.md` "Object IDs and the hash" (178-212) says at 205-207 that a conversion is future work (#62); "GC" (1259) and "Full GC" (1399) describe the mark. `docs/design/store-format.md` class table (121), store lock (214-260), messages M13-M15 (281-283), no-store text (316-319). README lines 12 (hash agility) and 63 (repo layout).
- Pack files are `<store>/packs/{num:016x}.pack`, with a `.idx` for each sealed pack and index `.run` files in the same directory (chunk-store `pack_io.rs` 50-52). `run_seed_with` ends with `cs.close()` (seed.rs 98), which seals the active pack and writes its `.idx`. An open takes the entries of a pack with a valid `.idx` from that `.idx` and does not read the pack (`ChunkStore::load`, chunk-store lib.rs 1525); only a pack with no `.idx` is scanned, and the newest such pack is cut at its first bad record (lib.rs 1545), so a flip there reads as `Missing`, not `Corrupt` (chunk-store `tests/store_tests.rs` `a_flipped_byte_in_a_record_is_detected`). Damage in a `.idx` or `.run` file makes the open rebuild the index from the packs. A record is the 33 ID bytes first, then flags and the raw and stored lengths (42 header bytes in all), the payload and a CRC; `read_record` (lib.rs 2941) returns `Error::Corrupt("object {id:?}")` (Display `damaged data: object ...`) on a bad CRC or hash. `ObjectId(pub [u8; 33])`; `chunk_store::chunk_ranges(&data)` gives the default-profile chunk ranges and `Blake3_256.id(&data[r])` the chunk IDs (as in chunk-store `tests/store_tests.rs` 178-194); `FileWriter::cut` (chunk-store `file.rs` 157-161) puts each range of `store.profile().ranges` and only then pushes its entry, so in a seeded default store these are the stored chunk IDs, and each chunk record comes before any file node that lists it.
