**stats.rs — `run_stats(store_path: &Path, json: bool)`:**

1. Follow the gc.rs offline pattern: check `mount.lock` but DO NOT refuse — stats should work on mounted stores too (read-only scan). Print a note if mounted.

2. Load store: `load_store_from_segments(&segs_dir)` to get `(dict, root_opt, snapshots)`.

3. Reconstruct metadata: `DictMetadataStore::load_from_root(dict.clone(), &root)` to access `logical_bytes()` and refcount data.

4. Compute stats:
   - `logical_bytes`: from `meta.logical_bytes()`
   - `block_count`: `dict.len()` (number of unique dictionary entries)
   - `physical_bytes`: `dict.len() * 92` (each Dictionary entry is 92 bytes — 28-byte Digest224 key + 64-byte Branches). Document this is dictionary metadata size, not block content size.
   - `dedup_ratio`: `logical_bytes as f64 / physical_bytes as f64` (guard against div by zero: if physical is 0, ratio is 0.0)
   - `snapshot_count`: `snapshots.len()`
   - `compressor`: read from store format version — if store_version >= 2, blocks have compression header. For v1 stats, just report "unknown" or infer from segment data. Simpler: hardcode "zstd (default)" since Phase 6 made zstd the default. This is informational.

5. Compute refcount distribution: iterate `meta.refcounts` (access via a public accessor — if `refcounts` is private, add a `pub fn refcount_distribution(&self) -> (usize, usize, usize)` method to DictMetadataStore that returns (unique, shared_2, shared_3plus) by iterating the BTreeMap). If adding a method is too invasive, compute distribution by iterating all dict keys and calling `get_refcount()` on each.

6. Per-snapshot stats: for each snapshot, use `collect_live_set(&dict, &[snap.root])` to get the set of blocks reachable from that snapshot. Compute unique block count and approximate size. This is optional/best-effort — if it's too slow for large stores, note "use --json for per-snapshot breakdown" and skip in human output.

7. Define `#[derive(Serialize)]` structs: `StoreStats`, `RefcountDist`, `SnapshotStats`.

8. Output: if `json`, `serde_json::to_string_pretty(&stats)` to stdout. If human, print a formatted table with labeled rows.

**scrub.rs — `run_scrub(store_path: &Path, json: bool)`:**

1. Check `mount.lock`: if present, print warning "Store is mounted; scrubbing closed segments only. Active writes not covered." but DO NOT refuse.

2. Load store: `load_store_from_segments(&segs_dir)` to get `(dict, root_opt, snapshots)`.

3. Walk all dictionary entries. For each `(key, branches)`:
   - The key is a `Digest224`. The branches contain the actual data or child references.
   - Re-compute the digest of the entry's content. The blockset Dictionary stores entries as `(Digest224, Branches)` pairs. The Digest224 key is the hash of the content that was interned. To verify: look up the entry by key, extract its raw content bytes, re-hash with the same algorithm, compare to key.
   - IMPORTANT: The Dictionary is a Merkle tree. Leaf entries contain raw data; internal entries contain child digests. The verification should check that for each key, `dict.get(&key)` returns the expected branches, and re-computing the digest of those branches matches the key. Use `blockset`'s digest computation (`blockset::to_digest224` or equivalent).
   - If the re-computed digest does not match the stored key, record as corrupted.

4. Define `#[derive(Serialize)]` structs: `ScrubReport { blocks_verified, corrupted_blocks, status }`, `CorruptedBlock { hash: String, corruption_type: String }`.

5. Output: if `json`, `serde_json::to_string_pretty(&report)`. If human, print summary line. If corruption found, list each corrupted block hash.

6. Exit code: return `Err` (which causes `std::process::exit(1)` in main.rs) if any corruption found.

7. Add unit tests in both files using `#[cfg(test)]` modules:
   - `stats.rs`: test with a fresh `DictMetadataStore` (empty store produces zero stats)
   - `scrub.rs`: test with a fresh store (no corruption = clean report)

NOTE on blockset Dictionary API: The executor should examine `blockset::Dictionary` methods to find how to iterate entries and retrieve content. Key methods are likely `iter()`, `get()`, `len()`. If `iter()` is not available, the scrub may need to use `collect_live_set` to enumerate all keys, then verify each.
