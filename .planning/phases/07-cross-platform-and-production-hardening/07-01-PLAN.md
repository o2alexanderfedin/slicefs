<task type="auto">
  <name>Task 2: Fix FUSE-T write path with direct_io mount option</name>
  <files>crates/slicefs-cli/src/mount.rs</files>
  <action>
The FUSE-T write bug root cause (confirmed via FUSE-T issue #45): macOS NFS client caching. FUSE-T translates FUSE to NFSv4. The NFS client considers writes complete before the NFS server has committed. Reads hit stale cache and return empty data.

Fix: Add `direct_io` mount option on macOS to bypass NFS page cache. This makes every read/write go directly to the FUSE handler.

1. In `build_mount_options()`, add a parameter `allow_other: bool` and detect macOS at runtime using `cfg!(target_os = "macos")`:
   - On macOS: push `MountOption::CUSTOM("direct_io".to_string())` to mount_options. fuser 0.17's `MountOption` enum has a `CUSTOM(String)` variant for non-standard options. The FUSE kernel module parses `direct_io` from the mount options string.
   - If `allow_other` is true, push `MountOption::AllowOther`.

2. Update the `build_mount_options` call sites in `run_mount()` to pass the `allow_other` parameter (from CLI args — already present as `Cmd::Mount { allow_other, .. }`). Currently `run_mount` does not receive `allow_other`; add it as a parameter.

3. Update `main.rs` to pass `allow_other` through to `run_mount()`.

4. Add a test `test_build_mount_options_macos_direct_io` that verifies on macOS builds the CUSTOM("direct_io") option is present (use `#[cfg(target_os = "macos")]`). Add a complementary test for Linux that verifies direct_io is NOT present.

5. Update existing `build_mount_options` tests to pass the new `allow_other` parameter (false for existing tests).

IMPORTANT: Do NOT change the fuser Config struct layout or session ACL. Only modify the mount_options vec.
  </action>
  <verify>
    <automated>cargo test -p slicefs-cli -- build_mount_options 2>&1 | tail -10</automated>
  </verify>
  <done>On macOS: `build_mount_options` includes `CUSTOM("direct_io")`; on Linux: it does not. `allow_other` flag is wired through from CLI to mount options. All existing mount tests pass with the updated signature.</done>
</task>
