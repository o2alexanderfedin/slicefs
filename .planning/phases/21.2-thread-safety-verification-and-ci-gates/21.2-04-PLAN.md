<objective>
Fix race (a) of Phase 19: a size change of a closed file (`setattr_size_logged` case B) runs under its transient cell only, with no stripe. Window 1: an unlink reclaims the inode during the splice (the setattr returns EIO, a manifest and a reference of the deleted inode stay, and the old root is released twice, so the refcount stats of content shared with another file are wrong; GC is reachability (mark and sweep), so no content that another file uses is freed). Window 2: a setattr of other fields of the same inode shares no lock with it, so the two inode writes and their records can be in opposite orders (replay gives another mtime). Two deterministic tests fail first; then the fix; then a stress test stays in the suite.

Decisions this plan implements: D-26, D-27, D-29, D-21 (the CI-kept check of this race is its stress test), D-33.

D-27 variant (recorded; flagged to the orchestrator): D-27 states the fix direction "re-check the inode under its stripe before the install; the install step must move out of the cell hold". RESEARCH race (a) step 6 found that moving the install out of the cell hold lets an open or a second size change of the inode enter between the splice and the install (the cell lock is what orders them, `filesystem.rs` 4121-4129). This plan uses the research variant that reaches the same guarantee without that move: the claim under the stripe plus an open-count pin (the pattern of `open_logged`, 4967-4985), and the install stays in the cell hold. The inode cannot be reclaimed during the install (the pin), and a fields call is ordered by the stripe and the cell. It is reversible (one function).

D-21 says "one model per race fix is also kept". This plan keeps a stress test, as D-26 and TSAFE-03 allow. A loom model of this race would need the whole file system (store I/O, zstd C code); a copy of the protocol is not allowed (D-20).

Purpose: the multi-worker Linux default made both windows reachable (21-VERIFICATION warning).
Output: the claim-under-stripe fix, `pin_inode`, the pause hook, the window tests, the stress test, three logs.
</objective>
