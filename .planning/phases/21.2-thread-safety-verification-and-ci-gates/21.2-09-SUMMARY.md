## Review results

- chunk-store: table "Executed by Miri" (Send, Sync, `bytes`, `Drop`, test `pack_io::tests::a_run_map_reads_back_moves_across_threads_and_unmaps`). Entries: the `len` argument by hand (three constructors, each stores the `len` it gave to `mmap`; private fields, no Clone, one `munmap`), `RunMap::new`, `madvise`, both `punch_hole`, `full_sync`. RunMap maps index run files (`Kind::Run`), not packs. A run is sealed before `map_run` (`RunWriter::finish` takes the writer by value), and `punch` opens only `Kind::Pack`.
- metadata: `getuid`/`getgid`.
- slicefs-cli: 15 entries (alloc_tune 3, fuset_watch 2, gc_pacing 1, signals 5, unmount 2, filesystem 2).
- Notes (none is memory unsafety; follow-ups only): (1) `unmount.rs` `kill(pid)` has no `pid > 1` check (required note), and `fuset_watch.rs` has the same gap with lower risk; (2) `on_signal` does not save `errno`; (3) FD_CLOEXEC is set after `pipe`, and its result is not checked (fd leak window only; no follow-up proposed); (4) `filesystem.rs` statfs blocks have no SAFETY comment, and the `alloc_tune.rs` macOS comment sits on the wrong line; (5) `fuse_pure.rs` takes only the first SCM_RIGHTS fd.

## Deviations from Plan

1. **Safety workflow triggers.** The owner changed `safety.yml` (b742f8b) to run only on `v*` tags and by hand. The doc says that, not "every push and PR". The plan truth "every push and PR checks it" no longer holds; the check runs in each Safety run and in each local clippy.sh run.
2. **The RunMap entry names run files, not packs.** The plan action said "why packs are append-only and freed whole". The code maps only index run files, so the entry argues sealed run files.
3. **signals.rs: the plan said the pipe is `O_CLOEXEC`.** It is `pipe()` and then `fcntl(FD_CLOEXEC)`, unchecked. The doc gives what the code does.
4. **No `cargo test --workspace` gate.** Both commits change only a doc and scripts; clippy.sh plus a build ran (orchestrator rule for doc-only commits).
5. **The lock_free_io.rs allow reason ("the block number") is not fixed.** It is a file under crates, and this plan's prohibition forbids that. It stays open, as in the 21.2-03 SUMMARY ("Known wording issue").
