<objective>
The ThreadSanitizer gate and the deadlock-detect stress gate (part of TSAFE-01): TSan runs a fixed set of the multi-worker and concurrency tests plus a short stress run on Linux; the deadlock job runs the in-process stress harness with the parking_lot detector. Both run on every push and PR with a time limit. Linux TSan was not measured by research (the Docker VM ran out of memory), so the first GitHub run is the measurement.

Decisions this plan implements: D-03 (tsan 30, deadlock 15), D-05, D-15, D-16, D-17, D-30. It also puts the race tests of D-26 into the TSan set.

D-30 choice (recorded, reversible): no mount-level stress run. A mounted daemon has no deadlock checker thread (only the harness polls `check_deadlock`), and the Linux Docker job of ci.yml already mounts with `--workers 4` (smoke, live checks, pjdfstest) (RESEARCH Decision 5).

Purpose: tool evidence for data races and lock cycles in real multi-threaded runs, on every build.
Output: tsan.sh, deadlock.sh, the two jobs, the macOS runs, the first CI run read by the orchestrator.
</objective>
