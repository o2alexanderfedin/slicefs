### `.github/workflows/safety.yml` (CI config, batch)

**Analog:** `.github/workflows/ci.yml` and `macos-mounts.yml`.

**Job shape** (ci.yml lines 12-30): one job per tool, `actions/checkout@v4`, steps call a script, output teed to `$RUNNER_TEMP` and grepped for proof the check ran.
```yaml
jobs:
  linux:
    name: Linux (tests, FUSE smoke, live checks, pjdfstest — in Docker)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Unit tests and Linux FUSE smoke test
        run: |
          set -o pipefail
          scripts/docker-linux-test/run.sh all 2>&1 | tee "$RUNNER_TEMP/all.log"
          grep -q 'Workers: 4 (set)' "$RUNNER_TEMP/all.log" || { echo "no 'Workers: 4 (set)' line in the output"; exit 1; }
```
**Timeout and trigger comment style** (macos-mounts.yml): `timeout-minutes: 240` sits directly under `runs-on:`; the header comment states when the workflow runs. macOS job: `runs-on: macos-latest`, `brew install pkg-config` then `brew install --cask macos-fuse-t/cask/fuse-t` (ci.yml macos job) - copy for the clippy macOS matrix row.
**New (no analog):** `on: push` (no branch filter) + `pull_request`, `concurrency: { group: ${{ github.workflow }}-${{ github.ref }}, cancel-in-progress: true }`, workflow `env: NIGHTLY: nightly-2026-02-11`. `ci.yml` uses `branches: [main, develop]` for both triggers; do not copy that filter. Note: macos-mounts.yml uses `paths-ignore` for docs; safety.yml should not.
**ci.yml edits (D-07):** add `timeout-minutes:` to jobs `linux` and `macos` (neither has one).

### `crates/chunk-store/src/sync.rs` (shim, cfg(loom) backend)

**Analog:** itself. Public API to preserve: `Mutex`, `RwLock`, `Condvar`, `MutexGuard`, `Rank`, `rank::*`, `WaitTimeoutResult` (line 26: `pub use parking_lot::WaitTimeoutResult;`).
**Condvar** (lines 462-490): parking_lot shape (`wait(&self, &mut guard)`, `wait_for(...) -> WaitTimeoutResult`); the rank entry is suspended around the wait. The loom backend must keep this signature and hold `Option<loom guard>` inside `MutexGuard`.
```rust
pub struct Condvar(parking_lot::Condvar);
pub fn wait<T>(&self, guard: &mut MutexGuard<'_, T>) {
    let at = guard.rank.suspend();
    self.0.wait(&mut guard.g);
    guard.rank.resume(at);
}
```
**cfg style already used here:** `#[cfg(debug_assertions)] mod track` (line 57, thread-local rank stack); change to `#[cfg(all(debug_assertions, not(loom)))]` and keep the `#[cfg(not(debug_assertions))]` no-op arms (lines 166, 223) reachable under loom. `#[cfg(feature = "lock-stats")]` / `#[cfg(not(feature = "lock-stats"))]` pairs (lines 296-431) show the in-file paired-cfg convention. Tests module is `#[cfg(all(test, debug_assertions))]` (line 491): under loom these must be off (`not(loom)`).

### `crates/slicefs-cli/src/filesystem.rs`

**Race (a) fix, claim-under-stripe pattern. Analog: `open_logged`** (lines ~4967-4985):
```rust
let fh = {
    let _ns = self.ns.lock(&[ino]);
    if self.meta.get_inode(ino).is_err() {
        return (Err(libc::ENOENT), None);
    }
    self.open_handle(ino, is_write, flags & libc::O_APPEND != 0)
};
```
Stripe held only for exists-check plus count; released before cell work; the counted handle keeps an unlinked inode as an orphan. Apply the same in `setattr_size_logged` case B (transient `FileCell`), then release the count with `uncount`. Lock order: gate 1, rename 2, stripes 3 (ascending), cell 4, maps 5, store 6; a stripe must not be taken while the cell is held.
**Pause point already in the window** (`setattr_size_closed`, lines ~4180-4190, between splice and install):
```rust
let hook = self.rebase_hook.lock().clone();
if let Some(hook) = hook {
    hook();
}
self.meta.set_manifest(ino, &[new_digest]).map_err(|_| libc::EIO)?;
self.meta.increment_refcount(&new_digest);
```
No new hook is needed for race (a) window 1. Hook type: field `rebase_hook: sync::Mutex<Option<RebaseHook>>` (line 1135), init `sync::Mutex::new(Rank::Short, None)` (line 1222), public setter (line 1357) `pub fn test_set_rebase_hook(&self, hook: Option<Arc<dyn Fn() + Send + Sync>>)`. It is a plain `pub fn`, not `cfg(test)`, so integration tests call it. If window 2 needs a second pause point, copy this triple (field, init, setter) with a new name.
**Race (b):** put the ancestor walk in `rename_held` (rename mutex rank 2 already held); walk `meta.lookup(dir, "..")` as research says. No analog for an ancestor walk exists; use RESEARCH.
**Gate and throttle seams (M2, M3):** `gate_shared`, `gate_exclusive`, `GateHold`, `GateGuard`, `throttle_write`, `FlushCtl` - extract free fns taking the lock/ctl as a parameter, same way `flusher::flusher_loop(ctl, pass)` already takes a closure. Model goes in `#[cfg(loom)] mod loom_tests` inside this file because `FlushCtl::new` is private.

## Shared Patterns

### Test-only hooks
Pattern: `Arc<dyn Fn() + Send + Sync>` stored in `sync::Mutex<Option<..>>`, cloned out of the lock before the call (so the hook runs with no lock held), set through a `test_set_*_hook` setter. Source: `filesystem.rs` lines 1135, 1222, 1357, 4186-4189. Apply to any new pause point.

### Lock rank discipline
Source: `chunk_store::sync` `Rank` enum and `rank::held()`; debug builds panic on violation. Race fixes and extracted seams must not take a stripe (3) under a cell (4) or anything under the store (6). Under `--cfg loom` the rank tracker is compiled out.

### Named test lists in scripts
Run by exact test name (`-- --exact`, `--test <file>`), print each name; Miri allow-list is a text file, one name per line. Existing convention for single tests: `run.sh harness <test-name>`.

### Doc and comment style
Rust: `//!` module header says what and why with issue numbers; Cargo features carry a one-line comment. Shell: header comment with usage and env vars. Plain short English, no home paths.
