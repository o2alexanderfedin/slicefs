# Phase 21.2 Plan 01: Safety workflow and loom models of the real worker pool Summary

The new Safety workflow (every push, every PR) runs `scripts/safety/model.sh`, which runs 4 loom models of the real `pool.rs` and the lock shim through one cfg point (`chunk_store::sync` and `sync::raw`). It is green on GitHub with `MODEL bound=3`.

## What was built

- `chunk_store::sync::raw`: std `Mutex`, `MutexGuard`, `RwLock` and guards, `Condvar`, `PoisonError`, `atomic`, `thread`; the loom types under `--cfg loom` (`PoisonError` stays std). `Arc` and `Weak` stay std (loom 0.7.3 has no `Weak`).
- The cfg(loom) backend of the shim: `Mutex`, `MutexGuard` (holds an `Option` of the loom guard), `RwLock`, `Condvar` (`wait_for` never times out) and an own `WaitTimeoutResult` (always not timed out). Rank tracking is compiled out under loom (`all(debug_assertions, not(loom))`); the 22 rank tests still pass in a normal debug build.
- `pool.rs` takes `Condvar`, `Mutex`, `MutexGuard`, `PoisonError`, the atomics, `JoinHandle` and `thread::Builder` from `sync::raw`. No other pool change.
- Models (thread count includes the model main thread):
  - `sync::loom_tests::loom_shim_condvar_wakes_a_waiter_all_orders` (2 threads, no bound)
  - `pool::loom_tests::loom_pool_two_workers_two_jobs_drain` (3 threads, bound 3)
  - `pool::loom_tests::loom_pool_one_worker_full_queue_all_orders` (2 threads, no bound)
  - `pool::loom_tests::loom_pool_drop_without_drain_runs_the_job` (3 threads, bound 3)
- loom is a `[target.'cfg(loom)'.dependencies]` entry of chunk-store and slicefs-cli, with `check-cfg` for `loom` and `kani`. `cargo tree -e normal -p slicefs-cli` has no loom.
- `scripts/safety/toolchains.sh` reads `RUST_STABLE`, `NIGHTLY`, `KANI_VERSION` from the env, else from the `env:` block of safety.yml (the only place of the pins), and has `need_toolchain`. `scripts/safety/model.sh` prints `MODEL bound=`, `MODEL crate=<c> passed=<n>`, `MODEL ok`, and fails on a cargo error, on 0 tests, or on no passed `loom_` test.
- `.github/workflows/safety.yml`: name `Safety`, push on `**` and pull_request, concurrency per workflow and ref with cancel-in-progress, `permissions: contents: read`, the pins `RUST_STABLE "1.100.0"`, `NIGHTLY nightly-2026-02-11`, `KANI_VERSION "0.68.0"`, job `model` (ubuntu-latest, 20 min, no `needs:`). ci.yml is unchanged.

## Red first, then green (planted faults, none committed)

| Model | Planted fault | Result |
|-------|---------------|--------|
| two workers, two jobs, drain | `Exit::drop` without `done.notify_all` | `deadlock; threads = [(Id(0), Blocked), (Id(1), Terminated), (Id(2), Terminated)]`, `test result: FAILED`, model.sh exit 1 (runs/model-red-21.2-01.log) |
| shim condvar | shim `Condvar::notify_one` does nothing under loom | `deadlock; threads = [(Id(0), Blocked(Location(None))), (Id(1), Terminated)]`, `test result: FAILED` |
| one worker, full queue | no `not_full.notify_all` in `worker_loop` | `deadlock; threads = [(Id(0), Blocked), (Id(1), Blocked)]`, then "panic in a destructor during cleanup" and SIGABRT (the deadlock panic unwinds through `Exit::drop`, which locks again); cargo exit 101, so model.sh fails |
| drop without drain | no `not_empty.notify_all` in `close_and_wait` | `deadlock; threads = [(Id(0), Blocked), (Id(1), Blocked), (Id(2), Terminated)]`, `test result: FAILED` |

All four pass on the real code.

## Deviations from Plan

### Gate and environment

**1. [Rule 3 - Blocking] Local test gate on a loaded host**
- **Found during:** Task 1 gate
- **Issue:** On this Mac, each new test binary takes 12 to 17 s to start (61 s for a binary built before this change; `/bin/ls` 0.07 s). The load came from other projects and Spotlight. The `pool_panic_tests` child tests (60 s `CHILD_LIMIT`) failed with empty child output, and the full suite ran 40 to 60 min.
- **Fix (orchestrator decision):** the local gate skips the 3 failing child tests; `pool_panic_tests` must pass in CI on Linux and macOS (it did, PR #177). The Task 2 gate hit its 1 h cap after 61 of 75 test binaries (all green); the other 14 then ran alone on the same tree (all green). Named in both commit bodies; details in deferred-items.md.
- **Commits:** 787fdfd, 98f316c

### Small choices

**2. Shim model name ends in `_all_orders`.** It runs with no bound, and model.sh names that form `*_all_orders`. The plan grep `fn loom_shim_condvar_wakes_a_waiter` still matches.

**3. loom backend as a private `imp` module.** parking_lot-shaped adapters over the loom types, so the shim bodies stay the same under both cfgs (only `parking_lot::` became `imp::`). No shim method needed `#[cfg(not(loom))]`.

**4. STACK.md lines inside the table cells.** A separate line under a table row would break the table, so the "Superseded for the Phase 21.2 models" text is appended to the `Concurrency tests` row and the `loom` row.

**5. Extra red runs.** The two new pool models were also shown red on a planted lost notify (not asked by the plan; orchestrator rule: every model red first).

**6. TSAFE-01 and TSAFE-02 not marked complete in REQUIREMENTS.md.** This plan delivers the first part of each: the workflow with job `model`, and the pool models. TSAFE-01 still needs the clippy, Miri, TSan, Kani and deadlock-detect jobs (plans 03, 05, 07); TSAFE-02 still needs the budget and gate models (plan 06). Plan 11 closes both.
