3. Rewrite `unmount.rs` with the enhanced sequence per CONTEXT.md decisions:
   - Change signature: `pub fn run_unmount(mountpoint: &Path, store_path: Option<&Path>) -> Result<(), Box<dyn std::error::Error>>`
   - Step 1 — Soft unmount: try `fusermount3 -u`, `fusermount -u`, `umount` (keep existing logic as `try_soft_unmount()`). On success, clean mount.lock if store_path given, return Ok.
   - Step 2 — Kill processes: `fn kill_processes_at_mountpoint(mountpoint: &Path)` — run `lsof +D <mountpoint>`, parse PIDs from column 2, send SIGTERM via `libc::kill`. Also `pkill -f go-nfsv4` to kill orphaned FUSE-T backend daemons. Sleep 1s to allow graceful shutdown.
   - Step 3 — Force unmount: `fn try_force_unmount(mountpoint: &Path) -> bool` — on macOS: try `diskutil unmount force <mp>`, fallback `umount -f <mp>`. On Linux: try `fusermount3 -uz`, `fusermount -uz`, `umount -l`.
   - Step 4 — Clean mount.lock: if store_path given, remove `store_path.join("mount.lock")`.
   - If force unmount also fails, return Err with suggestion to use `sudo diskutil unmount force`.
   - Print status messages: "Unmounted {path}" on success, "Soft unmount failed -- killing processes..." on escalation, "Force-unmounted {path}" on force success.

4. Unit tests:
   - test_run_unmount_nonexistent_path_returns_error (keep existing, update signature)
   - test_mount_lock_cleanup_on_success: create a tempdir with mount.lock, verify it's removed after unmount attempt (unmount itself will fail on non-mountpoint, but mount.lock removal logic can be tested by extracting the cleanup into a helper)
