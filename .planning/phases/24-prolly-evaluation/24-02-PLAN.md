<objective>
Add the batched edit of the prototype (PROLLY-01, D-16 item 3): `apply` takes one sorted batch of puts and deletes, rewrites only the touched nodes and their paths through the same splitter as the bulk builder, resynchronises with the old tree at the first new cut that lands on an old node end, and returns a canonical root. The tests prove order independence, idempotency, canonical roots, one-path writes, a model check with variable-length entries, and bounded memory.

Task 1 (tracer) wires one batch end to end: a put batch rewrites the touched leaves and their path, `get` reads the new values, and the root equals the bulk build of the final set. Task 2 adds deletes down to the empty map, the canonical collapse, the order and idempotency tests, and input checks. Task 3 adds the property test, the memory test, the crafted-node test, the doc and the gates.

Decisions this plan implements: D-02, D-10, D-11 (one splitter for build and apply), D-13 (a and b), D-15 (root is one ObjectId), D-16, D-17 (no node cache), D-18 (own implementation), D-06 (short tests). D-05: this plan changes no Cargo file (24-01 already added `proptest`).

Discretion choices (reversible, recorded in the SUMMARY): `Edit` is an enum with owned bytes; a batch is a slice sorted by key; an empty batch returns the same root with no reads; a shrink of the tree height may write up to depth nodes that the canonical collapse then skips (they stay unreferenced in the store; a later GC would drop them); no node cache.

Purpose: ROADMAP criterion 1 (the prototype is complete: build, get, apply, ordered iteration).

Per D-11, D-16, write apply.rs with the types of the artifact list and this algorithm (all of it in this task; Task 2 adds the shrink cases and tests):
1. Input checks before any read or write: keys strictly ascending (else `Error::Unsorted`), each key within `cfg.max_key` (`Error::KeyTooLarge`), each put within `cfg.max_entry` by `leaf_entry_len` (`Error::EntryTooLarge`). An empty batch returns `(root, ApplyStats::default())`.
2. Load the root; its level is h. The edits of level 0 are the batch. An edit of a level above 0 is "put child (last key, id, count)" or "delete child with this last key".
3. For each level from 0 to h, rewrite the level with its sorted edits:
   - An edit belongs to the old node of the level that covers its key: the first node whose last key is >= the edit key, or the last node of the level when the key is above every last key. Find nodes with a path cursor: a stack of decoded nodes and indexes from the root down to the level, one node per level, moved forward as a sorted sweep, so each old node of the level is read once per pass (count every `store.read` in `nodes_read`).
   - Copy mode: old nodes with no edits are kept as they are (no read of their entries is needed past the cursor path).
   - At a touched old node, start a fresh `LevelWriter` of the level (a node start is always a fresh splitter state) and feed it the merged entries of that node: old entries with the edits applied (a put replaces an equal key or inserts; a delete removes; a delete of an absent key does nothing). When the node's merged entries are done: if the writer's buffer is empty (a cut fell exactly at the old node end) and the next old node has no edits, the run ends here: from this point the old chunking is the new chunking (resync). Otherwise read the next old node and feed its entries too (it is replaced), and test again at its end. At the end of the level, flush the writer.
   - Record each replaced old node (its last key) and each new `NodeRef`.
   - The edits of the next level: "delete child with last key" for each replaced old node, and "put child" with (last key, id, count) for each new node, merged into one sorted list in which a put and a delete of the same key become the put; a put whose (id, count) equals the old child entry of that key is dropped (the node did not change).
   - Stop early when a level produces no edits for the next level (no node changed): the old root stays.
4. After level h: if the new level h has more than one node, build the levels above it with `Builder::with_level(store, cfg, h + 1)` and `push_node` for each new level-h node in order, then `finish`. If it has exactly one node, that node is the root. If it has none (every entry was deleted), the root is `empty_root(store)`.
5. `ApplyStats`: `nodes_read`, `nodes_written` and `bytes_written` (bytes passed to put; dedup may store fewer), and `high_water_bytes` = the largest sum seen of the decoded old nodes held (cursor path and current node), the writer buffer, and the pending edits of the next level.
Keep a module doc: memory is O(changes x depth); no node cache (D-17); no keyed collection of nodes; edits are a sorted `Vec`.
In lib.rs add `mod apply;` and re-export `apply`, `Edit`, `ApplyStats`.
Tests:
- `apply_one_put_then_get`: DEFAULT, `u64_entries(3_000, 3)`: one batch that puts a new 33-byte value for one existing key and inserts one new key; `get` returns both new values and an untouched key still returns its old value; the new root equals `build` of the final set (made into the same store).
- `one_change_writes_one_path` (D-13b): DEFAULT `u64_entries(20_000, 3)` and SMALL `u64_entries(5_000, 3)`: put a new value of the same width for one middle key: the `stats().objects` delta equals `BuildStats::depth` of the old tree, `ApplyStats::nodes_written == depth`, and the root differs from the old one.
- `apply_inserts_equal_bulk`: SMALL `u64_entries(2_000, 3)`: separate batches that insert before the first key, after the last key, in the middle, and 300 random keys in one batch; each new root equals `build` of its final set.
