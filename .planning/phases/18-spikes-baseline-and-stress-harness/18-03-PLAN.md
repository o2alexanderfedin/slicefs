Add `Mode { OneFile, ManyFiles }` to `Config` and keep the per-op wrapper from Plan 01 (serialize mutex first, then the timed gate read) for every new op kind (per D-04).

Many-files mode (per D-06):
- Setup: `handle_mkdir` of `shared` and of one directory `t<n>` per thread under the root.
- Each thread owns the names `t<n>-<k>` (k is a per-thread counter, never reused) in its own directory and in `shared`; it only creates, renames, unlinks, writes and fsyncs owned names. Per-thread model: map from (dir ino, name) to an entry with the inode number, the per-block versions (at most 16 blocks of 4 KiB, so files stay at most 64 KiB) and the open handle, if any. At most 32 live files per thread.
- Op mix (Claude's discretion, record the weights in a const table): create 15% (`handle_create` in own dir or `shared`, write 1..=4 blocks, keep the handle open or release it), write 25%, read 20%, fsync 5% (`handle_fsync` on an open handle), rename 10% (owned name to a new owned name, same dir or between own dir and `shared`), unlink 10% (release the open handle first, then `handle_unlink`), release 10%, open 5%. When an op has no target (for example no live file), pick create.
- Check after each step: after create or rename, `handle_lookup(dir, name)` returns the model inode (rename keeps the inode); after unlink or rename, the old name returns ENOENT; after each write, read the written blocks back and compare with `block_bytes`.
- Final check `fn verify_namespace(..) -> Vec<Mismatch>`: for each directory, the `handle_readdir` names (without `.` and `..`) equal the model names for that directory (for `shared`, the union of all threads); each name's `handle_lookup` inode equals the model; each file's content equals the model (open read-only, read, release).

One-file mode: add fsync (about 1 op in 25) on the thread's own handle.

Commit thread (both modes): every 250 ms call `timed_commit(&fs, &gate)` with the gate from `fs.commit_gate()`, until a stop flag is set after the workers are joined; record `commit_gate_wait`, `commit_hold` and `commit_total` histograms and print them as `op=` rows. A commit error is a `Mismatch`. The commit thread does not take the serialize mutex (as in the daemon, where the commit timer runs beside the one dispatch thread).

Report: add rows for every new op kind (`fsync`, `create`, `rename`, `unlink`, `open`, `release`) and change the header to name the mode.

Test `short_many_files` (per D-05): 4 threads, serialize on, an op count calibrated so that the whole test binary (`short_one_file` and `short_many_files` run in parallel) finishes in at most 5 s in a warm local debug build. Both short tests also assert `fs.test_dirty_total() < DIRTY_BUDGET / 4`.

Watchdog (no unbounded wait, project rule): `fn watchdog(limit: Duration, seed: u64) -> std::sync::mpsc::Sender<()>` spawns a thread that calls `recv_timeout(limit)`; on a message or a disconnect it returns; on a timeout it prints `STRESS watchdog: no finish after <s> s, seed=<seed>` to stderr and calls `std::process::abort()`. Every run starts one and drops the sender when it ends, so the watchdog never fires in a later test of the same binary. Short runs use 60 s; the long run uses its duration plus 60 s.

Env config per D-05 (only for the long run): `Config::from_env(defaults)` reads `STRESS_THREADS` (1..=64, default 8), `STRESS_SECS` (1..=3600, default 60), `STRESS_FILE_MIB` (1..=4096, default 64), `STRESS_SEED`, `STRESS_SERIALIZE` (`0` or `1`, default `1`) and `STRESS_MODE` (`one-file`, `many-files` or `both`, default `both`). A value outside its range panics with a message that names the variable. In a time-based run, each worker checks a deadline and a shared stop flag before each op.

Test `long_run` with `#[ignore = "long run by hand: STRESS_THREADS STRESS_SECS STRESS_FILE_MIB STRESS_SEED STRESS_SERIALIZE STRESS_MODE; use --release"]`: runs the selected modes with the env config; the one-file file size is `STRESS_FILE_MIB`; it asserts no mismatches and prints the full report.

Test `serialize_off_target` with `#[ignore = "target for Phases 19-21: needs file state kept in open_files (LOCK-01) and no cross-file take-out (LOCK-02)"]` (per D-04): both modes with 4 threads, serialize off, about 5 s each, files small enough that the dirty total stays below `DIRTY_BUDGET`; it asserts no mismatches and `max_inflight > 1`.

Run each ignored test once by hand and put the result in the SUMMARY (they are not commit gates): `long_run` with `STRESS_SECS=20` in `--release`, and `serialize_off_target`. The serialize-off run is expected to fail on today's code; record its first mismatches (for example EBADF on a shared handle) for Phase 19.
