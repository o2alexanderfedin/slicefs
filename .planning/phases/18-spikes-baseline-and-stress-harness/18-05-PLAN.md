<objective>
Run the three mounted Linux spikes on the Docker mount and save their raw numbers for Plan 07: S6 (small fsynced files per WAL strategy), S4 (kernel queue depth during random writes and readahead), S2 (bigwrite at 1 GiB and 4 GiB, measured again after #108).

Decision IDs (numbered in CONTEXT.md order, see 18-01-PLAN.md objective): D-09 S2, S4 and S6 run on the Linux Docker mount (`scripts/docker-linux-test/`): S2 with `bigwrite.sh` at 1 GiB and 4 GiB, S4 by the kernel queue depth (`/sys/fs/fuse/connections/*/waiting`) during random writes plus readahead, S6 with many small fsynced files, per-op log against the buffered strategies.

Ordering: this plan waits for Plans 02 and 03 only so that no cargo build runs on the machine while these tail latencies are measured (parallel builds distort the numbers). It shares no file with them. While a measurement runs, do not start other Docker jobs or cargo builds.

Limits stated up front (recorded in the logs, written into the doc by Plan 07): there is no WAL flusher yet, so S6 compares PerOp with the buffered strategies, not with a flusher; `waiting` counts the whole FUSE connection, not one inode, so S4 runs one active file only; S2 numbers vary a lot between runs (commit 736a490), so each size gets 3 runs.

Purpose: SPIKE-01 (S2, S4, S6 results; S2 measured again on the current code).
Output: two scripts, two run.sh modes, one bigwrite.sh line, three run logs.
