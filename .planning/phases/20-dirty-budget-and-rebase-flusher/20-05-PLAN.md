<objective>
The flusher policy: the three triggers of the owner's rule (idle, maximum age, buffer full) with the hot rule of A10.

Decisions that this plan implements (labels of 20-CONTEXT.md):
- [When dirty data is written] (user): "the flusher writes a file's dirty data when one of these is true: 1. the file was idle (no write) for some time, default 5 s; 2. its oldest dirty data reached a maximum age, default 30 s; 3. the buffer is full: the shared dirty total is at or above the background threshold (half of `--dirty-budget`), or one file is at its own limit."
- A10 (decided autonomously, reversible): "'Buffer full' steps the largest quiet dirty file first (no write in the last few hundred ms). A file that is written all the time is not stepped by the flusher below the hard limits; its writer pays with its own step ... Reason: every overlay write moves the generation, so a flusher step on a busy file is always dropped."
- [Flusher] pick: per-cell `last_write` and `dirty_since` timestamps (atomics); idle and expire pick cells whose times passed the limits.

Purpose: the flusher frees memory where a step can publish, and leaves a busy file to its writer.
Output: the timestamps, the test clock, the idle and expire modes, the hot rule, six tests.
</objective>

Facts:
- Every overlay write moves the overlay generation (`crates/slicefs-cli/src/overlay.rs` lines 179-185), and a step publishes only if the generation did not move (`step_publish`). So a flusher step on a file that a writer changes during the step's I/O is dropped.
- With the default constants, `DIRTY_LIMIT` (32 MiB) is half of `DIRTY_BUDGET` (64 MiB), which is the background threshold. So one busy file at its limit keeps trigger 3 true (research Q2, "Hot rule"). The hot rule stops the flusher from wasting steps on it.
- `CellGuard::sync_dirty` (filesystem.rs, about line 509 at 1f631b4) moves `FileCell::dirty` with the cell locked; it knows the old and the new cost.
- `write_in_cell` applies the write in the cell hold; the writer's own limit step and the hard-cap gate follow it.
- `FileCell::transient` cells are never candidates.
- The flusher of 20-02: `flush_pass` has the budget-full mode (largest first, overlays before streams, a skip per pass for a cell that freed nothing). `test_set_dirty_limit` and `test_set_dirty_budget` exist.
- A stream with no pending writes has cost 0 and is never a candidate. A stream with pending writes becomes an overlay in `free_dirty`; for an active stream that ends streaming (research Pitfall 8).

Planner choices (reversible; record them in the SUMMARY): hot window 300 ms (three pass intervals; A10 "a few hundred ms"); one FLUSH_STEP step per idle or expired cell per pass; a stream with pending writes is switched only in idle or expire mode, or in budget-full mode when no overlay candidate is left.
