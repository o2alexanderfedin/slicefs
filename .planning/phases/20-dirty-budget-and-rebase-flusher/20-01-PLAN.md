Cap rule (stated here, before the runs; CONTEXT [RSS] form "budget + per-writer step + measured overhead"):
- Inputs: the `vmhwm_mib=` values of the 6 measurement runs (3 P_old, 3 P0). Nothing else.
- Pm = the largest of the 6 values. Spread = largest minus smallest.
- Terms, in MiB:
  - B = 64: the dirty budget of the runs (`DIRTY_BUDGET`).
  - N x W = 4 x 1 = 4: one write in flight per writer (the throttle bound).
  - O = Pm - B - N x W: the measured fixed overhead (process, caches, kept pack copies, the writers' own step copies, allocator, model and check buffers).
  - F = 8: one flusher step, its copy and its splice output (2 x `FLUSH_STEP`; `FLUSH_STEP` is 4 MiB in plan 20-02). This is the only new memory holder that the flusher adds.
  - R = the largest of 16, ceil(Pm / 10) and 2 x Spread: room for run-to-run noise.
- CAP_MIB = B + N x W + O + F + R = Pm + F + R, rounded up to a multiple of 8.
- Branches:
  - A run with a mismatch, a panic, an errno or a failed test (A11): stop. Do not fix a cap. Report the seed and the first mismatches to the orchestrator (Rule 4): it is a Phase 19 bug that must be fixed before the flusher work.
  - P0 max > P_old max + 64 (more than one budget above the serialized runs): stop and report. The parallel path then holds memory that the serialized path does not.
  - CAP_MIB > 256 (the Phase 18 S7 cap): run one more serialize-off run with `MALLOC_ARENA_MAX=2` into a separate log, to show the allocator part. Then commit the rule's value (a test constant; reversible) and name it in the SUMMARY for the owner, with the arena result. The 64 MiB default budget is the owner's decision ([Mount options]), so the planner cannot lower it to keep 256.
