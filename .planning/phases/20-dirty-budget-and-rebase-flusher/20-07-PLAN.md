<objective>
ROADMAP criterion 4: "A Docker run with parallel random writers on large files keeps peak RSS (VmHWM) under one fixed cap." Also a short test in the suite of the dirty bound that makes that cap possible.

Decisions that this plan implements (labels of 20-CONTEXT.md):
- [RSS]: the Docker test reads VmHWM from /proc/self/status; the cap is fixed (plan 20-01, from P_old and P0).
- [When dirty data is written]: "Memory stays bounded by the per-file hard cap and the budget plus one step per writer."
- [Harness]: the default harness run does not start the flusher; the S7 flusher form is a small opt-in knob that this criterion needs.

The daemon has one dispatch thread until Phase 21, so a mount cannot run parallel writers yet. The criterion-4 run is the in-process S7 run in Docker, as research Q4 says.

Purpose: show that the flusher and the throttle keep memory under the cap that was fixed before they existed.
Output: one short test, the S7 knob, three Docker runs.
</objective>
