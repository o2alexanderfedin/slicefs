<objective>
The four mount options of the owner's answer, with checks, wired to the atomics that the throttle and the flusher read.

Decisions that this plan implements (labels of 20-CONTEXT.md):
- [Mount options] (user): "Add mount options with default values: `--dirty-budget` (bytes, default 64 MiB = today's `DIRTY_BUDGET`), `--dirty-limit` (bytes per file, default 32 MiB = today's `DIRTY_LIMIT`), `--dirty-idle` (seconds, default 5), `--dirty-expire` (seconds, default 30). Accept size suffixes (K, M, G) for the byte options if a parser exists; otherwise plain bytes. Validate: `--dirty-limit` <= `--dirty-budget`; both at least a few rebase steps; reject 0." Reversibility: costly.
- A3: "Minimum value 4 MiB for `--dirty-budget` and `--dirty-limit`."

Plain bytes, per the locked [Mount options] text (research suggested a hand-written `parse_size` with K, M and G). No size parser exists in the code or in Cargo.lock (checked at planning time: the only value parsers are `parse_compression`, `parse_hash` and `parse_backend_flag`). `--cache-size` is plain bytes too. A later release can accept suffixes, and it can lower the 4 MiB minimum, without breaking a user; the reverse breaks one.

Only these four options. The wait limit, the pass interval, the hot window and the flusher step stay internal.

Purpose: the owner can set the memory bound of a mount.
Output: the options, `parse_dirty_bytes`, `DirtyConfig`, the wiring, the tests.
</objective>

Per [Mount options] and A3. Plain bytes (see the objective for why).

- content.rs: `pub fn parse_dirty_bytes(s: &str) -> Result<usize, String>` next to `parse_compression`. Accept only a decimal integer of bytes. Refuse an empty value, a sign, a fraction, a unit suffix, and overflow. Refuse a value below `MIN_DIRTY_BYTES` (4 MiB, a public constant: 4 x `REBASE_STEP`); the message names the minimum in bytes. This also refuses 0.
- cli.rs, `Cmd::Mount`:
  - `dirty_budget: usize`, `#[arg(long, value_name = "BYTES", default_value_t = crate::filesystem::DIRTY_BUDGET, value_parser = crate::content::parse_dirty_bytes)]`;
  - `dirty_limit: usize`, the same with `DIRTY_LIMIT`.
  - Help texts. Budget: the most dirty (not yet stored) file data of all open files, in bytes, default 64 MiB, at least 4 MiB; a writer over it waits up to 5 s for the background flusher, then stores part of its own file. Limit: the most dirty data of one file, in bytes, default 32 MiB, at least 4 MiB, not above `--dirty-budget`.
- filesystem.rs:
  - `pub struct DirtyConfig { pub budget: usize, pub limit: usize, pub idle_secs: u64, pub expire_secs: u64 }` with `Default` (the constants, 5 s, 30 s) and `pub fn check(&self) -> Result<(), String>`. The check refuses a limit above the budget and names both values. It also refuses the byte minimum and 0 seconds, so a caller that builds the struct directly cannot pass them.
  - `pub fn set_dirty_config(&self, cfg: &DirtyConfig)` stores the four atomics. Keep the `test_set_*` hooks.
  - A hook that reads the budget and limit back, for the test.
- mount.rs: `run_mount` takes a `dirty: DirtyConfig` (one more argument). Its first statement is `dirty.check()?`, before the mount point is made. Call `fs.set_dirty_config(&dirty)` before the write-log replay, so replay memory follows the configured budget too.
- main.rs: build the `DirtyConfig` from the options (Task 2 adds the two time options; use the default times until then) and pass it.
