<objective>
ROADMAP criterion 3: "A test with all workers throttled while a commit waits finishes without deadlock." Two forms of the test, and a test of the flusher's no-wait rule.

Decisions that this plan implements (labels of 20-CONTEXT.md):
- [Deadlock]: "A commit never waits for budget. The flusher releases the gate between steps, so an exclusive gate waiter (commit cut) gets it. Test: all writers throttled, a commit waiting; it ends within a time limit".
- [Throttle]: the writer waits before the gate ("never wait for budget while holding the gate").
- [Flusher] threads: the gate is taken shared for each step, never across a sleep.

The rules hold after plans 20-02 and 20-03. So the red run of each test is a named GUARD MUTATION of the flusher, not committed.

Purpose: the gate, the budget and the flusher cannot form a cycle.
Output: three tests in `tests/flusher_tests.rs`.
</objective>

Facts:
- `slicefs_cli::commit_timer::timed_commit(fs, gate)` syncs the store, then takes the gate exclusive for the cut (commit_timer.rs line 44). `fs.commit_gate()` gives the gate.
- `tests/common/mod.rs`: `new_fs_with(store, WalConfig::PerOp)` (a logged file system, so a commit works) and `reload_and_replay(store)`.
- The rebase hook runs in the I/O phase of every rebase step, with the cell unlocked (`test_set_rebase_hook`). In a flusher step the flusher holds the gate shared then. In a writer's own step the writer holds the gate shared (its request) and the step token of its cell.
- `parker_at(&[n])` in `tests/lock_free_io.rs` (line 78) parks call number n until `go` (at most 10 s per call). Copy it into `flusher_tests.rs` if 20-02 did not.
- The flusher helpers of `flusher_tests.rs` (20-02, 20-03): `throttled_write`, the block-version model, `wait_until`, `watchdog`, the stop guard; hooks `test_pause_flusher`, `test_set_throttle_wait`, `test_set_flush_pass`, `test_throttled_now`, `test_flusher_stats`; `flusher::run_flusher`, `flusher::flush_pass`.
- Fill first with the default budget, pause the flusher, then lower the budget (research Q3).
- With std `RwLock`, a new reader waits behind a queued writer (S5, both systems). So the writers that the flusher wakes in form B wait for the commit cut before they get the gate. The test does not assert that order.

- A logged file system (PerOp) in a temporary store. 4 seeded files of 4 MiB, released and opened again `O_RDWR`, made overlays.
- Dirty limit 2 MiB, wait limit 30 s (a writer that leaves early is a bug, not a timeout), pass interval 20 ms.
- `run_flusher` in the scope, paused.
- Fill each file with about 1.1 MiB of dirty data with the default budget (32 KiB pieces on the 64 KiB grid; no file passes its limit, so no own step runs). Then set the budget to 4 MiB (the total is about 4.4 MiB).
- 4 writer threads, one per file. Each does 8 throttled writes and returns its results.
- Watchdog 60 s; the stop guard.

`all_writers_throttled_while_a_commit_waits_flusher_paused` (research form A):
- `test_throttled_now()` reaches 4 within 5 s.
- A thread runs `timed_commit`. It returns Ok within 10 s. After it returns, `test_throttled_now()` is still 4 (the commit did not need a writer to move).
- Unpause. All writers return Ok within 10 s.
- The total is below the budget plus 4 x (32 KiB + `EXTENT_OVERHEAD`).
- Contents match the models with the handles open, after release, and after `reload_and_replay`.
- GUARD MUTATION (not committed): in the flusher loop, take `gate_shared()` before the pause check and keep it while paused. The commit then cannot get the gate, and the test fails at "the commit returns within 10 s". The stop guard ends the flusher, so the scope ends.

`all_writers_throttled_while_a_commit_waits_flusher_in_a_step` (research form B):
- A rebase hook parks its first call.
- `test_throttled_now()` reaches 4 within 5 s. Unpause. The park is reached within 5 s: the flusher's first step is in its I/O phase and holds the gate shared.
- A thread runs `timed_commit` (it queues for the exclusive gate). Just before the park is let go, assert that the commit has not returned (the shared hold keeps it out).
- Let the park go. The commit returns Ok within 10 s. All writers return Ok within 10 s. The flusher stats show at least one published step.
- Contents match with the handles open, after release, and after `reload_and_replay`.
- GUARD MUTATION (not committed): make the flusher keep its gate hold from the first step across the pass wait and into the next pass. The commit then fails at "returns within 10 s".

Record both mutation runs in the SUMMARY with the assert text and the run time.
