Create `crates/slicefs-cli/src/filesystem.rs` implementing `fuser::Filesystem`:

1. **SliceFsFilesystem struct:**
   ```rust
   pub struct SliceFsFilesystem {
       meta: Arc<DictMetadataStore>,
       dict: Arc<Mutex<Dictionary>>,  // separate from meta's dict — for content reads via GetBytes
   }
   ```
   The `dict` here is a CLONE of the dictionary from DictMetadataStore at construction time. This avoids deadlock with DictMetadataStore's internal Mutex. During `seed`, both the meta store and content blobs are pushed into the SAME Dictionary. At mount time, we clone the dict for content reads.

   Constructor: `pub fn new(meta: DictMetadataStore, dict: Dictionary) -> Self`

2. **Helper: inode_to_file_attr(meta: &InodeMeta) -> FileAttr:**
   - mode & 0o170000 == 0o040000 => Directory
   - mode & 0o170000 == 0o120000 => Symlink
   - else => RegularFile
   - perm = (mode & 0o7777) as u16
   - blocks = (size + 511) / 512
   - atime = UNIX_EPOCH (noatime)
   - mtime/ctime from InodeMeta seconds + nanoseconds
   - blksize = 4096

3. **Helper: meta_error_to_errno(e: &MetaError) -> i32:**
   - NotFound -> ENOENT, AlreadyExists -> EEXIST, NotADirectory -> ENOTDIR
   - IsADirectory -> EISDIR, NotEmpty -> ENOTEMPTY, InvalidName -> EINVAL
   - Corrupted -> EIO, Io -> EIO

4. **Read operations (MUST implement):**
   - `getattr`: get_inode(ino), convert to FileAttr, reply.attr(TTL, &attr). TTL = Duration::from_secs(1).
   - `lookup`: meta.lookup(parent, name), then get_inode(child_ino), reply.entry(TTL, &attr, 0).
   - `readdir`: meta.list_directory(ino), skip `offset as usize` entries, reply.add() each with (index+1) as next offset. Break if buffer_full.
   - `read`: meta.get_manifest(ino) -> Vec<Digest224>. The manifest contains exactly one Digest224 — the CDC root. Convert to Digest256 via from_digest224. Lock self.dict, create GetBytes iterator, skip `offset` bytes, take `size` bytes, collect into Vec<u8>, reply.data(&data). For Phase 3 with test content, this byte-by-byte approach is acceptable.
   - `open`: reply.opened(0, 0) — no file handle tracking needed for read-only.
   - `opendir`: reply.opened(0, 0).
   - `release`: reply.ok().
   - `releasedir`: reply.ok().
   - `statfs`: reply.statfs with blocks/bfree/bavail/files/ffree from basic estimates (inode count from a reasonable default, block count from dict size). Keep it simple.
   - `access`: reply.ok() — read-only, all reads allowed.
   - `getxattr`: meta.get_xattr(ino, name), reply.data(&value) or reply.error(ENODATA).
   - `listxattr`: meta.list_xattrs(ino), format as null-separated names, reply.data or reply.size.

5. **Write operations (ALL return EROFS):**
   Explicitly implement every write method: `write`, `create`, `mkdir`, `mknod`, `symlink`, `link`, `unlink`, `rmdir`, `rename`, `setattr`, `fallocate`. Each calls `reply.error(libc::EROFS)`. Use EROFS (not ENOSYS) per user decision — EROFS means "read-only filesystem", ENOSYS means "not implemented".

6. **Lifecycle:**
   - `init(&mut self, _req, config)`: Set `config.set_max_readahead(128 * 1024)` if available. Log "SliceFS mounted (read-only)".
   - `destroy(&mut self)`: Call `self.meta.commit()`, log result. This prepares for Phase 4 write support per user decision. The actual dictionary serialization to disk happens in the mount command (Plan 03).

7. **Public accessor for destroy-time persistence:**
   - `pub fn meta(&self) -> &Arc<DictMetadataStore>` — so mount command can access the store after session ends.
   - `pub fn dict(&self) -> &Arc<Mutex<Dictionary>>` — so mount command can serialize dict to disk.

All unit tests operate on in-memory DictMetadataStore (no FUSE mount needed). Test the conversion helpers and the callback logic directly by constructing SliceFsFilesystem with a seeded DictMetadataStore.
