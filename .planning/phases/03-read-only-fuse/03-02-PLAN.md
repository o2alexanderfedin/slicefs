CRITICAL DESIGN NOTE from 03-RESEARCH.md Pitfall 4:
The Dictionary used for DictMetadataStore metadata AND for State::push_all content must be the SAME Dictionary instance. DictMetadataStore wraps its Dictionary in Mutex<Dictionary>. During seed, we need to:
1. Create DictMetadataStore::new() — this creates a Dictionary internally
2. Access the internal dict to push content into it via State::push_all
3. Or: Create a Dictionary externally, use it for both content and metadata

The cleanest approach: DictMetadataStore::new() creates the dict. We need to add a method to expose the dict for content operations, OR perform all content operations before constructing DictMetadataStore.

Recommended approach: Build everything with a raw Dictionary first:
1. Create Dictionary::default()
2. Push all file content via State::push_all(&mut dict, bytes)
3. Construct DictMetadataStore from that dict (needs a new constructor or use the dict for metadata too)

Alternative (simpler): DictMetadataStore already holds Mutex<Dictionary>. Add a `pub fn with_dict<F, R>(&self, f: F) -> R where F: FnOnce(&mut Dictionary) -> R` method to metadata crate, or use the commit() flow which returns the root and the executor serializes the dict separately.

SIMPLEST approach matching existing code: The DictMetadataStore::new() creates its own dict. During seed, we need to push file content into that SAME dict. The store's commit() method locks the dict and serializes state into it. We can expose the dict via a new `pub fn dict(&self) -> &Mutex<Dictionary>` accessor. Then seed does:
- `let store = DictMetadataStore::new();`
- `{ let mut dict = store.dict().lock().unwrap(); State::push_all(&mut *dict, &bytes); }`
- `store.set_manifest(ino, &[content_digest])?;`
- `let root = store.commit()?;`
- `let dict_bytes = serialize_dictionary(&*store.dict().lock().unwrap());`

Create `crates/slicefs-cli/src/seed.rs` with a `pub fn run_seed(store_path: &Path, source_dir: &Path) -> Result<(), Box<dyn std::error::Error>>` function:

1. **Create store directory** if it doesn't exist (`std::fs::create_dir_all`).

2. **Create DictMetadataStore and walk source:**
   ```rust
   let meta_store = DictMetadataStore::new();
   ```

3. **Walk source_dir recursively** using `std::fs::read_dir` + manual recursion (no extra deps). Process children before parents is not needed — process in natural order: for each entry in a directory, if it's a file, create it; if it's a dir, create_directory then recurse into it.

4. **For each regular file:**
   - Read file bytes: `std::fs::read(&path)`
   - Get file metadata: `std::fs::metadata(&path)` for size, mode, uid, gid, mtime
   - Push content into the store's dictionary:
     ```rust
     use blockset::content_dependant_tree::State;
     use blockset::Tree;  // MUST be in scope for push_all
     let content_digest: Digest224 = {
         let mut dict = meta_store.dict().lock().unwrap();
         State::push_all(&mut *dict, &file_bytes)
     };
     ```
   - Create inode via `meta_store.create_inode(&InodeMeta::new_file(...))`
     - Set size to file_bytes.len() as u64
     - Set mode to S_IFREG | (fs_metadata.permissions().mode() & 0o7777) on Unix, or 0o644 default
     - Set uid/gid from fs_metadata (Unix) or 0/0
     - Set mtime from fs_metadata.modified()
   - Link file into parent directory: `meta_store.link(parent_ino, &name, ino)`
   - Store content digest as single-element manifest: `meta_store.set_manifest(ino, &[content_digest])`

5. **For each directory (not the root source_dir itself — that maps to inode 1):**
   - Create InodeMeta::new_directory with appropriate mode/uid/gid
   - `meta_store.create_directory(parent_ino, &name, &meta)` — this creates the dir inode and adds . and .. entries

6. **Handle the root mapping:** The source_dir itself maps to inode 1 (the root dir in DictMetadataStore::new()). Its direct children are added under inode 1.

7. **Persist to disk:**
   ```rust
   let root = meta_store.commit()?;
   let dict_bytes = serialize_dictionary(&*meta_store.dict().lock().unwrap());
   std::fs::write(store_path.join("dictionary.bin"), &dict_bytes)?;
   // root.bin: 28 bytes (7 x u32 LE)
   let mut root_bytes = Vec::with_capacity(28);
   for word in &root {
       root_bytes.extend_from_slice(&word.to_le_bytes());
   }
   std::fs::write(store_path.join("root.bin"), &root_bytes)?;
   ```

8. **Wire into main.rs:** Replace the `todo!("seed")` stub with `seed::run_seed(&store, &source_dir)?`.

9. **Add `mod seed;`** to main.rs or lib.rs.

Note: The "directory-based store" decision is satisfied: the store path IS a directory containing dictionary.bin and root.bin. The simpler serialize_dictionary approach is used instead of per-blob FileStorageAdd, per the RESEARCH.md recommendation.
