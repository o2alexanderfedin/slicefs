<objective>
Make the metadata store safe and parallel for N request threads: an atomic single-inode read-modify-write, sharded inode and directory caches whose cold loads and flushes run with no lock held, no `StoreIo` lock on the hot path, and creates by a given inode number for replay.

Decision IDs are numbered in 19-01-PLAN.md (objective). This plan implements:
- D-05 `DictMetadataStore::modify_inode(ino, FnOnce(&mut InodeMeta))` under the `inode_live` shard lock.
- D-08 (part) replay creates an inode with the logged inode number: the store side, `create_inode_at` and `create_directory_at` (replay uses them in Plan 10).
- D-06 (use): shard locks are `Rank::Store`.
- D-18: the `Arc<Mutex<StoreIo>>` type stays in the constructors; only the hot path stops locking it.

RESEARCH Lock Inventory A rows 2-8 (with_dir, flush_dirs, load_meta, flush_inodes, manifest, xattr, create_directory) are closed here; Pitfall 7 (a late flush install brings back a deleted inode) has its test here.

Purpose: LOCK-01 names `dir_live`/`inode_live`; ROADMAP criterion 3 needs them free of disk I/O and hashing; read-modify-write races (RESEARCH dependencies 9-10) need modify_inode before requests run in parallel.
Output: the changes in `store.rs`, `store_io.rs`, the trait, the callers in `filesystem.rs`, a read-hold knob in `mem.rs`, two lock-stats sites.
</objective>
