<objective>
Order the namespace with striped locks, make open/close/unlink atomic, model the std commit gate in the rank checker at rank 1, and put `serialize_off_target` into the default suite.

Decision IDs are numbered in 19-01-PLAN.md (objective). This plan implements:
- D-04 `NamespaceLocks`: a fixed striped lock array; multi-inode operations take their stripes in ascending stripe order; a rename mutex for cross-directory rename comes first.
- D-06 the full rank: 1 gate, 2 rename, 3 stripes ascending, 4 cell, 5 short maps, 6 store internals.
- D-15 ascending stripe order is the LOCK-03 order; this plan updates the LOCK-03 text and ROADMAP criterion 4 to "in ascending stripe order (inode number hashed to a stripe)".
- D-16 the std commit gate is modelled in the rank checker at rank 1 through helper methods, so a test fails when a cell or stripe is taken without a gate hold (the checker side is in Plan 01; this plan wires it).
- D-18 (use) the gate stays a std `RwLock`; only helpers wrap it.

RESEARCH: Pattern 4 rules 1-5 and the rename-mutex part of rule 6, Pattern 5 (gate helpers), PITFALLS 6b/6c (lookup-then-lock revalidation, create in a removed parent), Inventory C dependency 11 (check-then-act namespace operations), Risk 7 (serialize_off_target shortened to 2 s per mode).

Purpose: ROADMAP criteria 4 and 2 (many-files mode), and the phase target `serialize_off_target`.
Output: `locks.rs`, namespace locking in `filesystem.rs`, the gate helpers in all callers, the un-ignored target, the wording change.
</objective>
