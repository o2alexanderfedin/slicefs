<objective>
Move the overlay rebase step out of the file lock with the copy -> I/O without lock -> publish-if-generation-unchanged protocol, so readers and writers of a file never wait for a rebase's chunk, hash or put.

Decision IDs are numbered in 19-01-PLAN.md (objective). This plan implements:
- D-02 (overlay rebase path) A write does its rebase step (chunk, hash, store put) outside the file lock. Under the lock it copies the range to rebase. It releases the lock and does the I/O. It takes the lock again and publishes the result only if the file generation did not change; otherwise it drops the result and retries later. Readers hold the file lock only for memory copies. A read sees all of a write or none of it, because a write applies to the overlay under the file lock (user choice; reversibility costly).
- D-13 (use): the writer's own budget step (`free_dirty`) runs through the same protocol.

RESEARCH: Pattern 1 (cell protocol, overlay part: `copy_step`, `discard`, `gen`, `rebasing` flag, hard cap, hook placement, publish with state read at publish time), Pitfall 1 (starvation, hard cap test), Pitfall 2 (no restore over newer bytes), Pitfall 8 (parked tests hold no gate and run no commit thread). Plan 07 applies the protocol to the streaming, flush, finalize and settle paths.

Purpose: ROADMAP criterion 1 ("readers do not wait for the I/O of writers") on the overlay path, which every random write takes.
Output: `overlay.rs` generation API, the three-phase `rebase_step`, `prepare_manifest`/`set_manifest_digest`, `lock_free_io.rs`.
</objective>
