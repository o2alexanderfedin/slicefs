<objective>
Replace the take-out pattern with one `Arc<FileCell>` per open inode, add a handle table that knows each handle's mode, give `readers` a per-inode lock, and adapt `keep_budget` to dirty atomics. In this plan the cell lock covers each step that chunks, hashes or puts (the same span in which the old code held the taken-out state); Plans 06 and 07 move that I/O out of the cell lock (D-02).

Decision IDs are numbered in 19-01-PLAN.md (objective). This plan implements:
- D-03 One `Arc<FileCell>` per open inode in a sharded `ino -> Arc<FileCell>` map; all handles share it; the alias map, the owner lookup helper and the heir swap go away; the last handle drop runs the finalize.
- D-07 `readers`: `HashMap<ino, Arc<Mutex<Reader>>>`; clone the Arc under the map lock and lock the per-inode reader only for the read.
- D-10 `write_rebase_bytes`, `write_base_bytes`, `last_rebase_bytes` become thread-local.
- D-13 `keep_budget` uses per-cell dirty atomics and a global total; each writer steps only its own file inline; the flusher and the throttle stay in Phase 20.
- D-06 (use): cell = `Rank::Cell` keyed by inode; map shards and handle table = `Rank::Short`.

RESEARCH: Pattern 2 (handle and cell table), Pattern 6 (readers), Pattern 8 (keep_budget, with D-13's "own file only"), Pitfall 4 (cell identity at last release), Pitfall 10 (counters), Inventory A row 1 (`readers`), single-thread dependencies 1-7 and 13-14.

Purpose: the stale reads, EBADF and no-op fsync that `serialize_off_target` showed in Phase 18 come from the take-out pattern; this plan removes it.
Output: the cell and handle tables in `filesystem.rs`, new lock-stats sites, `multi_handle_posix.rs` (first cases; Plan 08 adds the rest).
</objective>

Rules:
