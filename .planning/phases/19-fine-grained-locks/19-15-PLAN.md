<objective>
Close the rest of LOCK-05 (ROADMAP Phase 19 criterion 1).

Orchestrator decision G3 (gap closure), release and finalize part: finalize stays correct when steps drop, with a loop of unlocked steps and a bounded retry count, and it keeps the 19-07 rules on retire and new handles. Also: a stress/test mode that forces a step to drop, so the fallbacks run, and a lock-wait test that proves a reader does not wait for writer I/O in that mode.

19-14 added the step token, unlocked retries on the write and read paths, and `test_drop_steps` / `test_drop_every`. This plan:
- removes the last locked fallbacks (finalize's locked rebase step and its locked flush retry);
- moves the empty-manifest store calls out of the hold;
- runs the open-stream size change through the token;
- makes reads skip the transient cell;
- adds the forced-drop evidence.
D-02 (user decision): readers hold the file lock only for memory copies.

Planner choices (reversible):
- `FINAL_TRIES` = 8 passes in a row with nothing published, then finalize stops and leaves the cell live. This is the state 19-07 already has when a new writer stops a finalize. With no handle, only a size change or a forced drop can drop a finalize step, so the limit is reached only in tests or under a storm of size changes. The next release, the commit relog (overlay extents are logged again after each cut) or destroy stores the content.
- The transient cell keeps its splice under its own lock. It is a closed file, and an open or a second size change still waits for it (the 19-07 order). Readers stop locking it. The closed-file races with unlink and with a fields setattr stay deferred (deferred-items.md, owner scope).
- The destroy form of finalize becomes a separate `finalize_locked` (no request runs at destroy). The commit cut keeps its locked flush (exclusive gate, no request runs).

Purpose: no reader of a file waits for a writer's chunk, hash, store put or flush on any request path.
Output: unlocked finalize and setattr stream steps, the transient-cell read rule, the forced-drop lock rows, a short concurrent forced-drop test, and the harness knobs for the by-hand run.
</objective>
