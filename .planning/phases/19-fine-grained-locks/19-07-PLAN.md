<objective>
Apply the copy -> I/O without lock -> publish protocol to every other step that chunks, hashes or puts: streaming writes, the switch to an overlay, settling pending writes, reads, fsync and flush, the last-release finalize, and the truncate of a closed file. Prove that files do not wait for each other (criterion 2) and that reads stay safe during online GC.

Decision IDs are numbered in 19-01-PLAN.md (objective). This plan implements:
- D-02 (streaming, read, flush and finalize paths) chunk, hash and store put happen outside the file lock; publish only if the generation did not change; readers hold the file lock only for memory copies (copy the overlay view or clone the stream) and then read with no lock (user choice; reversibility costly).
- D-03 (use) the last handle drop runs the finalize, now in bounded steps.

RESEARCH: Pattern 1 ("Streaming writes (ruling)", "Finalize (last handle)", "Truncate of a closed file"), Pitfall 3 (GC deletes what a lock-free read uses: test), Pitfall 4 (retired cell during stepwise finalize), Pitfall 5 (out-of-order publish of fsync/flush), Inventory C dependencies 3, 4, 6.

Purpose: ROADMAP criteria 1 and 2.
Output: the protocol in `filesystem.rs` (and `content.rs` helpers if needed), new tests in `lock_free_io.rs` and `gc_online_tests.rs`.
</objective>
