<objective>
Put every hot-path lock of the three hot crates behind one shim, `chunk_store::sync`, over `parking_lot` 0.12, with a debug rank checker and the lock-stats timing inside the shim. No behavior change: this plan is the lock API that Plans 02-11 build on.

Decision IDs: CONTEXT.md has no numbered decisions, so this phase numbers them in CONTEXT order; the "Answers to the research open questions" list continues the numbering, and its deferred entry gets no ID.
D-01 parking_lot 0.12 (feature `arc_lock`) through one shim in chunk-store, metadata and slicefs-cli; the lock-stats wrapper and the rank checker wrap it; feature `deadlock-detect` (`parking_lot/deadlock_detection`) for stress builds (user choice; reversibility costly).
D-02 Read while write: copy under the file lock, chunk/hash/put with no file lock, publish only if the file generation did not change, else drop and retry; readers lock only for memory copies; a read sees all or none of a write (user choice; reversibility costly).
D-03 One `Arc<FileCell>` per open inode in a sharded ino map, shared by all handles; the alias map, `owner_fh` and the heir swap go away; the last handle drop finalizes.
D-04 `NamespaceLocks`: fixed striped lock array; multi-inode operations take stripes in ascending stripe order; a rename mutex comes first for cross-directory rename.
D-05 `DictMetadataStore::modify_inode(ino, FnOnce(&mut InodeMeta))` under the `inode_live` shard lock.
D-06 Rank: 1 commit gate (shared), 2 rename mutex, 3 namespace stripes (ascending), 4 `FileCell.state`, 5 short maps (`handles`, `orphans`, cell map shards, `readers` map), 6 store internals (`DictMetadataStore`, WAL, `ChunkStore`); checker = thread-local stack of held ranks behind `debug_assertions`.
D-07 `readers`: `HashMap<ino, Arc<Mutex<Reader>>>`; clone the Arc under the map lock, lock the per-inode reader only for the read.
D-08 The log record append (memory copy plus LSN) happens under the same locks as its apply; disk write and sync happen outside the locks; replay creates an inode with the logged inode number.
D-09 Issue #21 body is updated to the log-order rule; no licensing text.
D-10 `write_rebase_bytes`, `write_base_bytes`, `last_rebase_bytes` become thread-local or test-only.
D-11 LOCK-05 and POSIX 2.9.7 are shown by extending the Phase 18 harness: handles in read-only, read-write and `O_APPEND` modes; visibility across handles, all-or-none reads, appends that never overlap; lock wait rows show readers do not wait for writer I/O; many-files runs show no cross-file contention.
D-12 The daemon takes the append offset from the current size under the file lock.
D-13 `keep_budget` moves to per-cell dirty atomics and a global total; each writer steps only its own file inline; the flusher and the throttle stay in Phase 20.
D-14 LOCK-01 scope: a page-cache `pwrite` under `ChunkStore::inner` is not disk I/O; pack create, seal join, index flush, fsync and the KEEP_CAP wait are, and must leave the lock.
D-15 Ascending stripe order is the LOCK-03 order; the stripes plan updates LOCK-03 and ROADMAP criterion 4 to "in ascending stripe order (inode number hashed to a stripe)".
D-16 The std commit gate is modelled in the rank checker at rank 1 through helper methods, so a test fails when a cell or stripe is taken without a gate hold.
D-17 `O_APPEND`: no extra macOS CI probe; per-handle append flag, EOF under the cell lock, the log carries the effective offset.
D-18 `Arc<Mutex<StoreIo>>` (about 115 construction sites) and the commit gate stay std types in this phase.
Claude's discretion: shard counts, stripe count, the exact shim API.

This plan implements D-01, D-06 (checker core), D-16 (checker side: gate marker and strict-gate rule; the wiring is Plan 09) and D-18.

Purpose: every later plan adds locks with a rank; the checker must exist before the first new lock.
Output: `crates/chunk-store/src/sync.rs`, the migration of all hot-path lock sites, the `deadlock-detect` feature and the harness watchdog.
