<objective>
Swap the body of `rebase_overlay` (plan 14-01: a whole-file re-stream) for the splice of plan 14-02, use the splice for a size change with no open handle, and prove BUFR-03 and BUFR-05 with tests.

Decision IDs (14-CONTEXT.md has no IDs; the planner numbers the bullets in order, as in plan 14-01): D-04 [rebase re-chunks only near the dirty extents and replaces that range of chunk references; unchanged chunks keep their IDs], D-06 [a rebase is protected from online GC, with a test that runs GC during a rebase], D-08 [deterministic chunking; exact zero shortcut], D-13 [the splice API is in scope], D-19 [a base only the handle knows is a GC hazard; every base is installed and is a file root].

This plan implements D-04 (complete), D-06 (tests), D-13 (wiring), and proves D-08 and D-19 end to end.

Reading of BUFR-03 (and roadmap success criterion 4): the commit gate is never held exclusively (commit_cut, gc_start) for the hash of file content. A rebase holds the gate shared, as every FUSE callback does. On random data the splice re-chunks only near the change, so the shared hold is short. On long repeating non-zero data, canonical chunking (D-08) can make the splice re-chunk to the end of the file; then a timed commit or a gc_start waits until that callback ends. Memory stays fixed in that case. The SUMMARY repeats this reading, and plans 14-07 (write-log.md) and 14-08 (#98 comment) carry it.

GC safety argument, checked by the planner and tested here: every rebase runs inside a FUSE callback that holds `commit_gate.read()` (write, setattr, release, destroy), and gc_start takes `commit_gate.write()` before gc_begin. So no rebase straddles gc_begin. A rebase during mark or sweep puts only new objects (touched, so kept) and reuses chunks and whole nodes of its base by ID; the base is in the manifest of the gc_start commit and in file_roots, so it is marked.

Purpose: a rebase then costs O(change + resync + depth), so the commit gate never waits on the hash of a whole file and the 4 GiB Docker run is fast.
Output: content::splice, OverlaySource, the new rebase body, Case B with the splice, 6 new tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon rebase <-> online GC thread | The GC sweep deletes objects that no root and no touched set names; the rebase reuses objects by ID without a read |
| manifest tree (maybe from a peer) -> splice | Node lengths and levels are not trusted |
