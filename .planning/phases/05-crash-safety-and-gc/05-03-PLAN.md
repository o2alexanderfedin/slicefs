<objective>
Implement the mark-and-sweep garbage collection engine with segment compaction and background GC thread infrastructure.

Purpose: GC reclaims orphaned blocks from deleted/overwritten files. Without GC, the segment store grows unboundedly. The multi-root mark-and-sweep design ensures snapshot-referenced blocks are never deleted.

Output: GC engine that can collect live set from multiple roots, compact segments, and run as a background thread.

**gc/mod.rs — Mark-and-sweep engine:**

```rust
pub fn collect_live_set(
    dict: &Dictionary,
    roots: &[Digest224],
) -> HashSet<Digest224>
```
- For each root, call `mark_reachable(dict, root, &mut live_set)`
- `mark_reachable` is recursive: if digest already in set, return (cycle/duplicate protection). Otherwise insert digest, get Branches from dict, extract child Digest224s from Branches, recurse on each non-zero child.
- Extracting children from Branches: Branches is `[u32; 16]` = 64 bytes. The blockset Merkle tree stores child digests as pairs of Digest224s packed into Branches. The exact layout depends on blockset internals. Use `blockset::Tree` trait's iteration or, if not available, treat Branches as two potential child Digest224s: `branches[0..7]` and `branches[7..14]` (each is a Digest224). If a child is all-zeros, skip it (null/leaf node). This needs verification against the actual blockset Branches layout — check how `serialize_dictionary` packs entries.

Actually, the simpler approach: the live set should be collected at the Dictionary level. Every key in the Dictionary that is reachable from a root via the Merkle tree structure is live. Since `Dictionary` is essentially a `HashMap<Digest224, Branches>`, and the Merkle tree links parent digests to child digests through Branches, walk from roots through the tree structure.

Add `pub struct GarbageCollector` with:
- `pub fn new(segments_dir: PathBuf) -> Self`

- `GcStats { entries_scanned: usize, entries_removed: usize, segments_compacted: usize }`

**gc/background.rs — Background GC thread:**

```rust
pub struct GcHandle {
    shutdown: Arc<AtomicBool>,
    handle: Option<std::thread::JoinHandle<()>>,
}

impl GcHandle {
    pub fn shutdown(mut self) {
        self.shutdown.store(true, Ordering::SeqCst);
        if let Some(h) = self.handle.take() {
            let _ = h.join();
        }
    }
}

impl Drop for GcHandle {
    fn drop(&mut self) {
        self.shutdown.store(true, Ordering::SeqCst);
        // Don't join in drop — thread will exit on next loop iteration
    }
}
```

`pub fn spawn_background_gc(...)`:
- Takes `meta: Weak<DictMetadataStore>`, `segments_dir: PathBuf`, `interval: Duration`, `orphan_threshold: usize`, `shutdown: Arc<AtomicBool>`
- Spawns a thread that loops:
  1. `thread::sleep(interval)` (or use `condvar` for immediate shutdown response — but sleep is simpler and acceptable for Phase 5)
  2. Check `shutdown.load(Ordering::SeqCst)` — if true, break
  3. `meta_weak.upgrade()` — if None, break (filesystem unmounted)
  4. Lock `dict`, count entries with refcount=0 (approximate orphan count)
  5. If orphan_count > orphan_threshold, run `GarbageCollector::run_gc`
  6. Drop the Arc<DictMetadataStore> before sleeping again
- Returns `GcHandle` holding the shutdown flag and join handle

For the GC cycle, the thread needs access to the list of snapshot roots. For Phase 5, snapshots are not yet implemented (Phase 6), so the roots list is `[current_root]` only. Add a `pub fn current_root(&self) -> Option<Digest224>` method to DictMetadataStore that returns the last committed root (store it as a field updated by `commit()`).

Add background GC tests to the existing `gc_tests.rs` file.
