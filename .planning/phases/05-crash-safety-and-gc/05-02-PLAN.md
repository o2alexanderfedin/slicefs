**DictMetadataStore changes (store.rs):**
- Add field `wal: Option<Box<dyn WalStrategy>>` to DictMetadataStore
- Add `pub fn set_wal(&mut self, wal: Box<dyn WalStrategy>)` to set WAL after construction
- In every method that mutates `dict` (the Dictionary), BEFORE the mutation, call `self.wal.as_ref().map(|w| w.log_mutation(&entry))`. The WalEntry captures the Dictionary key-value pair being inserted. Methods to instrument: all places that call `dict.insert()` or equivalent through `intern_inode`, `create_dir_entries`, `add_dir_entry`, `intern_manifest`, `intern_xattrs`, and `commit()` (for RootUpdate). The key insight: the Dictionary is a content-addressed store — every `State::push_all` or `State::end()` call produces a Digest224 and inserts entries. Intercept at the Dictionary level by adding a `log_dict_insert` helper method that wraps dict operations.
- Add `pub fn flush_wal(&self) -> Result<(), WalError>` — calls `wal.flush_and_sync()`
- Add `pub fn shutdown_wal(&self) -> Result<(), WalError>` — calls `wal.shutdown()`
- IMPORTANT: Do NOT hold the dict Mutex while calling WAL methods — copy the key/branches first, drop dict lock, then log. This prevents the Dictionary lock from being held during fsync (see Pitfall 1 in RESEARCH.md).

**Segment-based persistence (add to segment/mod.rs):**
- `pub fn load_store_from_segments(segments_dir: &Path) -> Result<(Dictionary, Option<Digest224>), SegmentError>` — reads all segment files sorted by segment_id, replays DictEntry records into a Dictionary, returns the last RootUpdate digest seen
- `pub fn migrate_legacy_store(store_path: &Path) -> Result<(), SegmentError>` — reads dictionary.bin + root.bin, writes a single segment file with all entries + a RootUpdate, deletes dictionary.bin and root.bin
- Segment files live in `<store>/segments/` subdirectory
- Segment naming: `segment-{id:06}.seg` (e.g., `segment-000001.seg`)

**Dirty mount detection (mount.rs):**
- `pub struct MountLock { lock_path: PathBuf }` with `Drop` impl that removes the lock file
- `pub fn acquire_mount_lock(store_path: &Path) -> Result<MountLock, MountError>` — checks for `mount.lock`, returns DirtyMount error if present, otherwise creates it
- Update `load_store` to become `load_store(store_path, wal_config)`:
  1. Check for `dictionary.bin` — if present, call `migrate_legacy_store`
  2. Call `acquire_mount_lock` — if DirtyMount, replay WAL (segment files already contain the WAL entries; just re-load segments which is idempotent)
  3. Call `load_store_from_segments` to reconstruct Dictionary + root
  4. Call `DictMetadataStore::load_from_root`
  5. Create WAL via `create_wal(wal_config, store_path, next_segment_id)`
  6. Set WAL on DictMetadataStore

**CLI changes (cli.rs):**
- Add `--wal-strategy` argument to Mount subcommand with possible values: "per-op" (default), "periodic", "flush-on-fsync", "no-wal"
- Map string to `WalConfig` enum
- Pass to `run_mount`

**destroy() update (mount.rs or filesystem.rs):**
- In `destroy()`, instead of writing dictionary.bin, call `meta.shutdown_wal()` which flushes the final segment
- The MountLock drops automatically when the filesystem is destroyed, removing mount.lock

**Implement fsync FUSE callback in filesystem.rs:**

Add `fn fsync(&self, _req: &Request, ino: u64, fh: u64, _datasync: bool, reply: ReplyEmpty)` to the `impl Filesystem for SliceFsFilesystem` block:
1. Check if `fh` has a write buffer in `open_files` — if so, flush it through CAS pipeline using the same `flush_buffer_to_cas` logic as `release()`, BUT do NOT remove the open_files entry (unlike release, the file stays open after fsync)
2. Call `self.meta.flush_wal()` to ensure WAL entries are durably on disk
3. `reply.ok()` on success, `reply.error(libc::EIO)` on failure

Add a `pub fn test_fsync(&self, ino: u64, fh: u64) -> Result<(), i32>` helper method (same pattern as test_release, test_write etc.) for integration testing without FUSE.

**Key difference from release():** `flush_buffer_to_cas` in release() removes the buffer from `open_files`. For fsync, the buffer must be flushed (written to CAS) but then RESET to empty (not removed) — the file handle remains open for subsequent writes. Create a `flush_buffer_for_fsync` method that:
1. Takes the buffer out of open_files
2. Flushes it through CAS (same logic as flush_buffer_to_cas)
3. Puts an empty Vec back into open_files for the same fh
4. Returns Ok

Also handle the case where the fh is open for reading (no buffer entry) — fsync is a no-op, just call flush_wal and reply.ok().

Write tests in `crates/slicefs-cli/tests/fsync_tests.rs`. For the crash+reload test, create a DictMetadataStore with PerOpWal, write data, call test_fsync, drop everything without calling destroy, then load_store_from_segments and verify the data is present.
