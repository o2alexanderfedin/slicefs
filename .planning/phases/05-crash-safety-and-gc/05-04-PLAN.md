**gc.rs — Offline GC command:**

```rust
pub fn run_gc(store_path: &Path) -> Result<(), Box<dyn std::error::Error>>
```
1. Check for `mount.lock` — if present, return error "Store is mounted. Unmount first or use background GC."
2. Call `load_store_from_segments(store_path.join("segments"))` to get Dictionary + root
3. Collect roots: `[root]` (snapshots not implemented yet — Phase 6 will add snapshot root discovery)
4. Create `GarbageCollector::new(store_path.join("segments"))`
5. Call `gc.run_gc(&dict, &roots)`
6. Print stats: "GC complete: scanned {N} entries, removed {M}, compacted {K} segments"
7. Return Ok

**cli.rs — Add Gc subcommand:**
```rust
Gc {
    /// Path to the SliceFS block store directory.
    store: PathBuf,
}
```

**main.rs — Wire Gc command:**
Add `Cmd::Gc { store } => gc::run_gc(&store)?` to the match block.

**mount.rs — Background GC wiring:**
Update `run_mount` to:
1. After creating `SliceFsFilesystem` with `Arc<DictMetadataStore>`, create `Weak` reference
2. Call `spawn_background_gc(weak_meta, segments_dir, Duration::from_secs(60), 1000, shutdown_flag.clone())`
3. Store `GcHandle` — call `gc_handle.shutdown()` after `mount2` returns (before MountLock drops)
4. The `SliceFsFilesystem` needs to be constructed with `Arc<DictMetadataStore>` so the GC thread can hold a `Weak` — this is already the case (filesystem.rs uses `Arc<DictMetadataStore>`)

Note: `mount2` is blocking — it returns when the FUSE session ends. The GC thread runs concurrently during the session. After mount2 returns, shut down GC thread, then let MountLock drop.

Write tests in `crates/slicefs-cli/tests/gc_cli_tests.rs`. Create test stores with known live/dead entries using segment writer directly, then run `run_gc` and verify compaction results.

Create comprehensive integration tests in `crates/slicefs-cli/tests/crash_recovery_tests.rs` that prove the 5 phase success criteria. These tests use the `test_*` helpers on `SliceFsFilesystem` to drive the filesystem without mounting via FUSE.

**Test structure pattern for each test:**
1. Create a `tempfile::TempDir` as the store path
2. Create a `DictMetadataStore::new()` with `set_wal(PerOpWal)` pointing at the temp store's segments dir
3. Create a `SliceFsFilesystem::new(meta, content_dict, Some(store_path))`
4. Perform operations via `test_create`, `test_write`, `test_release`, `test_fsync`, `simulate_*` methods
5. For crash simulation: drop the SliceFsFilesystem WITHOUT calling destroy(). Ensure mount.lock remains.
6. For remount: call `load_store(store_path, WalConfig::PerOp)` which detects dirty mount, replays WAL
7. Verify filesystem state matches expectations

**Test SC1 (crash during write):**
- Create file, write "hello world", DO NOT release (simulates mid-write crash)
- Drop filesystem
- Remount from segments
- The unreleased file should either: (a) not exist (write was never flushed to CAS), or (b) have consistent state from the last flush
- No panics, no corrupted data, filesystem is browsable

**Test SC2 (fsync durability):**
- Create file, write data, call test_fsync
- Drop filesystem without destroy
- Remount, read file — data is present

**Test SC3 (orphaned blocks):**
- Create file A, write data, release (blocks in CAS)
- Delete file A (unlink) — blocks now orphaned (refcount=0 if properly decremented)
- Commit (so root no longer references file A's data)
- Run `GarbageCollector::run_gc` with current root as only root
- Verify: orphaned entries removed from segments

**Test SC5 (WAL replay):**
- Create store with PerOpWal
- Create several files, write data, commit
- Leave mount.lock in place (simulate dirty unmount)
- Call load_store — triggers replay
- All files and data present

**Test multiple fsync cycles:**
- Create file, write "A", fsync, write "B" (append), fsync
- Drop without destroy
- Remount, file contains "AB" (both syncs survived)

These tests exercise the complete integration: DictMetadataStore + WAL + segments + GC + fsync. They prove the phase success criteria without requiring an actual FUSE mount.
