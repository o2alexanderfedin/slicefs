<objective>
Build the layout engine of the Q-2 test (PMAP-01, D-02): extract the change of all five metadata maps of each real commit, and replay the commits into layout a (one prolly tree per map), layout b (one combined tree, refcounts inside) and layout c (combined tree, refcounts apart), with the measurements that the decision needs. Plan 25-06 adds the synthetic 1M/10M source and the runner on top of the same engine.

Task 1 (tracer) wires one path end to end: `maps` writes the five-map batches of the smoke commits, `layout --layout a` builds five trees, replays every commit and checks the final trees against the real final maps. Task 2 adds layouts b and c, the full output schema, the `--l`/`--node-max` options and the smoke asserts.

Decisions this plan implements: D-02 (both layouts wired into `benchmarks/prolly-bench`, with refcounts in every layout), D-04 (refcounts is a prolly map), D-01 (the bench streams the maps: two map streams at a time, never a whole map in RAM).

Discretion choices (recorded in the SUMMARY): layout c (b with refcounts apart) is a third arm, because refcounts have another key space and lifetime (#165) (RESEARCH A1); the combined key puts the inode first (`ino ‖ kind`), so the records of one file share a leaf; the key grammar leaves room for a later name suffix (`0x01 ‖ ino ‖ kind ‖ name`), but directory entries stay one value per directory in this bench (RESEARCH Open Question 1: by-name entries are a Phase 26 decision, the bench uses the value shape of today's maps); the edits of one commit are sorted in a `Vec` (a commit is small), the base is streamed.

Purpose: ROADMAP criterion 1 (the data for the layout decision).
Output: `layout.rs`, the `maps` and `layout` modes, smoke asserts, `runs/gate-25-05.log`.
</objective>
