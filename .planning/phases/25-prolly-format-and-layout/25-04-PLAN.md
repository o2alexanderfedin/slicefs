<objective>
Add the optional per-store boundary salt (D-10): a header setting line `boundary-salt <hex>` with its own ro_compat flag, set only by `slicefs seed --boundary-salt` when the store is made, and refused on an existing store. In Phase 25 the salt reaches no map code (the maps are still flat); plan 25-01 already made `prolly::Config` take a salt, and Phase 26 passes `Header::boundary_salt()` to it.

Task 1 (tracer) wires the path end to end through the library: `run_seed_with_salt` with `random` or a hex value writes the salt line and flag in the first header write, and the parser returns the salt. Task 2 adds the CLI option, the grammar and pairing refusals, the M18 refusal on an existing store and the concurrency test. Task 3 documents the salt in the store-format doc and runs the gates.

Decisions this plan implements: D-10 (salt line with its own flag, class ro_compat, default no salt, `seed --boundary-salt random`), D-11 (the salt is set at seed only; a later change of the salt is the deferred rebuild command and is out of scope here: an existing store refuses any other salt).

Discretion choices (recorded in the SUMMARY): class ro_compat (a build that does not know the flag can read the trees, because reading does not use the salt, but must not write them, because it would cut with another rule; same reasoning as `chunk-profile`); release word `v2.4` (release v2.4.0 is the first to know it); `random` is refused on an existing store even when the store has a salt (a salt is fixed when the store is made); the existing functions `run_seed_with`, `content::check_write_with` and `header::marker_with` keep their signatures and pass no salt (they have callers in the bench and in about 20 tests); no salt row in `stats` (the Feature flags row lists the flag; RESEARCH: low value); no dependency on the `prolly` crate from `slicefs-cli` in this phase.

Purpose: D-10 for ROADMAP criteria 3 and 4 (the salt is part of the rule input and of the format 8 header).
Output: the header line and flag, the seed option, tests, the doc section, `runs/gate-25-04.log`.
</objective>
