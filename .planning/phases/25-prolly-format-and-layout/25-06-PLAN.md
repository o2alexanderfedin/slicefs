<objective>
Complete the Q-2 and constants test (PMAP-01, D-02, D-05, D-08): a synthetic five-map source at 1M and 10M inodes with the D-02 commit mix, a runner for the whole matrix (Boost and synthetic rows, three layouts, three configs) that also runs in Docker on disk-backed storage, and the decision rules as a committed script, written before the run (pre-registration).

Task 1 (tracer) wires the synthetic path end to end: `synth` makes the five maps from generated streams, builds them in a layout through the engine of 25-05, runs `one` commits and checks the result. Task 2 adds the `mixed` and `insdel` patterns and the full check. Task 3 adds the runner, the decision script with a self-test, the Docker case and the README, and runs the smoke of the whole chain.

Decisions this plan implements: D-02 (Boost, 1M and 10M rows; one change, K=100, K=1,000, insert/delete heavy; both layouts and the refcounts-apart arm), D-04 (refcounts in every layout), D-05 (the 1B extrapolation method, as code), D-08 (the L sweep: Dolt values against L=8192 with two NODE_MAX values; forced-cut share), D-01 (streams only).

The pre-registered rules (the same text is in plan 25-07 and in `decide.py`; plan 25-07 must not change them):
- Rows. "Small" rows: for each source (Boost; synthetic 1M; synthetic 10M) the K=1 row (Boost `scatter` k=1, synthetic `one`) and the K=100 row (Boost `scatter` k=100, synthetic `mixed` k=100): 6 rows. "Large" rows: per source the K=1,000 row (Boost `scatter` k=1000, synthetic `mixed` k=1000) and the insert/delete row (`insdel` k=1000): 6 rows. Per row and layout the value is the median over its commits; nodes = nodes_read + nodes_written; CPU = cpu_user_s + cpu_sys_s.
- Layout (decided at the Dolt config 4096/16384): an arm X in {b, c} qualifies against a iff the mean over the small rows of nodes(X)/nodes(a) is at most 0.80, the mean over the small rows of CPU(X)/CPU(a) is at most 1.25 (an allowance for the noise of a shared host; a real CPU regression of the combined key is larger), the largest bytes_written(X)/bytes_written(a) over the large rows is at most 1.10, and the 1B node count of X is not larger than that of a. If both qualify, take the lower node ratio; within 0.02 of each other, take c. If none qualifies, take a (simpler; a tie goes to a). The deterministic columns (nodes, bytes) decide; CPU only guards.
- Constants (for the chosen layout): N1B(C) = the 1B node count; W(C) = the mean of the median bytes_written over the rows synthetic 10M `one`, synthetic 10M `mixed` k=100 and Boost `scatter` k=1; T(C) = the same mean of the median CPU; F(C) = forced cuts / nodes of the 10M base build. A config is eligible iff F(C) <= 0.005. A config C other than Dolt D (4096/16384) replaces D iff it is eligible, N1B(C) <= 0.65 x N1B(D), W(C) <= 2.5 x W(D) and T(C) <= 2.0 x T(D). If more than one qualifies, take the smaller NODE_MAX, then the smaller N1B. Else keep D.
- 1B extrapolation (D-05), per tree, from the `tree` row of the synthetic 10M base build: entries per leaf e = entries / leaves; fanout f = leaves / (nodes of level 1); scale the entries by 1,000,000,000 / n; leaves' = ceil(entries' / e); each level above = ceil(previous / f) until 1; nodes = the sum; depth = the number of levels. N1B of a layout = the sum over its trees.

Discretion choices (recorded in the SUMMARY): a new runner `layout.sh` instead of more modes in `bench.sh` (the Phase 24 runner stays as it is); synthetic refcount keys are `0x1e ‖ BE u64 slot ‖ 24 zero bytes` with the slot of a file's key given by an affine bijection mod 2N, so a file's keys land at random leaves while the stream stays in key order; an inserted refcount key copies a random existing slot and sets the last 8 filler bytes to a counter, so it sorts next to that slot at a random leaf.

Purpose: ROADMAP criterion 1 (the data) and criterion 3 (the constants of the rule).
Output: `synth.rs`, the runner, `decide.py`, the Docker case, README, `runs/gate-25-06.log`.
</objective>
