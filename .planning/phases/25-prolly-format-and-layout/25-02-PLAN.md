<objective>
Remove the duplicate inode map (PMAP-02, D-06): `inode_map` and `inode_data` hold the same entries; keep `inode_data`, keep `next_ino` in the root record, and shrink the old map type to a number allocator. The root record goes from 230 to 197 bytes.

Task 1 (tracer) wires the change end to end: a commit writes the 197-byte record, a reload reads it and restores `next_ino`, GC mark and rehash walk the five map keys. Task 2 renames the lock-stats site, updates the bench copy of the record, and runs the workspace and Docker mount gates (ROADMAP criterion 2).

Decisions this plan implements: D-06 (keep `inode_data`: the GC mark and rehash already walk it; `next_ino` is already a root record field, so only RAM changes), D-01 (no new whole-map load; `begin_commit` now clones five maps, not six).

Discretion choices (recorded in the SUMMARY): the type `InodeMap` becomes `InodeAlloc` in `inode_alloc.rs` (it is no longer a map); the lock-stats site and label are renamed to match (`inode_alloc`); the rehash map kind byte 5 is dropped and the other kind values keep their numbers (the byte lives only in rehash work files, not in the store format); `ROOT_DIR_INO` stays in the record (RESEARCH Open Question 5).

Purpose: ROADMAP criterion 2.
Output: the one-map root record, the allocator, the renamed lock site, the bench layout copy, `runs/gate-25-02.log`.
</objective>
