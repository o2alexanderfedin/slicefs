<objective>
Make online GC work on the on-disk index without O(N) RAM and without holding the store lock for a time that grows with the object count, with an all-or-nothing install: no pack changes and no tombstone becomes durable unless every index read that decided them succeeded. Prove that no lookup (get or the put dedup check) returns an object that GC removed.

Purpose: IDX-04 ("No lookup returns an object that online GC removed (GC tests with gc_begin / mark / gc_finish)") and the locked rule "Online GC writes a tombstone run before it punches or deletes a pack ... gc_finish works through the per-pack .idx files, not an O(N) map" [Concurrency: GC tombstones before punch/delete]. The plan checker added two properties: a read error ends the GC with no change, and the long passes run outside the store lock.
Output: the new gc_finish in lib.rs, helpers in index.rs, tests in gc_tests.rs, gc_fault_tests.rs and race_tests.rs.
</objective>

What this replaces: the 17-03 gc_finish runs all its phases under the store lock and fills a per-pack map of every current entry. This plan keeps its order (read everything that decides, then copy, then make tombstones durable, then change packs) but moves the long reads out of the lock and writes the tombstones to pending GC runs on disk instead of the memtable, so RAM stays per pack and nothing is durable before every read succeeded.

Why the touched set is split: today gc_finish holds the store lock for the whole call, so nothing is touched while it decides. With the passes outside the lock, a put or read can touch an object after its pack was planned. gc_finish therefore keeps the set from gc_begin up to its start (it decides with it, as today, so the existing GcStats do not change) and starts a second set for the time it runs; the install drops the plan of every pack that holds an object from the second set.

Out of scope (deferred in 17-CONTEXT.md): the RAM of the GC mark set (the live set passed to gc_finish) and of the touched sets. They still grow with the live and touched object counts; 17-09 drafts a follow-up issue.

  <action>
Write many_packs_gc_with_a_small_memtable first (Tasks 2 and 3 add the rest), then rewrite gc_finish [Concurrency: GC tombstones before punch/delete] [GC interaction] [Concurrency: Arc snapshot]. One gc_finish runs at a time (a GC mutex); merges may run at the same time, because they change no content.
1. Start (store lock; bounded by the memtable limit): take the touched set out as touched_before and put a new empty set in its place (touched_during: puts and reads while gc_finish runs). keep(id) means: in the live set or in touched_before. Sync the active pack and flush the memtable if it is not empty (a normal flush), so every entry of a pack at or below the boundary is in a run. Take an Arc snapshot of the run list. Note the active pack. Release the lock.
2. Pass 1, totals (no store lock): one merged iteration over the snapshot runs (newest wins, tombstones hide). For each current entry whose pack is at or below the boundary and is not the active pack: add to that pack's totals (record bytes, keep bytes, entry count, keep count). RAM: one small struct per pack. A read error returns the error at once: nothing was changed.
3. Decide per pack with today's rules (all kept and not small: keep and count kept_objects; keep bytes at least half and not small: punch; else compact, or delete when nothing is kept). A pack at or below the boundary that exists on disk, is not active and has no totals is unused and is deleted (as today).
4. Pass 2, one selected pack at a time (no store lock, except for the copies): the pack's entries come from its .idx file (decode_index), or from resync_scan when the .idx is missing or damaged. An entry is current if the snapshot lookup (Run::get on the snapshot runs, newest first) returns a Put with this pack and this offset; a lookup error is never "not current": it aborts the GC (step 7). Victims are the current entries that are not kept. Write the victims, sorted by ID, as tombstones (id, pack) to a pending GC run with RunWriter (the run number comes from next_run under a short store lock; the run is in no MANIFEST yet, so an open after a stop removes it as an orphan, 17-04). Record the plan: pack, action, pending run number, victim count and the raw and stored byte sums of the victims. For a pack to compact: take the store lock, read each kept record and append it to the active pack, insert its new Loc in the memtable (no stats change; a size-limit flush may happen, which is fine because no pack changed yet), release the lock; one pack per lock hold. A pack with nothing to remove gets no pending run.
5. Install (store lock; bounded by the touched_during set and the memtable limit): (a) for each ID in touched_during that is not kept: look it up in the snapshot (an error aborts the GC, step 7); if it is a current Put in a pack that has a plan, drop that plan (the pack is not changed in this GC, and its pending run is removed). (b) Sync the active pack (the copies are durable). (c) If the memtable is not empty, write it to a run as a flush does. (d) One MANIFEST write (write_durable) that adds that run and the pending runs of the kept plans as the newest runs, with hwm = (active pack, length) and the stats after the decrement of the kept plans' victims. This is the durable point. (e) Install the new run list, bump gen, remove the pending runs of the dropped plans, set touched to None. Release the lock. A failure in (b), (c) or (d) sets Inner::failed and returns the error: the MANIFEST is unchanged, so no tombstone is durable and no pack was changed; the pending runs are orphans that the next open removes. Before (d) and in every case (also when the memtable is empty and (c) does no flush), call io.sync_dir() on the index dir after the last pending run is written, so every run that the install MANIFEST lists has a durable directory entry (as the 17-03 flush and 17-06 merge do).
6. Destructive step, only after (d), one pack at a time, without the store lock (a read that took its Loc before the install sees the new gen and looks up again; a reader that already holds a pack handle keeps reading the unlinked file): delete and compact plans: remove the .idx, then the pack, then take the lock briefly to drop its reader and decrement stats.packs. Punch plans: re-derive the remaining current entries of the pack from its .idx with lookups in the live index (the victims now read as removed) and compute the ranges as punch_pack does today; a lookup error skips the punch of this pack (its tombstones are durable; its dead bytes stay until a later GC); else write the .idx with the remaining entries (write_durable), mark the header as punched and sync, then punch (today's error handling). Unused packs are deleted. Then sync_dir. A removal error returns the error (the tombstones are durable; a later GC removes the leftover packs).
7. Abort (any read error in steps 2, 4 or 5a): remove every pending run written by this GC, set touched to None, and return the error; no MANIFEST write happened and no pack changed. The copies of step 4 stay as harmless duplicates with newer, valid Locs. If the error is Corrupt, call request_index_rebuild (17-04) first, so the next writable open rebuilds the index from the packs.
8. Remove the per-pack map of every entry, Index::tombstone and its 17-03 callers if nothing else uses them. Keep GcStats semantics: the counts are those of the kept plans (a dropped plan counts its objects as kept).
9. pub fn last_gc_timing(&self) returns a GcTiming { lock_hold_max, lock_hold_total, wall } (Durations) of the last gc_finish: measure every store-lock hold inside gc_finish. A cfg(test) field gc_pass_hook (a Mutex of an Option of a boxed FnMut taking the ChunkStore and a pass number) is called once at the start of pass 1 and once at the start of pass 2, without the store lock, for the Task 3 tests. The doc comment of gc_finish states the RAM (per pack, plus one pack's entries) and the cost (one sequential pass over the runs, one snapshot lookup per .idx entry of the selected packs).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| index read -> GC decision | a failed or damaged read must not turn into a decision to remove |
| GC decision -> pack delete or punch | a destructive step on disk that a crash can interrupt |
| foreground puts and reads -> a running GC | the passes run without the store lock, so objects can be touched after their pack was planned |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-17-15 | Tampering | gc_finish destructive order | critical | mitigate | one MANIFEST write installs the tombstones and the synced copies before any punch or delete; a failure there fails the store and changes no pack; fault tests for a failed install and a failed removal, with MemIo::crash and reopen |
| T-17-16 | Tampering | put after GC | critical | mitigate | tombstones hide removed entries in runs; merges drop them only with the oldest run; four visibility tests cover deleted, compacted and punched packs, reopen, and merges during and after GC |
