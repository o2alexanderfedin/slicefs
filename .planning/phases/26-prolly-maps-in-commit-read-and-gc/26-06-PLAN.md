<objective>
Plumb the two store-wide tree settings that plan 26-04 left at defaults: the boundary salt of the header (so trees are canonical for a salted store) and the node cache cap as a mount option.

Task 1 passes the salt to every tree writer and to rehash. Task 2 adds `--meta-cache-size` and its docs, and runs the gates.

Decisions this plan implements (26-CONTEXT.md): "Carried from Phase 25: ... optional boundary salt"; "Decided autonomously: [Read path] Node cache size: fixed byte cap, default 64 MiB, mount option to change it, counted in the existing memory caps"; "Claude's Discretion: Node cache cap: a new byte cap of its own (default 64 MiB) with its own mount option".

Discretion choices (record in the SUMMARY): the option name `--meta-cache-size`; `--cache-size` stays a no-op (it has meant nothing since there is no read cache, and giving it a meaning would change old command lines).

Purpose: PMAP-03 (the read path is bounded and configurable; trees are canonical with a salt).
Output: salt plumbing, the option, README, `runs/gate-26-06.log`.
</objective>
