# Phase 26 - Execution rules (binding for every task of every 26-NN plan)

These rules are part of each PLAN.md of this phase (each plan loads this file in its `<context>`). `NN` below is the plan number.

1. **Worktree and branch.** The orchestrator made your worktree `.claude/worktrees/exec-26-NN` on the local branch `exec/26-NN` from `feature/phase-26-prolly-maps-in-commit-read-and-gc`, and merges it back with `--no-ff`. Work and commit only there. Do not make, switch or delete branches or worktrees. One exception: plans 26-01 and 26-13 make the detached worktree of tag `v2.3.0` with `scripts/prolly-bench/pmap07.sh prepare-v230` (it is never committed to). Never push, never tag, run no `gh` command that changes GitHub.
2. **Commits.** Every commit message ends with exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit code only when the tests named in the task pass. Each plan ends with `cargo test --workspace` green (the gate log of rule 9), so the phase branch is green after every merge (CI: Linux Docker with pjdfstest, macOS `cargo test`).
3. **Shell.** zsh. Run `export PATH="$HOME/.cargo/bin:$PATH"` before cargo. End every command with `</dev/null`, put `timeout N` on every command that can wait. No `pkill -f`, `pgrep -f`, `killall`, no `git stash`, no `git checkout` of another branch in a tree where cargo runs.
4. **Scratch.** At the start make one folder with `mktemp -d "${TMPDIR:-/tmp}/p26-NN.XXXXXX"`, write its literal path in your notes, and begin every later command that needs it with `SCR=<that path>;`. Temp files, logs and test stores go under `$SCR`, never in the worktree. Remove `$SCR` at the end.
5. **Long commands** (anything that can run past 9 minutes: `cargo test --workspace`, Docker runs, benchmarks): run them in the background with `timeout`, stdout and stderr to `$SCR/<name>.log`, then append `rc=<exit code>`. Wait for the notification; do not poll in a loop. Read the log; do not start a second run to "check".
6. **One heavy job at a time.** Never run two of `cargo test --workspace`, a Docker run or a benchmark at once. The chunk-store test `retry_tests` has a 200 ms timing check that can fail under load: if it is the only failure, run that test alone once (`cargo test -p chunk-store --test retry_tests`); a pass alone is not a failure. Record it in the SUMMARY.
7. **Docker.** Mounts only in Docker (`scripts/docker-linux-test/run.sh`, OrbStack), never on the macOS host. Use `SLICEFS_TARGET_VOL=slicefs-target-26-NN` so plans do not share build output. Use fresh stores only; never a store from an old Docker volume.
8. **Files.** Edit only the files of `files_modified` (and your SUMMARY). If a change outside them is needed to keep the build or a test green, make the smallest change, and record it in the SUMMARY as a deviation with the reason. Line numbers in plans drift: search by name.
9. **Gate log.** The last task of each plan writes `.planning/phases/26-prolly-maps-in-commit-read-and-gc/runs/gate-26-NN.log`: for each gate one section `== <name>`, the last 40 lines of its output, then `rc=<code>`. Save it through `sed -e "s|$PWD|<repo>|g" -e "s|$HOME|<home>|g" -e "s|$SCR|<scratch>|g"`. A gate log with any `rc=[1-9]` line is not committed as a pass; fix the cause or stop and report.
10. **Public text.** Committed text (code comments, docs, logs, commit messages) has no home or user paths, no host names, and no text about the legal terms of the code. Plain, short English.
11. **Slow test start.** If a test binary starts very slowly, count `ls target/debug/deps | wc -l`; above 200,000 files run `cargo clean` in your worktree before you suspect a hang.
12. **Locks.** The lock order at the top of `crates/metadata/src/store.rs` is binding; every new lock goes into that comment. No shard or overlay lock is held across a node read, a node put, a hash or a sync. New locks use `chunk_store::sync::{Mutex, Rank}`. A metadata-store lock that is timed reuses the `Site` of its map (`Site::InodeData`, `DirData`, `ManifestData`, `XattrData`, `Refcounts`); no new `Site` is added unless the plan says so. Any plan that changes a lock also runs `cargo test -p slicefs-cli --features lock-stats --test lock_stats_report` (feature-gated, so the workspace run does not cover it).
13. **Choices.** Reversible choices: decide and record them in the SUMMARY under "Decisions". The on-disk format items are settled by the owner (26-CONTEXT.md, "On-disk format"): no checkpoint for them. Cite a decision of 26-CONTEXT.md by its section and words (the file has no D-NN numbers).
14. **No store backward compatibility.** Do not add a read path for flat maps or for stores of earlier builds of this phase; a store made by an earlier plan of this phase is not read by a later one (tests make fresh stores).
