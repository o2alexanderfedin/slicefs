<objective>
Make the fs layer keep the memory bound of the xattr tree of plan 26-15: getxattr and listxattr answer size queries without reading values or building lists, refuse a too-small buffer before reading, read the macOS resource fork by position, and stream the name list into the reply. The vendored fuser passes the getxattr position it drops today. A Docker mount smoke sends large and many xattrs through the kernel.

Task 1 changes the fs layer and the handlers. Task 2 adds the fuser patch and passes the position. Task 3 adds the Docker steps and runs the gates.

Decisions this plan implements (26-CONTEXT.md "Xattrs by name (owner, 2026-11-27, replaces the per-set encoding)"): "listxattr is a range scan over the inode's prefix, streamed node by node; a read with an offset (macOS resource fork) reads only the chunks it needs. Memory per xattr operation is bounded by one request, not by the size or count of the xattr set"; and "Carried from Phase 25: ... FSKit is the only macOS backend; mounts only in Docker for tests".

Discretion choices (record in the SUMMARY): positioned reads only for `com.apple.ResourceFork` (as on macOS, where only the resource fork uses the position); a too-long name gives ERANGE (the Linux errno); the getxattr position is a local fuser patch (upstream fuser does not pass it), recorded as patch 4. Not in this plan: setxattr with a position (writes of the resource fork in parts); the owner decision is about reads, and the callback keeps ignoring that position as today (named in the SUMMARY as an open item).

Purpose: PMAP-03 (criterion 1, xattrs through the mount) with the owner's memory rule at the request boundary.
Output: the fs and handler changes, fuser patch 4, Docker steps, `runs/gate-26-16.log`.
</objective>
