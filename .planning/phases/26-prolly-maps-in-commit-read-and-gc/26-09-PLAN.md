<objective>
Convert the last map: directory entries by name in `dir_data`, with `.` and `..` as stored entries, readdir as a range scan, and an emptiness check that reads at most a few entries. The fs layer stops listing a directory to test emptiness.

Task 1 converts the store side (encoding, overlay, readdir merge, link, unlink, directories, delete, GC, rehash) and removes `directory.rs`. Task 2 changes the fs-layer callers and adds the directory tests, then runs the gates.

Decisions this plan implements (26-CONTEXT.md "On-disk format"): "Directory entries are stored by name in the `dir_data` tree: key = directory ino (8 bytes, big endian) || entry name; value = child ino + file type ... readdir is a range scan from the directory prefix; the per-directory list object goes away"; "`.` and `..` are stored as entries ... the entry's file type comes from the child's inode mode; readdir order is name byte order"; "Scope: ... paged readdir (resume from a name cookie) is a stretch item, not required"; and Claude's Discretion "how hard links appear in `dir_data` (each name is its own entry pointing to the same ino)".

Discretion choices (record in the SUMMARY): the dir overlay is `MapTree<DirKey, DirValue>` sharded by the directory ino (per-name pending edits, so one directory with many new names still flushes at `TREE_FLUSH`); shards timed `Site::DirLive`, root `Site::DirData`; the type byte equals the Linux `DT_*` number (`(mode & S_IFMT) >> 12`); paged readdir is not built (stretch item; the API keeps returning a `Vec`).

Purpose: PMAP-03 (all five maps are trees after this plan).
Output: `dirent.rs`, the dir tree, fs callers, tests, `runs/gate-26-09.log`.
</objective>
