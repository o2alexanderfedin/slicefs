<objective>
Prove the scale claims of the roadmap on real trees: the one-change commit at two store sizes (criterion 2), the bounded memory of the GC mark on a large map (criterion 3), GC with snapshots that share nodes, the online GC path, and the measured cost of walking every snapshot root.

Task 1 adds the bulk loader and the five-tree counter and load tests. Task 2 adds the memory test, the snapshot and online GC tests, records the snapshot cost and runs the gates.

Decisions this plan implements (26-CONTEXT.md): "Specific Ideas: Success criterion 2 uses a counter test at two store sizes"; "[GC] a stack of one node path per tree ... a test caps peak memory on a large map"; "Scope: ... the GC mark walks every snapshot root in full (N snapshots cost N times the node count) and this cost is accepted and recorded"; "Design target 1B+ inodes; counts from internal entry counts or the root record".

Discretion choices (record in the SUMMARY): sizes 10,000 / 300,000 (counter) and 50,000 / 200,000 (memory) so debug builds stay within the test time budget; a `#[ignore]` 1,000,000-file counter variant for release runs by hand; the absolute memory cap is 2 x the measured 50,000-file peak, written in the test with the measured number.

Purpose: PMAP-03 criterion 2, PMAP-06 criterion 3.
Output: `testkit.rs`, tests, the doc record, `runs/gate-26-11.log`.
</objective>
