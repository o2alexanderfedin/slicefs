<objective>
Make each commit report its tree work, and prove ROADMAP criterion 2 on the manifest tree before four more maps copy the pattern: a one-change commit reads and writes a number of nodes bounded by the tree height, at two store sizes, and a commit with no change keeps the root. The bench `whole` rows and the PMAP-07 report read the counters (check A of the PMAP-07 rule uses nodes read and written).

This plan was split from plan 26-04 to keep each plan inside the context budget. Plan 26-04 left the bench `whole` mode reading a tree field with `serialized_bytes` over the flat fields only; this plan adds the tree bytes and the node counts.

Task 1 adds `CommitStats` and the counter tests. Task 2 wires the bench and the report and runs the gates.

Decisions this plan implements (26-CONTEXT.md): "Specific Ideas: Success criterion 2 uses a counter test at two store sizes: nodes read and written for a one-change commit grow at most with the tree height"; "PMAP-07 target (owner, 2026-11-27): the 1/5 target applies to the pre-sync work of a one-change commit ... (CPU time and nodes read and written, sync excluded)"; "[Commit] per tree, sort the dirty keys, one apply batch, write new nodes, then the root record".

Discretion choices (record in the SUMMARY): sizes 2,000 and 40,000 files (two heights in a debug build within the test time budget); `bytes_written` and `nodes_written` include the root record; the stats lock is a leaf lock.

Purpose: the counters are the measure of PMAP-03 and the input of PMAP-07 check A; plans 26-07 to 26-09 push one `TreeStats` per converted tree by the same pattern, and plan 26-11 asserts on all five.
Output: `CommitStats`, `commit_counter_tests.rs`, the filled report module, bench counter fields, `runs/gate-26-14.log`.
</objective>
