<objective>
Pre-register the PMAP-07 rule before any measurement, extend the commit benchmark so one file builds in this tree and in tag `v2.3.0`, and measure an early flat baseline of `v2.3.0` (research assumption A5: is the target reachable at 1,000,000 inodes).

Task 1 writes the rule file and the decision script and commits them first. Task 2 extends `commit_bench.rs`, adds the two report modules and the Docker runner. Task 3 makes the `v2.3.0` worktree, runs the flat baseline at 100,000 and 1,000,000 files, and runs the gates.

Decisions this plan implements (26-CONTEXT.md): "PMAP-07 target" (1/5 for the pre-sync work: CPU and nodes, sync excluded; total wall time lower than flat; both recorded; rule committed before any measurement); "Claude's Discretion: PMAP-07 rubric reading" (Boost not `drop`); "Decided autonomously: [Bench] ... flat baseline with a v2.3.0 binary built in a separate worktree".

Discretion choices (record in the SUMMARY): the decision platform is Linux in Docker on disk-backed storage; thread CPU is measured with `clock_gettime(CLOCK_THREAD_CPUTIME_ID)` around `commit()`; the CPU of the sync system calls stays inside that number in both builds (it cannot be split out of `v2.3.0` without changing it), which biases against prolly, so a pass is conservative.

This plan is alone in wave 1 so that no other heavy job runs beside the early baseline (rule 6 of 26-EXEC-RULES.md). It changes no product code.

Purpose: PMAP-07 (ROADMAP criterion 5) is decided by a rule that existed before the numbers.
Output: the rule file, the script, the runner, the extended bench, `runs/pmap07-early-flat.log`, `runs/gate-26-01.log`.
</objective>
