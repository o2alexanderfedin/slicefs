<objective>
Convert the inode map: the inode record goes inline into `inode_data` leaves, and the inode cache with dirty flags becomes the tree overlay of plan 26-04 (the node cache now holds the clean data).

Task 1 converts the inode map and its read, modify, create-at and delete paths, with the ported race tests. Task 2 ports GC and rehash for the tree and runs the gates.

Decisions this plan implements (26-CONTEXT.md "On-disk format"): "the inode record goes inline in `inode_data`"; "inode values carry no tag byte (always the inline record)"; "This removes about one chunk-index entry and one read per inode lookup"; and "Carried from Phase 25: counts from internal entry counts or the root record".

Discretion choices (record in the SUMMARY): replace `inode_live` by `MapTree<u64, InodeMeta>` (one overlay scheme for every map; the clean-inode cache is the node cache); the overlay shards stay timed `Site::InodeLive` and the root lock `Site::InodeData` (the lock-stats report expects both labels); `INODE_CACHE_MAX` goes.

Purpose: PMAP-03 (no inode map in RAM, inode reads on demand).
Output: the inode tree, tests, `runs/gate-26-08.log`.
</objective>
