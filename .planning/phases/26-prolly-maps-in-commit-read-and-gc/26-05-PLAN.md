<objective>
Prove the commit protocol of plan 26-04 on the manifest tree before four more maps depend on it: fault points at every write and sync step, requeue of every overlay on failure, race tests, the online GC order, and crash windows that replay to a consistent tree.

Task 1 adds the fault points, the full requeue and the race and GC-order tests. Task 2 adds the crash matrix with a tree validator and extends the write-log crash windows, then runs the gates.

Decisions this plan implements (26-CONTEXT.md): "Decided autonomously: [Crash tests] test-only fault point after each node write and each sync step, then replay and check the tree"; "[Commit] per tree ... then the root record with the five new roots"; "Carried from Phase 25: Online GC stays mandatory".

Discretion choice (record in the SUMMARY): the fault-point list above. A crash between two node puts of one commit is covered by `MemIo::crash()` at AfterApply and BeforeSync: no sync runs between the puts of a commit, so the crash drops all of them (and a small `pack_limit` covers packs that seal mid-commit).

Purpose: PMAP-08 and the concurrency half of PMAP-03 on one tree; plan 26-12 widens the matrix to all five trees.
Output: fault points, tests, `runs/gate-26-05.log`.
</objective>

## Flagged assumptions (edge probe)

- PMAP-08 (category `unclassified`, unresolved): a torn record inside a pack file (a crash in the middle of one write) is handled by the chunk store's recovery at open, not by a fault point of this phase. `MemIo::crash()` keeps only synced bytes, which covers a crash between any two node puts. If the owner wants torn-record cases per node put, that is a chunk-store test, not a metadata one.
