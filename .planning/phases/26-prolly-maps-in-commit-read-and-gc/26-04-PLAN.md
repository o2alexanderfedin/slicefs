The tracer of the phase: the `manifest_data` map becomes a prolly tree through every layer the phase touches (overlay, working root, flush, commit, root record, load, GC mark, rehash, bench), with real end-to-end tests. The other four maps stay flat in this plan; plans 26-07 to 26-09 copy this pattern for them. Plan 26-14 (next wave) adds the commit counters, the counter test of ROADMAP criterion 2 and their users in the bench and the PMAP-07 report.

Task 1 (tracer) builds `pmap.rs` and wires the manifest tree through store, load and the GC mark, with the end-to-end test. Task 2 ports rehash. Task 3 makes the bench `whole` mode read a tree field, runs the gates and commits. Rehash and the bench are in this plan because the workspace is red without them once the manifest field is a tree (rule 2).

Decisions this plan implements (26-CONTEXT.md): "On-disk format: ... `manifest_data` values stay 33-byte `ObjectKey`s"; "Decided autonomously: [Read path] read on demand ... bounded node cache; dirty entries stay in memory until commit; no whole map in RAM"; "[Commit] per tree, sort the dirty keys, one apply batch, write new nodes, then the root record"; "[Commit] ... also fix IN-01"; "[GC] a stack of one node path per tree"; "Scope: rehash is ported to rebuild the trees"; "Carried from Phase 25: ... 197-byte root record with five map keys".

Discretion choices (record in the SUMMARY): overlay flush at `TREE_FLUSH` dirty entries per tree (16,384; 8 under `cfg(test)`); trees reuse the lock `Site` of their map; the default node cache of a `StoreIo` is 64 MiB (26-CONTEXT.md "Node cache size") until plan 26-06 adds the option; `manifest_digest` keeps its `Option` signature and logs a read error (a lost release only leaks a refcount; GC is mark-based).

Purpose: retire the riskiest part (the working-root/overlay protocol) on one map before four more depend on it.
Output: `pmap.rs`, the manifest tree, `Ref::Tree`, rehash of trees, the bench reading a tree field, tests, `runs/gate-26-04.log`.

3. `pmap.rs` (copy the ticket scheme of `Live<T>`; RESEARCH Pattern 1 and 2). Module doc states the protocol, which later plans follow:
   - Read: lock the key's overlay shard; a pending edit (`Some(v)` or a delete) answers; else unlock, then read the working root, then `prolly::get_in`. Never read the root first and the overlay after.
   - Write: overlay only (`put` marks dirty and drops an in-flight ticket); no node I/O under a shard lock.
   - Read-modify-write: `read_with_gen` gives the value and the tree `gen` read before the tree read; the caller relocks, rechecks the overlay and `gen`, and retries on a change (no lost update; replaces the digest compare of today).
   - Flush (hot path, called with no shard lock held, when `dirty() >= TREE_FLUSH`): `apply_lock.try_lock()`, else skip; take dirty (tickets), sort by encoded key, `apply_in` on the working root, `install` (root, then `gen += 1`), then `settle` (an entry leaves the overlay only if its ticket is current). On an error, requeue the taken entries and keep the error so the next commit fails (as `kept` does).
   - Commit: `begin_commit` takes `apply_lock` only to wait out a running flush and set `prepared = true`, then releases it before the write-log cut (the cut takes cell and short-map locks of the file system, which rank below `Rank::Store`; holding a Store lock there panics the debug rank checker). A flush takes `apply_lock` with `try_lock` and skips when it is busy or `prepared` is set, so no flush applies after the cut. `begin_commit` then cuts, takes dirty and in-flight entries with new tickets and reads the cut root. `finish_commit` applies the batch to the cut root (`apply_batch` returns the new root and the `prolly::ApplyStats` of the apply; plan 26-14 reports them), writes the root record, then under `apply_lock` installs, settles and clears `prepared`. Failure before install (and `Drop` of an unfinished commit): requeue every overlay and clear `prepared`; after install: nothing to requeue (the state is in the working root; the next commit writes it again).
   - Map `prolly::Error` to `MetaError::Corrupted("<map> tree: ...")`, never unwrap.
