# Phase 21.1 Plan 02: The header check at every open point Summary

**Every command that opens a store now checks the header first, before any write. A store with data and no header, a format other than 7, or a bad header line is refused with its own message. An unknown ro_compat flag refuses gc, seed, snapshot create and switch, and `mount --hash` and `mount --auto-snapshot`. stats, scrub and snapshot list still run. ## Deviations from Plan

### New side effect: the orchestrator must decide (not fixed; no blocker)

- **A command that writes, on a path with no store, now makes the directory and FORMAT.** Seen for `slicefs gc <path>` and `slicefs snapshot create <path>` (the binary run on a missing path). `snapshot switch` has the same first statement, but it was not run. These commands call `check(Want::Write)` first, so a missing path is a new store and gets FORMAT. Then the command fails as before ("failed to load segments: ... No such file or directory"). Before this plan, these commands did not write anything to a missing path. The plan's must-have ("a write command writes the header durably first") allows this. A later fix can be small: those three commands can refuse a path with no `segments/` before the check. `stats`, `scrub`, `snapshot list` and `mount` write nothing (Read or Mount).

### Decisions inside the plan (reversible)

1. **`write_hasher` does not call `check`.** It reads and parses the header only (no open decision). `open` and `open_read_only` take the hash from the header that their own check returns, so they read the file once.
2. **The `select_hash` print line.** `check(Want::Write)` now writes the header of a new store before the hash compare. To keep the old output, the line "New objects use hash ..." is printed only when FORMAT existed before the check.
   (Review fix WR-03: that guard was always true in `seed`. Now `content::check_write` does the header step of `seed`: it reads the hash name first, and a new store gets the `--hash` hash in its first header write, through `header::check_with`. Thus no line is printed, and the guard is gone. The seed gate range now has `content::check_write(`, not `header::check(`.)
3. **`header::write_text` is private.** `select_hash` now uses `write_header`, so no code outside header.rs writes header text.
4. **`run_seed` keeps its `create_dir_all(store_path)`** after the check. It does nothing now, but it is the end of the awk range of the seed gate.
   (Review fix WR-04: the line is removed. The awk range of the seed gate now ends at the next `create_dir_all`, the one of `segments/`. After review fix WR-03 the range has `content::check_write(`, not `header::check(`, so the gate prints 0; see decision 2.)

### Behavior to note

- **`seed --hash md5 <new dir>`** writes the header of the new store, then refuses the unknown hash name (the check is the first statement, before `select_hash`). (Review fix WR-03: the name is now read first, so this makes nothing.)

## Notes for plan 21.1-03

- `stats.rs` calls `crate::header::check(store_path, crate::header::Want::Read)?;` after its legacy and `segments/` checks, and drops the result. Plan 03 can keep the returned `Opened`: `header: None` is an empty store with no header (show the format as `none`, JSON `null`); `Some(h)` has `h.format` and `h.flags()` (`Flag { class, name, release }`, `Class::word()` gives `compat`, `ro_compat`, `incompat`). `access` is `ReadOnly(flag)` for an unknown ro_compat flag.
- `an_empty_store_read_writes_nothing` (store_header_tests.rs) already runs `run_stats` on an empty `segments/` with no FORMAT. Plan 03 can add the `none` output check there or in stats.rs.
- For the Docker ro-compat EROFS check: `mount` on a store with `ro_compat <name> r-test` appended prints the M6 line (`Mounting read-only: ...`) and mounts with FUSE `RO`. `--hash` and `--auto-snapshot` are refused (M11, M12), so the script must not pass them. A `mount.lock` left by an earlier crash or a pending write log refuses the mount (M8, M7): unmount the seeded store cleanly first, or use a store made by `seed` only.
- `grep -rn 'FORMAT\|older SliceFS\|vt0\|slicefs-store' scripts/docker-linux-test/` finds nothing: no script edits the header or matches an old message text.
- The Linux form of `start` (`backend: Option<()>`) is still compiled only by CI or Docker. This plan added code to `start` that does not depend on the backend.
- Message functions in header.rs (for the doc of plan 04): `msg_no_header` (M1), `msg_older` (M2), `msg_newer` (M3), `msg_unknown_format` (M4), `msg_incompat` (M5), `msg_mount_read_only` (M6), `msg_ro_write` (M6w), `msg_log_pending` (M7), `msg_lock_present` (M8), `msg_bad_line` (M9, reasons `bad feature flag line`, `the feature {name} is listed twice`, `two hash lines`, `unknown setting`), `msg_too_large` (M10), `msg_ro_hash` (M11), `msg_ro_auto_snapshot` (M12), `msg_not_text`.
