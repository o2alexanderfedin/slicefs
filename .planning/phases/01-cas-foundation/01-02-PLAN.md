  <files>
    crates/cas-local/src/mem_block_store.rs

  <behavior>
    - put() then get() returns same data (round-trip)
    - put() same hash twice is idempotent (no error, no duplicate storage)
    - get() on non-existent hash returns CasError::NotFound
    - exists() returns true after put(), false before
    - delete() removes block; subsequent get() returns NotFound
    - delete() on non-existent hash is idempotent (no error)
    - Integrity check: put() verifies hash matches data at write time; mismatched hash returns IntegrityFailure
    - Integrity check on read (verify_on_read=true): simulated corruption detected — since MemBlockStore uses HashMap there is no real "corruption", but we test that the verification code path runs by confirming correct behavior
    - verify_on_read=false skips integrity check
    - Thread safety: concurrent put/get from multiple threads does not panic
    - Property test: for any random data, hash-then-put-then-get round-trips correctly
  </behavior>
  <action>
Implement `MemBlockStore` in `mem_block_store.rs` following the research code example:
- Struct with `store: RwLock<HashMap<ChunkHash, Vec<u8>>>`, `config: BlockStoreConfig`, `hasher: Box<dyn ContentHasher>`.
- Constructor `new(config: BlockStoreConfig, hasher: Box<dyn ContentHasher>)`.
- `put()`: compute hash of data via `self.hasher.hash(data)`, compare to provided hash. If mismatch, return `CasError::IntegrityFailure`. If hash already exists, check stored bytes match (if different, return `CasError::HashCollision`). Otherwise insert.
- `get()`: lookup in HashMap. If `verify_on_read`, re-hash retrieved bytes and compare. Return data or error.
- `exists()`: read lock, `contains_key`.
- `delete()`: write lock, `remove`. Idempotent.

Write `#[cfg(test)]` module with all behavior tests. Use `Blake3Hasher` from the sibling module for the hasher dependency. Use `proptest` for the round-trip property test. For thread safety test, use `std::thread::scope` with 4 threads doing concurrent put/get.
