Add the following test functions to streaming_tests.rs. Each test uses the existing `fresh_fs()` helper. Group under a comment block `// === Phase 11: Non-sequential write handling (STRM-02) ===`.

**test_nonseq_fallback_on_gap** (STRM-02a):
- Create file, write 5 bytes at offset 0, then write 5 bytes at offset 20 (gap).
- Release. Read back full content.
- Assert: bytes 0..5 are original data, bytes 5..20 are zeros, bytes 20..25 are second write data.
- Total size should be 25.

**test_fallback_materializes_streaming_content** (STRM-02b):
- Create file, write 100 bytes sequentially at offset 0.
- Write 10 bytes at offset 50 (triggers fallback, overlaps existing streaming content).
- Release. Read back.
- Assert: bytes 0..50 are original, bytes 50..60 are second write, bytes 60..100 are original.

**test_pwrite_existing_file_preserves_content** (STRM-02d):
- Create file, write 100 bytes at offset 0, release.
- Re-open same file for writing (using test_open or by creating a new fh -- check how streaming_tests.rs handles this; may need to call the FUSE open path or use a helper).
- NOTE: If there is no test_open helper, implement the test by: create file, write+release, then create a second file handle on the same inode. The simplest approach: after release, the committed content is in CAS. Create a new test that writes at non-zero offset to a NEW file (byte_count=0 path) and asserts zeros fill the gap. The existing-file-reopen test may need a test_open helper. If no helper exists, skip this variant and note it in the summary.
- Write 5 bytes at offset 50.
- Release. Read back.
- Assert: the gap 0..50 is zero-filled (since new file handle starts with byte_count=0 and empty State, and no committed manifest exists for the new handle scenario). OR if testing actual reopen: bytes 0..50 are original, bytes 50..55 are new data, bytes 55..100 are original.

**test_read_in_buffered_mode** (STRM-02e):
- Create file, write 10 bytes at offset 0 (sequential), write 5 bytes at offset 20 (non-sequential, triggers fallback).
- DO NOT release. Read back via test_read.
- Assert: bytes 0..10 are first write, 10..20 are zeros, 20..25 are second write.

**test_fsync_in_buffered_mode** (STRM-02f):
- Create file, write 10 bytes at offset 0, write 5 bytes at offset 20 (triggers fallback).
- Call test_fsync. Then write 5 more bytes at offset 30.
- Release. Read back.
- Assert: correct content across all offsets. fsync mid-stream did not corrupt.

**test_truncate_in_buffered_mode** (STRM-02g):
- Create file, write 10 bytes at offset 0, write 5 bytes at offset 20 (triggers fallback).
- Call test_setattr_size(ino, Some(fh), 15) to truncate.
- Release. Read back.
- Assert: content is 15 bytes (original 10 + 5 zeros, the non-sequential part at 20 is truncated away).

**test_out_of_order_writes** (STRM-02i):
- Create file. Write chunks in reverse order simulating writeback_cache reordering:
  - write(fh, 30, b"CCCC") -- offset 30, not 0, immediately triggers fallback
  - write(fh, 0, b"AAAA")
  - write(fh, 15, b"BBBB")
- Release. Read back.
- Assert: bytes 0..4 = "AAAA", 4..15 = zeros, 15..19 = "BBBB", 19..30 = zeros, 30..34 = "CCCC".

**test_overlapping_writes** (STRM-02k):
- Create file, write 10 bytes (b"AAAAAAAAAA") at offset 0.
- Write 5 bytes (b"BBBBB") at offset 3 (triggers fallback, overlaps).
- Release. Read back.
- Assert: bytes 0..3 = "AAA", 3..8 = "BBBBB", 8..10 = "AA".

**test_mixed_seq_then_nonseq** (STRM-02l):
- Create file, write 4 sequential chunks of 10 bytes each (offsets 0, 10, 20, 30 -- all sequential).
- Then write 5 bytes at offset 15 (non-sequential, triggers fallback).
- Release. Read back.
- Assert: first 15 bytes from original sequential writes, bytes 15..20 from the non-sequential write, bytes 20..40 from the original sequential writes.

**test_sequential_stays_streaming** (STRM-02h regression):
- Create file, write 5 sequential chunks of 100 bytes each (offsets 0, 100, 200, 300, 400).
- Release. Read back. Assert all 500 bytes correct.
- This confirms sequential writes don't falsely trigger fallback.
