<objective>
Tracer of Phase 21: one request kind (getattr) goes the whole new path, end to end: the `--workers` option, the worker count resolution in `run_mount`, the `Pool` in `MountedFs`, the hand-off from the fuser reader, the gate inside `serve` on the worker, the reply after the gate is released, and the drain plus join at the start of `destroy`. A Docker Linux smoke mount with 4 workers proves the slice. The other callbacks stay inline on the reader in this plan (plan 21-02 moves them).

Decisions that this plan implements (labels of 21-CONTEXT.md):
- [Worker count option]: `--workers N`, Linux default clamp(available_parallelism / 2, 1, 8), macOS default 1, reject 0, no upper bound on an explicit value, 1 runs inline (costly: public option; the name and the defaults are locked by the owner).
- [Pool]: one fuser reader thread plus a SliceFS pool; a queue bounded so memory stays bounded.
- [Shutdown]: drain the queue and join the workers (each wait has a time limit), then `destroy()` work (`shutdown`: flusher stop, then the gate).
- [Locks]: the handler returns its result; the worker sends the reply after all guards are dropped; debug assert that no ranked lock is held at the reply.
- [Waits]: every new wait has a time limit; no wait while a ranked lock is held.
- Claude's discretion (this plan decides): queue depth max(2 x N, 4) slots and 8 MiB of payload, one oversize job admitted when the queue is empty; thread names `slicefs-worker-<k>`; the hand-off is a boxed closure; the CPU count comes from `std::thread::available_parallelism`, read once at mount.

Purpose: prove the architecture on one path before 30 callbacks depend on it.
Output: `pool.rs`, the option, the wiring, getattr through the pool, the drain, the tests, and one smoke log.
</objective>
