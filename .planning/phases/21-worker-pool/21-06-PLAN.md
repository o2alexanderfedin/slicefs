<objective>
Measure the [Step limit] of plan 21-05 against the hard bar: S7 VmHWM at or under CAP_MIB 320 at 1, 2, 4 and 8 writers, with 16 writers recorded, the research CAP(N) rule, and the 64 MiB rise rule as a signal for the owner.

Decisions that this plan implements (labels of 21-CONTEXT.md):
- [Step limit], with the orchestrator reading of the user answer (2026-11-23, in 21-CONTEXT.md): "the 320 MiB cap is a hard bar at every writer/worker count the default can give: 1, 2, 4 and 8 ... A miss at any of these keeps POOL-05 (and the [Step limit] item) open ... At 16 (above the default cap of 8) a miss is recorded and reported to the owner, and does not block. The R3 64 MiB rise rule: keep as a report-to-owner signal only."
- [Bench]: peak memory per worker count; this plan gives the in-process part. Research Q7 and Open Question 8: `CAP(N) = Pm(N) + F + R`.

The S7 process itself holds memory per writer (a 1 MiB block-version model, a 1 MiB write buffer, 1 MiB check reads, a thread stack and its allocator arena). The notes give that term, so a rise of the daemon part can be told from a rise of the test part. The bar still applies to the measured VmHWM as it is.

Purpose: evidence that peak memory does not grow with the number of writers.
Output: one Docker log and its notes.
</objective>

Pass rule (stated here, before the runs; do not change it after):
- Runs: S7_FLUSHER=1, default sizes (1024 MiB files, 128 MiB mix, a commit every 30 s), in this order: three rounds of 4, 8, 16, 1, 2, 4 writers, then one more 4. So 4 writers run 7 times, and 1, 2, 8 and 16 run 3 times each (19 runs); the counts are spread over the set (host load was 13-19 in earlier runs).
- R1, the hard bar: every run at 1, 2, 4 and 8 writers passes its model check and has VmHWM <= 320 (the harness asserts it at these counts).
- R2, report only: every run at 16 writers has VmHWM <= 320.
- R3, report only: Pm(8) - Pm(4) <= 64 and Pm(16) - Pm(4) <= 64, where Pm(N) is the largest VmHWM at N writers.
- CAP(N) for N in 4, 8, 16: Pm(N) + F + R, rounded up to a multiple of 8, with F = 8 and R = the largest of 16, ceil(Pm(N) / 10) and 2 x Spread(N), Spread(N) = the largest minus the smallest VmHWM at N. Recorded only; `CAP_MIB` stays 320.
- Branches:
  - In every case: do not change `CAP_MIB`, `SAVE_STEPS` or `SLOT_WAIT` to fit a run, and run the whole set (a cap miss does not end the set, so every count has its numbers).

  - A miss of R1: one more run at the writer count with the highest miss, with `-e MALLOC_ARENA_MAX=2`, into `runs/s7-step-limit-arena.log` (the allocator part, as in Phase 20); the notes have `R1=miss` and the cause; finish the plan.   - A miss of R2 or R3 (with R1 passed): the notes have `R2=miss` or `R3=miss` and the cause (the before and after at the same writer count, the harness term); finish the plan; the SUMMARY lists it as an owner report. No extra run is needed.
