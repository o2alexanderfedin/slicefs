<objective>
Move every request callback to the pattern of the 21-01 tracer: the reader copies the arguments it must, hands a job to `run`, the job takes the gate only inside `serve`, and the reply is sent after `serve` returned. This is the fix of a gap that research found in the code today, also with one thread: every callback sends its reply while the commit-gate guard is still alive (research Q5, "Pitfall 1").

Decisions that this plan implements (labels of 21-CONTEXT.md):
- [Locks]: "Each handler returns its reply data; the worker sends the reply after the handler returns and all guards are dropped. In debug builds, assert no ranked lock is held at the reply."
- [Order]: no global order; DESTROY, INTERRUPT, FORGET and the operations that SliceFS does not override stay inside fuser on the reader (research Q2: "Every callback that `MountedFs` overrides, except `init` and `destroy`, goes through the pool"); no per-inode queue on Linux.
- [Worker count option]: `--workers 1` runs the handler inline on the reader thread, as today (no copy of the write payload).
- [Bench] support (research Open Question 6, Claude's discretion): a read-once switch `SLICEFS_FUSE_TRACE=0` for the per-request trace lines, default on, so the logs do not change; the bench of plan 21-08 uses it.

Purpose: ROADMAP criterion 2 ("replies are sent after all locks are released") for every request, and the whole request surface on the pool.
Output: the restructured callbacks, `tests/reply_after_locks.rs`, a `serve` unit test, two Docker logs.
</objective>

- fuse_callbacks.rs overrides 31 request callbacks: getattr lookup readdir read open opendir release releasedir flush fsyncdir fsync statfs access getxattr listxattr setxattr removexattr write create mkdir mknod symlink readlink link unlink rmdir rename setattr getlk setlk fallocate. After 21-01, getattr uses `run` and `serve`; the other 30 still take `let _op = self.gate_shared();` and reply inside that hold. Non-comment `gate_shared(` lines: 32 after 21-01 (init, serve and 30 callbacks).
- Only create, mkdir, mknod and symlink read the request header (`req.uid()`, `req.gid()`; lines 474-576 at 9157444). `Request` has no `Clone`: copy the `u32` values before the hand-off.
- Borrowed arguments that die when the callback returns: `name: &OsStr` (and `newname`, `link_name`, `target`), `data: &[u8]` of `write`, `value: &[u8]` of `setxattr`. The pool path copies them (`to_os_string`, `to_vec`); the weight of a job is the payload bytes it owns (write data, setxattr value), else 0.
- `write` (line 423 at 9157444) calls `self.throttle_write()` before the gate (Phase 20 rule: no lock while it waits), times the throttle, the gate wait and the handler, and prints a `[slow-write]` line when the sum is 50 ms or more. Keep the throttle before `serve` and keep the slow-write line (it is not a trace line).
- The `run` helper takes `impl FnOnce() + Send + 'static`, so the inline write with a borrowed payload cannot use it. `write` matches on the pool itself: no pool, call a `write_job` with the borrowed `data` on this thread; a pool, copy `data` and submit a job that calls `write_job` with the copy. `setxattr` can copy in both paths (small values).
- 100 lines of fuse_callbacks.rs contain `[FUSE]` (the ENTRY and EXIT trace lines, and the init and destroy lines).
- `crates/slicefs-cli/tests/no_take_out.rs` is the model of a source test (`include_str!`, walk back to the nearest `fn` header).
- `chunk_store::sync::rank::enter(Rank::Short)` returns a marker that pops the rank on drop: a closure given to `serve` that returns such a marker keeps a ranked entry alive past the gate drop.
- Docker: the method of plan 21-01 (context). In the container, `available_parallelism` is 32 (no quota), so a mount with no `--workers` runs 8 workers (16 clamped to 8): the unchanged `verify-phases.sh` already runs on the pool path.
