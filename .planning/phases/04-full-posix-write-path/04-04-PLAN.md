Add an `all_inode_sizes(&self) -> Vec<(u64, u64)>` method that returns `(ino, size)` pairs by iterating inode_data keys and loading each inode. This is O(N) but correct for Phase 4. Alternatively, add a simpler `total_logical_bytes(&self) -> u64` that walks all inodes and sums sizes.

Implementation choice (Claude's discretion): Use the running counter approach for better performance. Add `logical_bytes: Mutex<u64>` field to DictMetadataStore. **statfs() implementation:**
Replace hardcoded values:
```rust
fn statfs(&self, _req: &Request, _ino: INodeNo, reply: ReplyStatfs) {
    let logical = self.meta.logical_bytes();
    let physical_entries = {
        let dict = self.dict.lock().unwrap();
        dict.len() as u64
    };
    let physical = physical_entries * 92;
    let bsize: u32 = 4096;
    let blocks = logical / bsize as u64 + 1;
    let bfree = u64::MAX / 2; // effectively unlimited for dedup fs
    let bavail = bfree;
    let files = 1_000_000u64; // max inodes (generous)
    let ffree = files - (logical / (bsize as u64 + 1)); // rough estimate
    reply.statfs(blocks, bfree, bavail, files, ffree, bsize, 255, 0);
}
```

**POSIX locking stubs (POSIX-12):**
If `getlk` and `setlk` methods exist in the fuser Filesystem trait, implement them to return `Errno::ENOSYS`. When FUSE receives ENOSYS for lock operations, the Linux kernel handles local file locking internally. This is the standard approach for FUSE filesystems and pjdfstest skips lock tests that get ENOSYS.

Check if fuser 0.17 defines `getlk`/`setlk` in the Filesystem trait. If they have default implementations already returning ENOSYS, no action needed. If not, add explicit stubs.

Write tests in `crates/slicefs-cli/tests/statfs_tests.rs`.

  <action>
Create a comprehensive integration test file that exercises all Phase 4 POSIX operations through the `DictMetadataStore` + `SliceFsFilesystem` pipeline. These tests simulate what pjdfstest would check, but run entirely in-process without a FUSE mount.

Test categories (map to pjdfstest categories):

**1. File operations (POSIX-01):**
- Create file, write content, close, read back -- content matches
- Create file, write at offset, close, read full -- zero padding correct
- Create file, close without writing -- empty file exists with size 0
- Delete file -- lookup returns ENOENT
- Create file in subdirectory -- nested paths work

**2. Directory operations (POSIX-02):**
- mkdir creates directory with . and ..
- mkdir in subdirectory (nested mkdir)
- rmdir on empty directory succeeds
- rmdir on non-empty directory returns ENOTEMPTY
- rmdir on non-directory returns ENOTDIR

**3. Rename (POSIX-03):**
- Rename file within same directory
- Rename file across directories
- Rename file overwrites existing target
- Rename directory within same parent
- Editor pattern: create temp, write, rename over original

**4. Symlinks (POSIX-04):**
- Create symlink, readlink returns target
- Symlink to non-existent target (dangling symlink -- POSIX allows this)
- Symlink with long target path (>256 chars)

**5. Hard links (POSIX-05):**
- Create hard link, nlinks == 2
- Unlink one hard link, nlinks == 1, file still accessible
- Unlink last hard link, inode deleted
- Hard link to file in different directory

**6. Truncate (POSIX-09):**
- Truncate file to shorter length
- Truncate file to longer length (zero extend)
- Truncate file to 0

**7. Permissions (metadata):**
- chmod changes mode bits
- chown changes uid/gid
- mtime updates on write

**8. Dedup verification:**
- Write identical content to two files -- same manifest digest
- Write different content -- different manifest digest
- Overwrite file content -- old refcount decremented, new incremented

Each test uses `DictMetadataStore::new()` + `Dictionary::default()` to construct test state. Tests call metadata store methods directly (same code path as FUSE callbacks without kernel overhead). Use `blockset::State::push_all` for content writes and `GetBytes` for content reads, mirroring the exact pipeline.

Mark the module with `#[cfg(test)]`. Use descriptive test names prefixed by category: `test_file_create_write_read`, `test_dir_rmdir_notempty`, etc.

Target: 30+ individual test cases covering the pjdfstest categories applicable to SliceFS.
