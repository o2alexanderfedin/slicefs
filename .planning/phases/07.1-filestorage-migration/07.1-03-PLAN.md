    **Step 1 — Rewrite collect_live_set in gc/mod.rs:**

    Replace Dictionary-based BTreeMap walk with file_storage_get DFS:
    ```rust
    use blockset::{file_storage_get, to_digest224, Io};
    use crate::store_io::StoreIo;

    pub fn collect_live_set(io: &mut impl Io, roots: &[Digest224]) -> HashSet<Digest224> {
        let mut live = HashSet::new();
        for &root in roots {
            mark_reachable(io, root, &mut live);
        }
        live
    }

    fn mark_reachable(io: &mut impl Io, key: Digest224, live: &mut HashSet<Digest224>) {
        if !live.insert(key) {
            return;
        }
        // Read the batch file for this key
        if let Some(bytes) = file_storage_get(io, &key) {
            // The bytes represent the content stored under this key.
            // For internal Merkle nodes, the batch file contains child references.
            // We need to parse the batch file to find child Digest224 keys.
            //
            // However, file_storage_get returns the LEAF content (it recursively
            // resolves external nodes). For GC, we need to know which batch FILES
            // are alive, not which leaf data is alive.
            //
            // REVISED APPROACH: GC for FileStorage works differently than for Dictionary.
            // With Dictionary, dead entries are in the BTreeMap and need removal.
            // With FileStorage, dead entries are batch files on disk.
            // GC needs to:
            // 1. Walk from live roots to find all reachable batch file names
            // 2. Delete batch files not in the reachable set
            //
            // For now, the segment compaction (which removes dead DictEntry records)
            // was the main GC mechanism. With DictEntry gone, segment compaction
            // only keeps RootUpdate + SnapshotRecord — it's already minimal.
            //
            // FileStorage file GC (cleaning orphan vt0/ files) can be deferred to
            // a later phase since orphan files are harmless (just waste disk space).
        }
    }
    ```

    IMPORTANT REALIZATION: The current GC (`collect_live_set` + `compact_segment`) works by:
    1. Finding live Digest224 keys via Dictionary traversal
    2. Compacting segments to remove DictEntry records for dead keys

    After this migration, DictEntry records no longer exist in segments. Segment compaction is now trivial (just keep RootUpdate + SnapshotRecord). The main purpose of GC was to remove dead Dictionary entries from segments — that's gone.

    FileStorage orphan file cleanup (removing vt0/ batch files that no live root references) is a separate concern. For now, implement a simplified GC:

    ```rust
    pub fn collect_live_set(io: &mut impl Io, roots: &[Digest224]) -> HashSet<Digest224> {
        // With FileStorage, the "live set" concept changes.
        // Batch files are named by their root Digest224.
        // A file is "live" if it's reachable from any live root.
        // For now, return empty set — segment compaction handles cleanup.
        // FileStorage orphan cleanup is future work.
        HashSet::new()
    }
    ```

        let mounted = store_path.join("mount.lock").exists();

        let vt0_dir = store_path.join("vt0");
        let mut blocks_verified = 0usize;
        let mut corrupted = Vec::new();

        if vt0_dir.is_dir() {
            for entry in std::fs::read_dir(&vt0_dir)? {
                let entry = entry?;
                let path = entry.path();
                if path.is_file() {
                    // Read batch file, deserialize to Dictionary entries, verify hashes
                    let data = std::fs::read(&path)?;

                        }

                }

        let vt0_internal = store_path.join("vt0").join(".");
        // ... same pattern ...

        // Print report (same format as before)
    }
