<objective>
Replace in-memory Dictionary with file-backed FileStorageAdd/file_storage_get in DictMetadataStore and remove DictEntry from WAL/segment format.

Purpose: This is the core migration — after this plan, Merkle tree nodes live on disk as batched files instead of in ~67 GB of RAM. The WAL simplifies to only RootUpdate + SnapshotRecord entries. Crash safety is maintained via fsync-before-RootUpdate ordering.

Output: DictMetadataStore using StoreIo, simplified WAL/segment format without DictEntry
</objective>

       - Remove `SegmentEntry::DictEntry` variant from the enum. Keep `RootUpdate` and `SnapshotRecord`.

       - Remove `payload_bytes()` match arm for `DictEntry`.

       - In the record parsing logic, when `RecordType::DictEntry` (0x01) is encountered, skip the payload bytes (read payload_len bytes and discard). Do NOT error — old segment files may still contain DictEntry records. Just skip them silently.
       - Actually, since we removed DictEntry from RecordType, `from_u8(0x01)` returns `None`. The reader should handle `None` from `from_u8` by skipping `payload_len` bytes.

    3. In `segment/writer.rs`:
       - Remove any ability to write DictEntry records. The writer should only accept `SegmentEntry::RootUpdate` and `SegmentEntry::SnapshotRecord`.

    4. In `segment/compaction.rs`:
       - Remove all DictEntry filtering logic from `compact_segment()`.
       - The function no longer needs a `live_set` parameter for dict entry filtering (it only filters/keeps RootUpdate and SnapshotRecord entries).
       - Update the function signature accordingly and simplify the compaction logic.

    5. In WAL (`crates/metadata/src/wal/`):
       - Remove `WalEntry::DictionaryAppend` variant.
       - Remove `log_mutation` handling for `DictionaryAppend`.
       - In the segment-writing WAL implementation, remove the code that converts `WalEntry::DictionaryAppend` to `SegmentEntry::DictEntry`.

    **Important:** Do NOT remove the `log_new_dict_entries` method or `prev_keys` pattern from store.rs yet — that happens in Task 2 below. This task only removes the WAL/segment infrastructure that they write TO.

    **Step 2 — Replace dict field in DictMetadataStore:**

    Add `use std::sync::Arc;` and `use crate::store_io::StoreIo;` imports.

    **Step 3 — Update DictMetadataStore::new():**
    Change signature to accept `io: Arc<Mutex<StoreIo>>`:
    ```rust
    pub fn new(io: Arc<Mutex<StoreIo>>) -> Self {
        let mut io_guard = io.lock().unwrap();
        let mut fsa = FileStorageAdd::new(&mut *io_guard);

        let mut inode_map = InodeMap::new();
    ```

    **Step 4 — Update all intern_* call sites in store.rs (write path):**
    Every place that currently does:
    ```rust
    let mut dict = self.dict.lock().unwrap();
    let prev_keys: BTreeSet<Digest224> = dict.keys().copied().collect();
    let digest = intern_something(&mut *dict, ...);
    let new_entries: Vec<_> = dict.iter().filter(...).collect();
    // ... later: self.log_new_dict_entries(new_entries);
    ```
    Changes to:
    ```rust
    let mut io = self.io.lock().unwrap();
    let mut fsa = FileStorageAdd::new(&mut *io);
    let digest = intern_something(&mut fsa, ...);
    drop(fsa); // flush FileStorageAdd
    drop(io);  // release lock
    // No WAL dict entry logging needed — files on disk ARE the state
    ```

    Remove ALL `prev_keys`/`new_entries` diff-tracking patterns (approximately 7+ occurrences in store.rs). Remove the `log_new_dict_entries()` method entirely. Remove `log_wal_entry` calls for `WalEntry::DictionaryAppend`.

    **Step 5 — Update all load_* call sites in store.rs (read path):**
    Also update the load_* function signatures (from Plan 01 they still take `&Dictionary`). Change them to take `&mut impl Io`:

    In each of inode.rs, inode_map.rs, directory.rs, manifest.rs, xattr.rs, change `load_*` functions:
    ```rust
    // OLD:
    pub fn load_inode(dict: &Dictionary, key: &Digest224) -> Result<InodeMeta, MetaError> {
        let digest256 = from_digest224(key);
        let get_data = GetData::new(dict, &digest256);
        let bytes: Vec<u8> = GetBytes::new(get_data).collect();
        deserialize_inode(&bytes)
    }

    // NEW:
    pub fn load_inode(io: &mut impl Io, key: &Digest224) -> Result<InodeMeta, MetaError> {
        let bytes = file_storage_get(io, key)
            .ok_or(MetaError::Corrupted(format!("missing inode node {:?}", key)))?;
        deserialize_inode(&bytes)
    }
    ```

    Apply same pattern to load_manifest, load_xattrs, load_inode_map, list_dir_entries, load_entry_list.

    Every call site in store.rs that does `let dict = self.dict.lock().unwrap(); load_something(&*dict, ...)` changes to `let mut io = self.io.lock().unwrap(); load_something(&mut *io, ...)`.

    **Step 6 — Directory functions that do both read and write:**
    Functions like `add_dir_entry`, `remove_dir_entry`, `lookup_dir_entry` do both `load_entry_list` (read) and `intern_entry_list` (write). With FileStorageAdd holding `&mut Io`, we can't simultaneously have `file_storage_get` using the same `&mut Io`.

    Solution: Read first, then write. Each call site:
    1. Lock io, call file_storage_get to load entry list, collect bytes, release io
    2. Lock io again, create FileStorageAdd, write new entry list, release

    Change directory functions to take `io: &mut impl Io` as a single parameter. Inside the function, do read ops first (file_storage_get), clone the data, then do write ops (using a local Dictionary for the small intern, then State::push_all into a FileStorageAdd).

    Actually, simplest approach: have directory functions take `io: &mut impl Io` and internally create `FileStorageAdd` for writes. Since `FileStorageAdd::new(io)` borrows io mutably, we can read FIRST, then create the FSA:
    ```rust
    pub fn add_dir_entry(io: &mut impl Io, dir_digest: &Digest224, name: &str, ino: u64) -> Result<Digest224, MetaError> {
        // Read current entries (uses file_storage_get internally)
        let mut entries = load_entry_list(io, dir_digest)?;
        // ... manipulate entries ...
        // Write new entry list
        let mut fsa = FileStorageAdd::new(io);
        let result = intern_entry_list(&mut fsa, &entries);
        Ok(result)
    }
    ```
    But `entry_key` also uses `StorageAdd` (it hashes the name). So `entry_key` needs to happen after `FileStorageAdd` is created. And it's called DURING the manipulation. So we need to restructure slightly: load entries, then create FSA, then do entry_key and intern in one scope.

    **Step 7 — Remove dict() accessor:**
    Remove `pub fn dict(&self) -> &Mutex<Dictionary>`. Replace with `pub fn io(&self) -> &Arc<Mutex<StoreIo>>` (returns a reference to the Arc, letting callers clone it if needed).

    **Step 8 — Update set_wal():**
    Remove the bootstrap loop that logs all existing dict entries to WAL. The new `set_wal` simply stores the WAL strategy:
    ```rust
    pub fn set_wal(&mut self, wal: Box<dyn WalStrategy>) {
        *self.wal.lock().unwrap() = Some(wal);
    }
    ```

    **Step 9 — Update commit():**
    The commit function currently does all intern_* calls under a single dict lock. After migration:
    1. Lock io, create FileStorageAdd
    2. Intern all maps (inode_map, inode_data, dir_data, manifest_data, xattr_data, refcounts)
    3. Build root record bytes, push_all into FileStorageAdd
    4. Call fsa.end() — this flushes the top-level batch file to disk (via StoreIo's write() which already fsyncs)
    5. Drop fsa and io lock
    6. Log RootUpdate to WAL (AFTER fsync, per crash-safe ordering)

    **Step 10 — Update load_from_root():**
    Change signature from `load_from_root(dict: Dictionary, root: &Digest224)` to `load_from_root(io: Arc<Mutex<StoreIo>>, root: &Digest224)`:
    ```rust
    pub fn load_from_root(io: Arc<Mutex<StoreIo>>, root: &Digest224) -> Result<Self, MetaError> {
        let mut io_guard = io.lock().unwrap();
        let bytes = file_storage_get(&mut *io_guard, root)
            .ok_or(MetaError::Corrupted("missing root node".into()))?;
        // Parse root record bytes (same 184-byte format)
        // Load sub-digests via file_storage_get
        let inode_map = load_inode_map(&mut *io_guard, &inode_map_digest)?;
        let inode_data = load_u64_digest_map(&mut *io_guard, &inode_data_digest)?;
        // ... etc
        drop(io_guard);

        Ok(DictMetadataStore {
            io,
            inode_map: Mutex::new(inode_map),
            // ... same fields minus dict
        })
    }
    ```

    Also update the internal `load_u64_digest_map` and `load_digest224_u64_map` helper functions to take `&mut impl Io` and use `file_storage_get`.

    Also update `intern_u64_digest_map` and `intern_digest224_u64_map` to take `&mut impl StorageAdd`.

    **Update tests:** All unit tests in store.rs that use `DictMetadataStore::new()` must now pass an `Arc<Mutex<StoreIo>>`. Use `tempfile::TempDir` to create a temporary directory for each test. Update test setup accordingly.
