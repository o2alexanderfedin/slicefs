<architectural_decision>
## How Compression Integrates with blockset Dictionary (RESOLVED)

**Background:** The blockset `Dictionary` is a `BTreeMap<Digest224, Branches>` that stores
content as a Merkle tree. `State::push_all(&mut dict, &buf)` takes raw bytes, encodes each
byte as a `Digest256` leaf via `from_byte`, builds internal tree nodes via `StorageAdd::add`,
and returns a `Digest224` root. The `Digest224` is deterministic for identical input bytes.
`GetBytes` reconstructs the original bytes by traversing the tree.

**The Dictionary IS the storage** — there is no separate block store. Dictionary entries
(92-byte DictEntry records) are persisted to WAL segment files. Compression cannot
intercept individual "block writes" because the abstraction does not expose them.

**Chosen approach: Push compressed bytes into State::push_all.**

Write path:
1. `compress_block(compressor, &raw_buf)` produces `wire_bytes` (1-byte AlgorithmId header + compressed payload)
2. `State::push_all(&mut dict, &wire_bytes)` stores the compressed content as a Merkle tree, returns `compressed_digest: Digest224`
3. Manifest stores `compressed_digest`; refcount on `compressed_digest`
4. `inode.size` is set to `raw_buf.len()` (original uncompressed size — what stat() reports)

Read path:
1. Get `compressed_digest` from manifest
2. `GetBytes::new(GetData::new(&dict, &root256)).collect()` retrieves all `wire_bytes`
3. `decompress_block(compressor, &wire_bytes)` strips header, decompresses, returns raw bytes
4. Apply offset/size slicing on the decompressed raw bytes (NOT on wire_bytes — cannot skip into compressed stream)

**COMP-02 compliance note:** The user decision says "hash original (uncompressed) content
for dedup." With this approach, the `Digest224` is computed on compressed bytes, so dedup
is per-compressor: same raw content + same compressor + same level = identical wire_bytes =
identical Digest224 = dedup works. Cross-compressor dedup (same file with zstd vs lz4) is
NOT achieved. This is an acceptable trade-off because: (a) users configure one compressor
per mount, (b) changing compressor mid-store is rare, (c) achieving true raw-content dedup
would require a dual-digest manifest format change that is disproportionately complex.
Document this limitation in code comments.

**Pre-Phase-6 migration:** Blocks written before Phase 6 have no compression header.
Add a `StoreVersion` segment entry (new `SegmentEntry::StoreVersion { version: u32 }` variant
with `RecordType::StoreVersion = 0x04`). On first Phase-6 mount, write `StoreVersion { version: 2 }`
to the WAL. Store the version in `SliceFsFilesystem`. Read path: if `store_version < 2`,
bytes from GetBytes are raw (no header); if `>= 2`, bytes have the 1-byte compression header.
The version is tracked per-store, not per-block.

**Symlinks:** Symlink targets are small (path strings). Compress them the same way for
consistency. The NoneCompressor or incompressible detection will handle them efficiently.
</architectural_decision>

    **Step 5: Write StoreVersion marker on first Phase-6 mount.**

    In `mount.rs` `run_mount` (or `load_store`): after `load_store_from_segments` returns
    `store_version`, if `store_version < 2`, write `SegmentEntry::StoreVersion { version: 2 }`
    to the WAL immediately. Update the local store_version to 2. This is a one-time migration
    marker. All subsequent reads know to expect compression headers on new blocks.

    Note: blocks written BEFORE this marker still have no header. The store_version gates
    whether NEW writes get compression headers. For reads, since store_version is bumped
    at mount time, ALL reads after the first Phase-6 mount will try to decompress. This means
    old blocks (no header) need special handling: `decompress_block` must handle the case
    where wire_bytes[0] is not a valid AlgorithmId. If invalid, treat the entire wire_bytes
    as raw uncompressed content. This is safe because valid AlgorithmId values are 0x00-0x03,
    and raw file content starting with those bytes is handled by the header semantics
    (0x00 = None = passthrough). Actually, this creates ambiguity for old blocks starting
    with bytes 0x00-0x03.

    **Better migration approach:** Track BOTH the store_version AND which specific Digest224s
    were written with compression. Simpler: keep `store_version` as a field, but only set it
    to 2 AFTER the first Phase-6 mount. On read, check: if the Digest224 was written during
    this session (after version bump), it has a header; if it was loaded from pre-Phase-6
    segments, it does not.

    **Simplest correct migration:** Actually the simplest approach is: do NOT bump store_version
    for existing blocks. Instead, in `decompress_block`, make it resilient: peek at byte[0],
    if it is a valid AlgorithmId, proceed normally. If AlgorithmId::None (0x00), the remaining
    bytes are returned as-is. For pre-Phase-6 blocks where the first byte of actual content
    happens to be 0x00-0x03, this COULD misinterpret. But: AlgorithmId::None (0x00) means
    "return remaining bytes verbatim" which is correct behavior for uncompressed data. The
    only risk is if old data starts with 0x01 (Zstd) or 0x02 (LZ4) — decompression would fail.

    **Final migration approach (use this):** On mount, write StoreVersion=2 to WAL. Maintain
    a `HashSet<Digest224>` of digests created during this mount session (or after store_version
    bump). On read: if digest is in the session set, it has a header; otherwise, treat as raw.
    This is precise but memory-intensive. SIMPLER: just use a `compressed_digests: Mutex<HashSet<Digest224>>`
    field on SliceFsFilesystem. Every `flush_buffer_to_cas` inserts the digest. On read, check
    membership. If not a member, treat bytes as raw (pre-Phase-6).

    Actually even simpler: write ALL new blocks with `AlgorithmId::None` header when compressor
    is NoneCompressor. For pre-Phase-6 blocks, `decompress_block` tries to parse the header;
    if decompression fails (invalid compressed data), fall back to treating the full wire_bytes
    as raw content. This makes the read path self-healing:
    ```rust
    fn read_content(&self, digest: &Digest224) -> Result<Vec<u8>, i32> {
        let wire = self.get_bytes_from_dict(digest)?;
        if self.store_version >= 2 {
            // Try decompress; on failure, assume pre-Phase-6 raw block
            match decompress_block(&*self.compressor, &wire) {
                Ok(raw) => Ok(raw),
                Err(_) => Ok(wire),  // fallback: old block without header
            }
        } else {
            Ok(wire)  // store never upgraded — all blocks are raw
        }
    }
    ```
    Use this fallback approach. It handles mixed old/new blocks gracefully.
