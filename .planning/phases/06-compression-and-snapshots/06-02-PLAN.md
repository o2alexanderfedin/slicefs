  <name>Task 1: Compression in filesystem write and read paths</name>
  <files>crates/slicefs-cli/src/filesystem.rs, crates/slicefs-cli/Cargo.toml</files>
  <behavior>
    - SliceFsFilesystem::new accepts a compressor: Arc&lt;dyn Compressor&gt; parameter
    - flush_buffer_to_cas compresses raw bytes via compress_block AFTER hashing (State::push_all uses raw bytes)
    - FUSE read() decompresses wire bytes via decompress_block BEFORE returning to kernel
    - flush_buffer_for_fsync also compresses via compress_block
    - setattr truncate (CAS read-resize-push path) decompresses then recompresses
    - Content hash (Digest224) is always computed on raw uncompressed bytes
    - Same content written with different compressors produces the same Digest224
  </behavior>
  <action>
    1. Add `slicefs-compression` dependency to `crates/slicefs-cli/Cargo.toml`.

    2. Add `compressor: Arc<dyn Compressor>` field to `SliceFsFilesystem`. Update `new()` to accept `compressor: Arc<dyn Compressor>`.

    3. **Write path** — In `flush_buffer_to_cas`:
       - The hash (State::push_all) MUST operate on raw `buf` bytes (COMP-02: dedup-first-then-compress)
       - CRITICAL ARCHITECTURAL NOTE: The blockset `Dictionary` and `State::push_all` handle their own internal storage format. Compression must be applied at the Dictionary storage level, not by wrapping the push_all call. The correct approach:
         - The `State::push_all` call pushes raw content into the Dictionary, which stores it as internal tree nodes (Digest224 keys + Branches values). These are 92-byte metadata entries, NOT the raw file bytes.
         - Compression should be applied to the raw file bytes that get stored in the Dictionary's leaf nodes. Since blockset handles its own storage internally, compression needs to wrap the Dictionary's internal byte storage.
         - **Simplest correct approach**: Store compression at the block level OUTSIDE the blockset abstraction. Add a `compressed_blocks: HashMap<Digest224, Vec<u8>>` overlay in SliceFsFilesystem that stores compressed raw file content alongside the Dictionary. On write: push_all to get digest, then store compress_block(raw_buf) keyed by digest. On read: look up compressed bytes by digest, decompress_block to get raw content.
         - Actually, re-reading the codebase: `State::push_all` pushes content into the Dictionary as a Merkle tree of Digest224 nodes. The actual byte content is reconstructable via `GetBytes` trait on Dictionary. The Dictionary stores content as tree structure, not raw bytes. Compression should wrap the content at the point where it enters/leaves the user-visible layer.
         - **Correct approach for Phase 6**: Since the Dictionary is a Merkle tree that chunks content internally, and we cannot intercept individual chunk storage without modifying blockset, apply compression at the whole-file level: compress the entire buffer before `State::push_all`, and decompress after `GetBytes`. This means the hash IS on compressed bytes within the tree, but the dedup identity check uses a separate raw-content hash stored in the manifest. However, this violates COMP-02.
         - **Recommended approach**: Store compressed file content as a sidecar. When `flush_buffer_to_cas` is called: (a) compute content_digest via `State::push_all(&mut dict, &buf)` on RAW bytes (preserving dedup identity), (b) store `compress_block(compressor, &buf)` as the actual retrievable content in a `compressed_content: HashMap<Digest224, Vec<u8>>` in the filesystem, persisted alongside the store. On read: retrieve compressed bytes and `decompress_block`. This keeps dedup on raw content hash.
         - **Simplest pragmatic approach**: Since blockset's Dictionary already handles content storage efficiently via its Merkle tree, and modifying its internals is out of scope, apply compression transparently by modifying what bytes are pushed into State::push_all. Push COMPRESSED bytes. Store the raw-content hash separately in the manifest (extend set_manifest to store both raw_hash and compressed_digest). This way: (a) dedup checks use raw_hash (from manifest), (b) storage uses compressed bytes (via Dictionary). The manifest maps raw_hash -> compressed_digest for lookup.

       **IMPORTANT**: Review how `State::push_all` and `GetBytes` work in the actual codebase before implementing. The exact compression integration point depends on whether Dictionary stores opaque byte blobs or structured tree data. Read `blockset` crate source to determine the right interception point. The key constraint is: content hash for dedup MUST be on raw bytes (COMP-02), but stored bytes should be compressed (COMP-01).

    4. **Read path** — In FUSE `read()`:
       - After retrieving bytes via `GetBytes`, decompress if the content was compressed
       - Use `decompress_block` which reads the 1-byte AlgorithmId header

    5. Similarly update `flush_buffer_for_fsync` and the CAS read-resize-push path in `setattr` truncate.

    6. **Pre-Phase-6 migration**: Write a `StoreVersion` marker. On first Phase-6 mount, write a version marker segment entry. Read path: if no version marker found, all stored content is uncompressed (no header byte). If version marker >= 2, all new content has compression header. This prevents garbage when reading old blocks.

    Note: The exact compression integration depends on blockset internals. The executor MUST read the blockset crate's `State::push_all`, `GetBytes`, and `Dictionary` implementations to determine whether compression wraps the push or the stored bytes. The goal: hash raw content for dedup, store compressed content for space savings.
