  <action>
Per [Where to run] and [Metrics]. This task changes no repo file; it only runs the script. Run on the macOS host (APFS). `slicefs seed` does not mount, so the no-mounts rule is kept.
1. Set M=${MEASURE_ROOT:-$HOME/slicefs-measure}, CUR=$(cat $M/bin/current.txt), OUT=$M/results/(today as YYYY-MM-DD). Create OUT and write its path into $M/results/latest.txt.
2. Write $OUT/machine.txt with key=value lines:
   - cpu= (`sysctl -n machdep.cpu.brand_string`)
   - cores= (`sysctl -n hw.physicalcpu`)
   - ram_bytes= (`sysctl -n hw.memsize`)
   - macos= (`sw_vers -productVersion`)
   - fs= (the "File System Personality" from `diskutil info` for the device that `df $M` reports)
   - ssd= (the "Solid State" value from the same output)
   - load_before= (`sysctl -n vm.loadavg`)
   Do not record the host name, the user name or any path.
3. Make sure nothing heavy runs: no cargo or rustc process (pgrep), and no other build or test. Do not start other heavy work until the run ends.
4. Start ONE background job (the Bash tool with run_in_background). It runs the builds strictly one after the other, never in parallel, so the timings do not disturb each other: for b in c2f82fa, 7016bb6, CUR, run `WORK=$OUT/work LABEL=$b scripts/pack-measure/seed-measure.sh $M/bin/slicefs-$b $M/data 3`, with stdout to $OUT/seed-$b.csv and stderr to $OUT/seed-$b.log, and stop at the first non-zero exit. Then merge the three CSVs into $OUT/seed.csv, keeping the header line once.
   - The job can take more than an hour: c2f82fa writes hundreds of thousands of vt0/ files per run. That is why it must not run in the foreground (the 10-minute limit).
   - Wait for the exit notification. Do not poll in a loop.
   - The first rand run creates $M/data/in-rand-1073741824/random.bin once, before any timing. All builds then use the same file.
5. After the job ends, append load_after= (`sysctl -n vm.loadavg`) to machine.txt.
6. When a seed fails, read $OUT/seed-LABEL.log, fix the cause (disk space, a wrong path) and run that build again. Do not edit numbers by hand.
7. Copy seed.csv and machine.txt verbatim into the SUMMARY of this plan, so the numbers stay with the phase record. The scratch dir stays uncommitted.
  </action>
